# 导演台验证轮次 7：资源状态与导出边界收口

日期：2026-07-16

## 本轮目标

在轮次 6 的正式资产绑定基础上，收口浏览器资源替换、动作资源兼容性和导出结果处理，避免“看起来加载成功但预览仍使用旧资源”的情况。

## 已实现

- 统一解析三维资产接口的 `url`、`local_path`、`path`，项目相对路径统一映射到 `/static/`。
- 角色模型和动作资源分别维护未加载、加载中、已就绪、加载失败状态；失败状态可单独重试。
- 更换角色模型时重建导演台场景，清理旧 GLTF 对象；更换动作资源时清理旧动作缓存并立即刷新时间线。
- 独立动作 GLB 至少命中当前角色对象树中的一个动画轨道，否则标记为不兼容，不显示“已加载”。
- 兼容性检查是轻量的轨道目标命中检查，不等同于完整骨骼重定向；跨骨架动作仍需现场验收。
- WebM 编码器选择、导出文件名清理和服务端任务结果 JSON 解析抽为可测试工具。

## 交付边界

本轮没有把第三方示例模型写入用户工程，也没有声称服务端具备无头 Three.js 渲染能力。当前工作树没有用户授权的 GLB/VRM 文件，因此真实素材的上传、骨架匹配和下载仍需在新鲜浏览器会话中用已授权素材做一次现场验收。
