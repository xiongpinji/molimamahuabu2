# 短剧工厂分镜视频多图能力修复（2026-07-31）

## 问题与根因

- 线上默认视频模型为 `lingjing-video-v1`。
- 后端已支持该模型上传多张参考图，并通过 `reference_images` 提交。
- 前端只用不完整的模型名正则判断多图能力，漏掉 `lingjing-video-v1` 和 `omni-fast*`，因此单镜生成错误提示“不支持多图”。
- 单镜、批量生成、一键流程和修复流程各自拼装视频请求，模型覆盖、全能模式和连续帧参数存在不一致风险。

## 修改范围

- 新增集中式多图能力判断，覆盖灵境、Omni Fast、Seedance 2、Grok Video、Kling Omni、Agnes Video。
- 每个分镜优先使用自身 `video_model`，否则使用项目默认模型。
- 单镜、批量生成、一键流程、修复流程统一调用 `buildSbVideoRequestContext`。
- 不支持多图的模型继续保守降级；支持多图的模型传递场景、角色、物品及连续帧参考。

## 验收标准

- `lingjing-video-v1` 不再出现错误的“不支持多图”提示。
- 四个分镜视频入口不再直接拼装 `reference_image_urls`。
- 后端灵境多图上传与提交测试通过。
- 本次相关前后端测试和生产构建通过；前端全量套件不得新增失败。
