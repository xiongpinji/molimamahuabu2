# 画布失败视频任务释放后可重新提交

## 目标

视频生成已经明确失败且冻结积分已经退款后，画布节点必须从不可重复提交的待核对状态收口为失败，刷新页面后允许用户在同一节点重新提交。

## 线上只读证据

- 画布持久化节点为 `running`，`generationActive=false`，保留任务 ID 和旧的供应商 `403` 错误。
- 同一任务的 `video_generations` 已为 `failed`。
- 同一任务的积分预扣已为 `refunded`，但 `async_tasks` 仍为 `needs_attention`。
- 前端对 `needs_attention` 按结果未知保护，继续禁止重复提交；因此后端三个状态没有一致收口是直接原因。

## 修改边界

- 新建视频任务预扣积分后，同时把预扣 ID 和计费模型写入异步任务，避免后续对账丢失关联。
- 周期对账仅在“媒体记录失败 + 对应预扣已退款”两项强证据同时成立时，把仍为 `pending`、`processing` 或 `needs_attention` 的异步任务收口为 `failed`。
- 预扣仍为 `held`、供应商结果仍未知或已有成功证据时继续禁止重复提交。
- 不修改供应商调用、价格、成功扣款、30 分钟保护窗口、画布连线、提示词或生成结果。

## 成功标准

- 旧数据中已退款但异步任务仍待核对的记录自动收口，刷新画布后同一节点可重新提交。
- 新视频任务的媒体记录和异步任务持有同一个预扣 ID。
- 未退款的结果未知任务继续保持待核对，防止重复扣费。
- 对账重复运行保持幂等。

## 验证记录

- 红灯：新增两项回归测试，分别复现异步任务缺少预扣关联、退款后仍为 `needs_attention`；修改前均失败。
- 绿灯：`videoBilling.test.js` 与 `providerReconciliation.test.js` 共 44 项通过、0 项失败。
- 受影响回归：对账、账本、任务恢复、视频计费、兑换码时间夹具、功能锁与发布范围共 370 项通过、0 项失败。
- Hosted CI 首轮暴露兑换码测试使用当日到期时间导致 `CODE_EXPIRED`；已仅将测试夹具改为固定未来时间，未改业务逻辑。
- 功能锁与精确发布范围审计通过；旧批准已移入历史，新批准只覆盖本次两处运行时修复及对应测试。
