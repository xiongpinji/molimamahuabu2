# 画布积分卡片跨会话防覆盖门禁

## 目标

把画布节点底部的醒目预计积分提示从一次性样式修复升级为受保护的生产合同。后续任何工作树、会话或增量发布候选，只要退回旧的灰色 `billing-note`、删除醒目卡片或弱化关键字重，都必须在 CI、生产预检或服务器发布门禁阶段失败，不能切换为线上版本。

## 当前问题

- 生产发布由多个并行会话从不同 worktree 制作；只依赖某个分支中的样式和测试，旧工作树仍可能把线上文件覆盖回旧版本。
- Git 测试只能保护包含该提交的分支，不能约束一份从旧版本制作、直接上传到服务器的候选 release。
- 因此需要仓库内门禁和服务器共享门禁两层保护；共享门禁必须位于 `/opt/moli-drama/shared`，不能随 release 切换而消失。

## 受保护合同

1. `HomeCanvasNode.vue` 必须使用 `billing-cost`，并带 `aria-live="polite"`。
2. 定价节点必须显示“本次预计扣除 X 积分”，积分数字由 `<strong>` 单独强调。
3. 未定价节点必须显示“积分待管理员配置”。
4. 卡片整体字重不得低于 `800`，积分数字不得低于 `900`，并保留醒目背景与边框。
5. 生产构建产物必须同时包含目标文案、类名和关键字重，不能只修改源码而遗漏构建。

## 实现边界

- 新增一个无网络、只读的 Node 审计脚本；既可审计仓库源码，也可用 `--require-build` 审计生产构建。
- 将审计接入 `preflight:production` 和依赖安全 CI。
- 在线上共享目录安装同一审计器；所有 `/opt/moli-drama/current` 切换前都必须用它验证候选 release。
- 共享门禁只允许在明确审查后进行一次可信引导安装；安装后候选只能被现有共享验证器审计，不能替换验证器或激活脚本。门禁升级必须作为独立安全变更人工审查，避免候选携带放水验证器来自证。
- 在工作区根 `AGENTS.md` 和仓库 `AGENTS.md` 写明强制发布规则，使不同 worktree 的后续会话都能看到。
- 不修改积分价格、生成请求、结算、数据库或节点布局。

## 验收标准

1. 降级源码夹具被审计器拒绝。
2. 缺少醒目积分合同的构建夹具被 `--require-build` 拒绝。
3. 当前源码和真实生产构建通过审计。
4. `npm run preflight:production` 在读取数据库前执行受保护合同审计。
5. CI 明确执行同一审计命令。
6. 线上共享门禁接受当前 release，并拒绝一个故意降级的隔离候选；拒绝验证不得切换 `current`。
7. 最终线上健康状态、AI 音乐进程和当前积分卡片发布保持不变或升级为包含门禁的版本。

## 权衡说明

- 无法阻止拥有 root 权限的人故意删除或绕过门禁；本方案针对正常 Codex/人工发布流程提供持久且可验证的强制约束。
- 不采用常驻文件监控或自动改写线上源码，避免误判造成服务抖动；使用共享发布门禁、CAS 和明确的会话规则阻止切换更安全。
