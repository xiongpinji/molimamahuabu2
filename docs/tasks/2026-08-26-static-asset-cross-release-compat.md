# 旧标签页跨版本静态资源兼容修复

## 问题

生产发布后，已打开的旧标签页仍运行旧入口脚本；当它继续加载旧版动态分块时，新 release 已删除对应哈希文件。后端随后把缺失的 `/assets/*.js` 回退为 `index.html`（HTTP 200、`text/html`），浏览器因此报动态模块加载失败。

## 本阶段边界

- 只修改隔离工作树中的前端构建、前端恢复入口和后端静态资源服务。
- 不推送、不部署、不修改生产数据库、不触发供应商或付费调用、不触碰 AI 音乐。
- 不改变 `/api`、`/static` 用户素材、画布业务逻辑或短剧工厂业务逻辑。

## 成功标准

1. 已存在的 `/assets/*` 正常返回，缺失的 `/assets/*` 返回真实 404，绝不返回 SPA HTML。
2. 每次前端构建保留本次资源与紧邻上一版本的资源，并清理更老兼容资源，避免无限增长。
3. 新版入口捕获 Vite 动态分块加载失败时至多自动刷新一次；短时间再次失败时不循环刷新。
4. SPA 路由仍返回 `index.html`，HTML 明确要求重新验证缓存。
5. 聚焦测试、前端生产构建和相关既有回归全部通过。

## 非目标

- 不引入 Service Worker。
- 不取消 Vite 代码分割或改成无哈希文件名。
- 不扫描其他 release 目录，也不让运行时读取生产发布历史。

## 实现边界

- 后端仅调整 `frontweb/dist` 的静态资源挂载：`/assets` 缺失时返回非 HTML 404，真实 SPA 路由继续回退到 `index.html`。
- 前端构建清单只保留当前代和紧邻上一代；候选被重复构建时仍保留原线上上一代，不把构建次数误判为发布代数。
- 客户端只在 Vite 动态分块预加载失败时刷新一次，并用 30 秒会话冷却阻止刷新循环。
- 精确发布白名单共 11 个源码、测试、文档与清单文件；不包含 `frontweb/dist`、生产数据库、上传目录、模型配置、积分逻辑或 AI 音乐。
