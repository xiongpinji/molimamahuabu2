# DJPSD 开放 API 图片模型接入

## 目标

将 `https://shiping.djpsd.com` 公开 OpenAPI 中当前返回的三个图片模型接入图片生成主链：`image-v1`、`image-v1-2k`、`image-v1-4k`。后台完成配置、无生成连接验证和定价后，画布图片节点通过现有动态模型目录自动显示，不新增前端写死的画布模型列表。

## 已核对的上游事实

- `GET /v1/models` 当前返回 1K、2K、4K 三个图片模型及 `video-v1`。
- `POST /v1/media/generate` 请求为 `{ model, prompt, params }`；`params` 支持 `aspect_ratio` 和 `images`。
- 参考图先经 `POST /v1/media/upload` 上传，再把返回地址放入 `params.images`。
- `GET /v1/media/status?task_id=...` 查询异步任务，认证使用 Bearer API Key。
- 上游只读扣费规则当前为 1K=1、2K=2、4K=3 上游积分；这是供应商成本信息，不直接替代本平台面向用户的积分定价。

## 约束

- 使用中转站真实 OpenAPI，不调用站内 `/task/create` 用户页面接口，不模拟生成结果。
- 连接验证只查询不存在的任务，禁止创建付费图片。
- 文生图和多参考图都走同一适配器；不把固定“三张参考图”写入供应商客户端。
- 本地图片、data URL 和公网图片必须先上传；API Key 只能发给与 Base URL 同源的端点。
- 1K/2K/4K 由模型 ID 决定，画幅从画布传入的像素尺寸或比例转换为 DJPSD 支持的比例。
- 提交请求在取得任务 ID 前连接中断、或轮询未取得最终结果时，必须写明“结果未知/状态未知”，让积分保持冻结，避免自动退款后重复生成。
- 生产激活前必须确认三个模型各自的本平台积分价格；不得把上游积分或推测价格静默写入用户计费。

## 验收标准

1. 三个图片模型都能由 `callImageApi` 路由至 DJPSD 开放 API。
2. 文生图请求包含正确的模型、提示词和画幅；多参考图逐张上传并按原顺序写入 `params.images`。
3. 相对结果地址补全为中转站绝对图片地址；失败、完成无图片、轮询超时分别产生明确状态。
4. 自定义提交/查询端点跨域时拒绝发送 Bearer。
5. 后台图片/分镜图片配置可选择 DJPSD 及三个实时模型，并自动填写创建和查询端点。
6. 无生成连接测试以现有生产 API Key 通过；专项测试、后端全量、前端相关测试和生产构建通过。
7. 生产配置验证成功且模型完成正价定价后，`/canvas/model-catalog` 自动返回三个模型，画布无需再次发版。
