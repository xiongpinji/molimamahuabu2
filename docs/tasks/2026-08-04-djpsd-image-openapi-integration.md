# DJPSD 开放 API 图片模型接入

## 目标

将 `https://shiping.djpsd.com` 中经过真实生成验证的图片模型接入图片生成主链。当前仅开放 `image-v1`、`image-v1-2k`；`image-v1-4k` 虽出现在模型目录中，但真实创建任务失败，因此不得进入后台生产配置和前端可选模型。

## 已核对的上游事实

- `GET /v1/models` 当前返回 1K、2K、4K 三个图片模型及 `video-v1`，但模型列表不是生成能力证明。
- 使用生产 DJPSD Key 绕过我方平台计费直接验证：`image-v1` 创建任务 `320435` 并成功产出图片，上游扣除 1 点；`image-v1-2k` 创建任务 `320523` 并成功产出 2K 图片，上游扣除 2 点。
- 同样方式提交 `image-v1-4k` 时，上游直接返回 HTTP 400：`任务扣费规则未配置`，且未扣上游积分；问题发生在上游创建任务阶段，与我方平台计费无关。
- `POST /v1/media/generate` 请求为 `{ model, prompt, params }`；`params` 支持 `aspect_ratio` 和 `images`。
- 参考图先经 `POST /v1/media/upload` 上传，再把返回地址放入 `params.images`。
- `GET /v1/media/status?task_id=...` 查询异步任务，认证使用 Bearer API Key。
- 成功实测的上游成本为 1K=1、2K=2；这是供应商成本信息，不直接替代本平台面向用户的积分定价。

## 约束

- 使用中转站真实 OpenAPI，不调用站内 `/task/create` 用户页面接口，不模拟生成结果。
- 只读连接验证只证明 Key 和端点可访问，不能把模型标记为可开放。每个新增模型必须完成一次真实生成、成功终态和结果文件读取验证后，才能写入前端预设及生产模型列表。
- 适配器可以传递任意数量的参考图，但“文生图验证通过”不得推导为“参考图生成已验证”；前端能力必须按真实生成模式分别开放。
- 本地图片、data URL 和公网图片必须先上传；API Key 只能发给与 Base URL 同源的端点。
- 1K/2K 由模型 ID 决定，画幅从画布传入的像素尺寸或比例转换为 DJPSD 支持的比例。
- 提交请求在取得任务 ID 前连接中断、或轮询未取得最终结果时，必须写明“结果未知/状态未知”，让积分保持冻结，避免自动退款后重复生成。
- 生产激活前必须确认开放模型各自的本平台积分价格；不得把上游积分或推测价格静默写入用户计费。

## 验收标准

1. `image-v1`、`image-v1-2k` 都能由 `callImageApi` 路由至 DJPSD 开放 API；通用适配器可以继续兼容 4K 请求，但 4K 在重新实测成功前不得开放选择。
2. 文生图请求包含正确的模型、提示词和画幅；适配器可逐张上传多参考图并按原顺序写入 `params.images`，但只有参考图真实生成成功的模型才能在参考图节点中启用。
3. 相对结果地址补全为中转站绝对图片地址；失败、完成无图片、轮询超时分别产生明确状态。
4. 自定义提交/查询端点跨域时拒绝发送 Bearer。
5. 后台图片/分镜图片配置可选择 DJPSD 及两个真实生成验证通过的模型，并自动填写创建和查询端点；4K 不在可选列表中。
6. 1K、2K 使用现有生产 API Key 完成真实生成和结果文件验证；专项测试、后端全量、前端相关测试和生产构建通过。
7. 生产 DJPSD 配置只保存 1K、2K；`/canvas/model-catalog` 仍可同时返回其他已验证、已定价的图片供应商模型，画布无需为新增后台模型再次发版。
