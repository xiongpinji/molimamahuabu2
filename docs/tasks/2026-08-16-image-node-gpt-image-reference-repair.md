## 文档合同

Feishu 文档 2026-08-14 当前 GPT-Image-2 多档章节规定：

- 1K 同步：`POST /v1/images/generations`，JSON。
- 1K 同步模型 ID：`gpt-image-2-1k`。
- 参考图字段：`reference_image_urls`，最多 6 张，解码后总和不超过 5 MiB。
- 支持画幅示例：`1024x1024`、`1536x1024`；同步结果返回 `data[0].url`。
- 2K/3.5K 是异步 `/v1/videos` 合同，不得与 1K 同步合同混用。

文档与项目现有协议代码都没有字面模型 ID `image-2`；本任务按文档中的目标模型 `gpt-image-2-1k` 准备接入。真实生成未通过前不得写入生产模型目录。

## AIHubCC `gpt-image-2` 图生图重新验证

- 目标 Key 的只读 `/models` 返回 HTTP 200，且模型目录包含 `gpt-image-2`；任务文档不记录 Key。
- 使用 1 张 1,737,650 字节 PNG 真人角色设定图，执行且仅执行 1 次 `POST /v1/images/edits` multipart 请求；字段为 `model`、`prompt`、`size=1024x1024`、`image` 文件，客户端自动重试关闭。
- 62.511 秒后返回 HTTP 200 和 `b64_json`；产物是可读取 PNG，尺寸 1254×1254、大小 1,768,419 字节、SHA-256 `90c8c0216b63dd1cf08fe9d403b9c595a3d2b54d66be581af833a855818835c8`。
- 视觉验收：产物保持同一成年女性的脸部、发型与多视图角色设定图结构，按提示把米白休闲服替换为深蓝商务套装；没有出现提示词要求之外的人物或明显破图。
- 根因结论：此前失败是把参考图 URL 放入 `/images/generations` JSON，供应商需要 `/images/edits` 文件上传；不是该模型缺少图生图能力。
- 该证据首先证明单张参考图合同；后续已在同一 Key / 通道上完成下述多参考图上限验证。
- 安全保护：模型客户端只接受已落盘并转换成 data URL 的参考图，不直接抓取任意远程 URL，避免把画布输入变成服务端外连入口。
- 真实验证未写生产任务、用户积分、生产模型配置或数据库；尚未推送、部署。

## AIHubCC `gpt-image-2` 多参考图上限验证

- 2026-08-16 使用同一目标 Key 和 `/v1/images/edits` multipart `image[]` 文件数组执行 5 次有界探测；每次仅提交 1 次、自动重试关闭，所有参考图先压缩为 256×256 JPEG，排除总上传体积干扰。
- `16` 张：HTTP 200，74.793 秒，返回可读取 1254×1254 PNG，1,572,838 字节，SHA-256 `6bebe293299c6976e5cb87005c1f7d74f18202a55c290148bf5468dd7ba0a98f`。
- `17` 张：HTTP 200，82.193 秒，返回可读取 1254×1254 PNG，1,684,148 字节，SHA-256 `da78c5c16184edd50a67c25862ddf47780bee06eb01703c867fd8ff9e12107b5`。
- `32` 张：47.217 秒后 HTTP 502，AIHubCC/Cloudflare `Bad gateway`，无产物、无重试。
- `20` 张：HTTP 200，70.321 秒，返回可读取 1254×1254 PNG，1,684,505 字节，SHA-256 `ae67a00663700a2db076067526afca2db6a5af0347b985cb9bd0b9241abb6cf0`；视觉检查为正常角色设定图，没有明显破图。
- `21` 张：32.031 秒后 HTTP 502，AIHubCC/Cloudflare `Bad gateway`，无产物、无重试。
- 结论边界：当前 Key/当前通道的实测安全上限为 `20` 张；`21` 与 `32` 均失败。由于供应商返回的是通用 502 而不是结构化“超过上限”错误，本结论不表述为供应商永久硬上限，生产配置应保守锁定 `maxReferences=20` 并在提交前拒绝第 21 张。
- 按供应商页面标示的 ¥0.033/请求估算，本轮最多 5 次请求约 ¥0.165；实际结算以供应商账单为准。测试没有写生产任务、平台积分、模型配置或数据库。
