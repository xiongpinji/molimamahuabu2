# 视频供应商前端目录一致性

## 问题

生产后台存在多个启用的视频供应商，但“连接测试”结果没有持久化。画布自由节点读取 `/canvas/model-catalog`，短剧工厂读取 `/video-models`，首页和单次生成读取 `/billing/catalog`，三套目录只能各自按启用状态或计费状态推断可用性，无法保证一致。

## 生产核对（2026-08-04）

| 配置 | 模型 | 启用 | 计费 | 无付费连接验证 |
| --- | --- | --- | --- | --- |
| xai | lingjing-video-v1 | 是 | 60 积分/秒 | 通过，483ms |
| djpsd_openapi | video-v1 | 是 | 60 积分/秒 | 通过，108ms |

连接验证仅使用供应商的只读/不存在任务查询或现有的密钥探针，不提交视频生成任务。它证明网络、路由与鉴权可用，不等同于一次付费生成成功。

## 判定与范围

- 本任务中的“验证确认”指后台已保存配置最近一次连接测试成功。
- 视频模型公开可选必须同时满足：配置启用、最近验证成功、模型价格启用且为正整数。
- 新建配置默认未验证；连接相关字段实际变化后自动恢复为未验证。
- 失败验证会保存失败状态、检查时间和脱敏后的错误摘要。
- 本次只统一视频供应商在全部用户前端入口的可选择性，不改变文本、图片和语音的既有公开规则。
- 环境变量中的画布视频兜底不能绕过后台验证状态进入公开目录。
- 候选 release 必须保留线上已有覆盖行为：单图润色字段迁移、音频计费目录参数、灵境 4 秒计费下限，以及画布目录的 provider、默认音色和 requirePrice 字段。

## 验收标准

1. 数据库保存 `unverified`、`verified`、`failed` 状态及最近检查信息。
2. 保存配置的连接测试成功或失败后，状态与时间可从后台配置接口读回，且不暴露密钥。
3. `/video-models`、`/canvas/model-catalog`、`/billing/catalog` 对视频模型使用同一验证门槛。
4. 所有已验证且启用、已计费的视频模型在三套目录中均可选择；未验证、验证失败或停用模型均不可选择。
5. 连接参数修改会撤销验证，名称、优先级等非连接字段修改不会误撤销。
6. 后端专项与全量测试、前端全量测试及生产构建通过。

## 生产发布门（必须按顺序）

1. 先备份生产数据库，并从当前线上 release 复制候选 release；此时不切换线上软链接。
2. 使用候选 release 的迁移代码为生产数据库补充验证列，旧进程继续提供服务。
3. 使用候选 release 对所有启用的视频配置执行不产生付费任务的连接验证，并持久化结果。若任一目标配置失败，停止发布，不切换流量。
4. 切流前确认生产数据库中 `lingjing-video-v1`、`video-v1` 对应配置均为 `verification_status='verified'`，且价格为 enabled 的正整数。
5. 使用候选 release 和生产数据库读取三套目录，确认 `/video-models`、`/canvas/model-catalog`、`/billing/catalog` 都同时包含 `lingjing-video-v1`、`video-v1`，且无未验证或未计费视频模型。
6. 以上检查全部通过后才能切换 release 并重启服务；随后再次读取三套目录、健康状态和服务重启次数。任一检查不通过立即停止切流，已切流则恢复上一 release。
