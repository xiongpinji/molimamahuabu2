# 本地开发卫生（DEV Hygiene）

## 禁止把仓库放在双向同步盘里

本仓库**不要**放在百度网盘、OneDrive、iCloud、坚果云等**双向同步**目录内作为工作副本。

同步软件会：

- 在编辑过程中回写/覆盖未保存或刚保存的源码（已在本项目中复现）
- 锁住 SQLite / `better-sqlite3` 原生绑定，导致本地库或 npm 安装失败
- 破坏 git worktree、junction 与 `node_modules`

## 正确做法

1. 工作副本固定在本机非同步路径（例如非网盘盘符下的独立目录）。
2. 备份与协作只用 **git remote**；网盘最多做只读归档，不要双向同步正在开发的目录。
3. 开发期若必须用网盘备份：改为「仅上传」或定时打包，不要实时双向同步。
4. 部署暂存可使用 `%LOCALAPPDATA%\\moli-drama\\deploy-staging\\`，用完清理，勿依赖同步盘里的补丁脚本。

## 与发布的关系

受保护发布候选必须从线上实时 `current` 克隆并只覆盖审计文件。本地同步盘污染的工作区文件**不得**直接 scp 上线。
