# Windows 正式发行闭环计划（2026-07-24）

## 目标

把桌面端从“能在本地打包”推进到“品牌资源正确、PR 可回归构建、正式发布必须签名且产物可验证”的 Windows 发行状态。

## 明确假设

1. `D:\熊品记库\图片肖像\ecdc71b5-7018-4e87-b0fd-20b6558d2f4f.png` 是用户确认的品牌图标原图。
2. Windows 小尺寸图标只使用该图像，不把“茉莉妈妈 / 短剧制作平台”文字压入图标；完整名称写入产品名、文件描述和安装包名称，避免小图标文字不可读。
3. `%APPDATA%\localminidrama-desktop` 是已有用户数据目录，继续保留，避免品牌升级造成数据丢失。
4. 产品发布者改为“茉莉妈妈”；上游 MIT 许可证继续保留，这是开源合规要求，不属于要移除的产品联系方式。
5. 代码库不能生成或伪造 Windows 签名证书。PR 构建明确为未签名验证包；正式标签发布缺少签名机密时必须失败。

## 范围

- 桌面端 Windows 产品名、发布者、描述、应用 ID、安装包名称和图标。
- PR / 主分支 Windows 未签名构建门禁。
- 标签发布的签名机密检查、强制签名、Authenticode 校验、SHA-256 校验文件和 GitHub 产物证明。
- 对应自动化测试、文档和本机打包验证。

## 不在本阶段

- 购买或签发代码签名证书。
- macOS 签名、公证与 DMG 品牌资源。
- 修改历史许可证、第三方版权声明或已有用户数据目录。

## 验收标准

1. 自动化测试可检查品牌元数据、ICO 资源、PR 构建门禁和正式发布安全门禁。
2. PR 工作流能在 `windows-latest` 生成安装版和便携版，并上传校验文件。
3. 正式发布工作流在没有 `WIN_CSC_LINK` / `WIN_CSC_KEY_PASSWORD` 时明确失败。
4. 正式发布启用 `forceCodeSigning`，逐个校验 EXE 的 Authenticode 状态，并生成 SHA-256 校验文件和 GitHub 产物证明。
5. 本机完成前后端测试、依赖审计、Windows 打包、EXE 资源元数据与启动验证；本机无证书时只允许得到明确记录的未签名验证包。

## 执行顺序

1. 先写失败测试，覆盖品牌配置与发行工作流契约。
2. 生成品牌 PNG/ICO，并最小修改 `desktop/package.json`。
3. 新增 PR Windows 构建工作流，强化标签发布工作流。
4. 执行全量回归、审计和真实 Windows 打包验证。
5. 选择性提交、推送、创建 PR，并等待远端 CI 结果。
