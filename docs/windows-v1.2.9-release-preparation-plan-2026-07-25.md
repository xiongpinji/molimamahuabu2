# Windows v1.2.9 发布准备计划

日期：2026-07-25

## 目标

在不创建未签名正式包、不触碰主工作区未提交改动的前提下，将仓库准备到可触发 `v1.2.9` 正式签名发布的状态：

1. `frontweb`、`backend-node`、`desktop` 的包版本和 lock 文件根版本统一为 `1.2.9`。
2. `CHANGELOG.md` 记录自 `v1.2.8` 以来已合并的公开平台、画布、模型、计费、安全、备份和桌面发行能力。
3. 自动化契约阻止三端版本不一致、标签版本不一致或变更记录缺失的发布。
4. 发布说明明确证书配置、标签创建、草稿 Release 复核与回滚步骤。

## 非目标

- 不在仓库中保存签名证书或密码。
- 不在缺少 `WIN_CSC_LINK`、`WIN_CSC_KEY_PASSWORD` 时创建 `v1.2.9` 标签。
- 不自动公开 GitHub Release。
- 不修改应用业务功能、数据库结构或品牌身份。

## 实施顺序

1. 先增加版本一致性与发布记录契约测试，并确认旧版本状态会失败。
2. 将三个包及其 lock 文件根版本提升到 `1.2.9`。
3. 更新变更记录和管理员发布/回滚操作说明。
4. 运行发布契约、后端与前端测试、前端构建、依赖门禁和 Windows 未签名验证构建。
5. 选择性提交并通过 PR 合并；仅在真实签名密钥存在后创建标签。

## 成功标准

- 版本一致性与正式发布契约测试通过。
- 后端、前端全量测试和前端生产构建通过。
- Windows PR 验证包仍明确保持未签名，正式标签工作流仍强制真实签名。
- `git diff --check` 和变更审计无误。
- GitHub PR 的必需检查通过并合并到 `main`。

## 当前外部阻塞

截至 2026-07-25，仓库未配置 `WIN_CSC_LINK` 和 `WIN_CSC_KEY_PASSWORD`，且没有既有 GitHub Release。本阶段可以完成并合并 v1.2.9 发布准备，但不能诚实地创建正式签名标签或安装包。
