# 预发布可运营性阶段计划（2026-07-24）

## 目标

在不修改生产配置、不覆盖业务数据库、不调用付费模型的前提下，交付一套可重复执行的上线前检查与 SQLite 数据保护工具。

## 范围

1. 生产预检
   - 校验公开平台模式、注册开关、JWT/管理员令牌长度和首管理员邮箱。
   - 校验调试模式、TLS 校验、CORS、素材公网地址和数据库路径。
   - 校验 SQLite `quick_check`、管理员账号和已启用模型价格。
   - 输出只包含检查结果，不输出任何密钥原文。
2. 数据库备份
   - 使用 SQLite 在线备份能力生成一致性快照。
   - 为备份生成 SHA-256、大小、时间和完整性结果清单。
   - 创建后立即重新列出并校验最新备份。
   - 默认保留 6 份；空间不足、`ENOSPC` 或 `EIO` 时停止，不自动重试。
3. 恢复演练
   - 只恢复到显式指定的新文件。
   - 目标文件已存在时拒绝覆盖。
   - 恢复后执行哈希与 SQLite `quick_check` 校验。
4. 运维说明
   - 给出预检、备份、列出、验证和恢复演练命令。

## 非目标

- 不修改 `configs/config.yaml` 为生产值。
- 不向仓库写入密钥、令牌或供应商凭据。
- 不实现支付渠道。
- 不覆盖当前数据库，不执行生产恢复切换。
- 不发起真实图片、视频或语音模型请求。

## 成功标准

1. 新测试先因能力缺失而失败，再由最小实现修复。
2. 安全配置样例通过预检；当前开发配置必须被明确判定为不可发布。
3. 备份文件可通过 SHA-256 和 SQLite `quick_check`；篡改后验证失败。
4. 恢复演练不得覆盖已有文件，恢复出的临时数据库可查询原数据。
5. `node --test test/productionPreflight.test.js test/databaseBackup.test.js` 通过。
6. 后端全量测试、前端全量测试和前端构建通过。
7. 变更独立提交并创建阶段 PR。

## 实施顺序

1. 先编写生产预检失败测试。
2. 实现最小预检服务和 CLI。
3. 先编写备份、校验、保留和恢复演练失败测试。
4. 实现最小数据库备份服务和 CLI。
5. 补充运维文档，执行全量回归与安全审计。

## 人工阻塞项

真实供应商小额生成验证需要正式测试账号、有效 API 密钥和明确额度；上述条件具备前保持阻塞，不使用模拟结果替代。
