# 画布图片预览空格拖动设计

## 背景

画布模式的图片节点在生成图片后，已经具备双击打开全屏预览和 `Ctrl/⌘ + 滚轮`缩放能力。当前缺少在放大状态下移动查看图片局部区域的操作。

本次仅补齐图片预览层的“按住空格 + 左键拖动”交互，不改变画布导航、图片生成、视频预览、素材引用或计费逻辑。

## 已确认需求

- 仅当图片缩放比例大于 `100%` 时允许拖动。
- 用户按住空格后，再按住鼠标左键拖动图片。
- 松开空格、松开鼠标或窗口失焦时立即停止拖动。
- 拖动图片时不得带动画布节点或底层画布。
- 保留现有双击预览、滚轮缩放、关闭按钮和 `Escape` 退出行为。

## 方案选择

采用浏览器原生 Pointer Events 和指针捕获：

- 不引入第三方手势库。
- 不将预览层改造成滚动容器。
- 在现有预览状态旁增加位移、空格键状态和拖动状态。
- 使用 `setPointerCapture` 保证指针移出图片后仍能连续拖动。

该方案修改面最小，且能明确隔离图片拖动与 Vue Flow 画布拖动。

## 交互状态

预览层维护以下状态：

- `scale`：现有图片缩放比例。
- `pan.x`、`pan.y`：相对预览中心的图片位移。
- `spacePressed`：图片预览打开期间是否按住空格。
- `dragging`：是否正在执行图片拖动。
- `dragStart`：拖动起点的指针坐标与起始位移。

图片样式统一使用：

```text
translate(pan.x, pan.y) scale(scale)
```

## 事件流程

### 开始拖动

同时满足以下条件时才开始：

1. 当前是图片预览，不是视频预览。
2. `scale > 1`。
3. 空格键处于按下状态。
4. 指针事件来自鼠标左键。

开始时阻止默认行为和事件传播，记录起点，并捕获当前指针。

### 拖动中

根据当前指针坐标与起点坐标的差值更新 `pan.x`、`pan.y`。拖动仅改变预览图片的 transform，不修改节点数据或画布 viewport。

### 停止与复位

- `pointerup`、`pointercancel`、空格键抬起或窗口失焦：停止拖动。
- 缩放回到 `100%` 或更小：停止拖动并将位移归零。
- 关闭预览或打开另一张图片：缩放和位移全部归零。
- `Escape`：沿用现有关闭预览逻辑，并触发相同复位。

## 视觉反馈

- 图片放大但未按空格：提示“按住空格 + 左键拖动”。
- 图片放大且按住空格：光标显示 `grab`。
- 正在拖动：光标显示 `grabbing`，临时关闭 transform 过渡，避免拖动滞后。
- `100%` 或更小时不显示可拖动光标。

## 兼容与冲突边界

- 只修改图片全屏预览相关模板、状态、事件和样式。
- 不修改视频预览。
- 不修改 Vue Flow 的画布平移快捷键或节点拖动配置。
- 合入前重新对比最新 `origin/main` 和其他画布分支；若缩放实现已经合并，则只叠加拖动逻辑。
- 生产部署不在本设计阶段授权范围内，后续必须按项目受保护发布规则单独确认。

## 验收标准

1. 图片为 `100%` 时，按空格拖动不会产生位移。
2. 图片放大到 `100%` 以上后，按住空格和左键可以连续拖动。
3. 未按空格、非左键或视频预览均不能触发图片拖动。
4. 松开空格、松开鼠标、指针取消或窗口失焦后，继续移动鼠标不会改变位移。
5. 缩放回 `100%`、关闭预览或重新打开图片后，位移归零。
6. 拖动图片时，底层画布 viewport 和节点位置不变。
7. 现有双击预览、`Ctrl/⌘ + 滚轮`缩放、关闭按钮和 `Escape` 退出测试继续通过。

## 测试策略

- 先增加失败测试，覆盖模板事件绑定、比例门禁、复位逻辑和事件清理。
- 再实现最小生产代码使测试通过。
- 运行相关 Node 测试、前端构建和定向浏览器交互验证。
- 浏览器验证同时检查图片 transform 和底层画布 viewport，不能只看提示文字。
