# 模型展示名称与用户备注统一目录设计

**日期：** 2026-08-07
**状态：** 已由用户确认方案 A
**适用范围：** 管理员模型计费后台、首页快速生成、自由创作、画布节点、短剧工厂

## 1. 背景与问题

管理员模型计费后台已经能够维护 `display_name`，首页和画布的部分入口会读取该字段，但短剧工厂仍直接显示供应商模型 ID。当前系统也没有专门面向普通用户的模型备注字段，因此管理员无法及时说明模型能力、限制、适用场景或临时状态。

此外，生产预检仍把三个历史固定模型视为必须启用，导致管理员主动停用 `seedance 2.0` 后，正常发布被误判为缺少价格。模型是否对用户开放应由实时配置、验证状态、定价状态和管理员启停状态共同决定，而不是由历史模型名称决定。

## 2. 目标

1. 管理员在一个位置维护模型展示名称和用户备注。
2. 首页、自由创作、画布和短剧工厂显示完全一致的名称和备注。
3. 普通用户只看到展示名称；原始模型 ID 继续作为内部路由值，不因改名而改变供应商调用。
4. 管理员停用模型后，该模型不再出现在普通用户可选目录中，后端生成接口仍拒绝调用。
5. 生产预检验证公开目录的真实可用性，不强迫管理员重新启用已主动停用的历史模型。
6. 增加自动化门禁，防止任一入口再次绕过统一目录、硬编码展示名称或漏传用户备注。

## 3. 非目标

- 不修改供应商模型 ID、API 地址、密钥或模型能力配置。
- 不自动启用、停用或改价任何模型。
- 不允许备注覆盖模型能力校验、计费校验或真实生成验证。
- 不增加富文本、HTML、图片或外链编辑器；备注仅为纯文本。

## 4. 统一字段合同

`model_credit_prices` 继续作为展示与计费元数据的唯一管理来源，并新增：

- `display_name`：前端展示名称，必填，去除首尾空格，长度 1–120 个字符。
- `public_note`：普通用户可见备注，选填，去除首尾空格，最长 500 个字符，按纯文本渲染。
- `model`：原始模型 ID，只用于管理员识别、供应商路由和任务记录。
- `status`：管理员启停状态；`disabled` 不进入普通用户公开目录。

数据库升级使用现有 `ensureColumn()` 模式新增非破坏性列：

```sql
ALTER TABLE model_credit_prices
ADD COLUMN public_note TEXT NOT NULL DEFAULT '';
```

旧记录迁移后备注为空，不改变原有展示名、价格和启停状态。

## 5. API 与数据流

### 5.1 管理员接口

`GET /api/v1/billing/prices` 返回原始模型 ID、展示名称、用户备注、类型、价格、状态和供应商摘要。

`PUT /api/v1/billing/prices/:model` 接受并保存：

```json
{
  "display_name": "Seedance 极速版",
  "public_note": "适合快速预览，支持 480P 和 720P。"
}
```

写接口继续受平台管理员和计费管理员权限保护。无效展示名或超过 500 字的备注返回 400，不落库。

### 5.2 普通用户公开目录

`GET /api/v1/billing/catalog` 返回首页与自由创作所需字段：

```json
{
  "model": "seedance-2.0-fast",
  "display_name": "Seedance 极速版",
  "public_note": "适合快速预览，支持 480P 和 720P。",
  "category": "video",
  "credits": 560,
  "status": "enabled"
}
```

`GET /api/v1/canvas/model-catalog` 返回画布与短剧工厂所需字段：

```json
{
  "kind": "video",
  "model": "seedance-2.0-fast",
  "label": "Seedance 极速版",
  "note": "适合快速预览，支持 480P 和 720P。",
  "credits": 560,
  "capabilities": {}
}
```

公开目录只包含同时满足以下条件的模型：

1. 供应商配置处于启用状态；
2. 已通过真实生成验证且结果文件可读；
3. 管理员计费状态为 `enabled`；
4. 已配置正整数积分价格。

任何一项不满足，模型不进入普通用户选择器。后端生成接口仍独立执行验证、状态和价格校验，不能只依赖前端隐藏。

### 5.3 短剧工厂路由保持

短剧工厂仍读取 AI 配置获得供应商能力、默认模型和声音策略，但模型选择器的名称与备注改为与 `/canvas/model-catalog` 合并后的统一条目：

```js
{
  value: 'seedance-2.0-fast',
  label: 'Seedance 极速版',
  note: '适合快速预览，支持 480P 和 720P。'
}
```

提交生成任务时只发送 `value`，因此管理员改名和改备注不会改变供应商路由。

## 6. 前端交互

### 6.1 管理员模型后台

每个模型卡片增加“用户备注”多行文本框，并保留原始模型 ID、展示名称、类型、价格、状态和供应商信息。保存成功后使用服务端返回值覆盖本地数据，刷新页面仍能回读。

新增模型区域同样提供用户备注。搜索同时匹配原始模型 ID、展示名称和用户备注。

### 6.2 首页与自由创作

模型选择器显示 `display_name`。选择器下方始终显示当前模型的 `public_note`；空备注时不占用提示区域。切换生成类型或模型时备注同步更新。

### 6.3 画布

图片、视频、文本和音频生成节点的模型选项显示 `label`。节点编辑器、生成参数面板和视频生成弹窗在模型选择器下方显示当前条目的 `note`。

所有位置继续保存和提交原始 `model`，画布持久化数据不因展示名称变化而失效。

### 6.4 短剧工厂

批量视频模型选择器、单分镜视频模型选择器和底部批量操作选择器统一显示 `label`。每个选择器下方显示当前模型备注，并复用同一组辅助函数，避免三个入口各自实现映射。

## 7. 生产预检语义

删除“GPT-5.5、gpt-image-2、seedance 2.0 必须全部启用”的固定名称判断。生产预检改为通过统一公开目录验证：

- 文本、图片、视频三个核心类别各至少有一个已验证、已启用、已定价的公开模型；
- 公开目录中的每个条目都有非空模型 ID、非空展示名称、合法正整数积分价格；
- 管理员主动停用的模型不计入缺失，也不会被预检重新启用。

若某个核心类别没有可用模型，预检明确返回缺失类别并阻止部署。

## 8. 回归门禁

扩展 `model-ui-protection-v1`：

1. 后端模型价格服务必须包含并返回 `public_note`。
2. 画布目录必须把 `display_name` 映射为 `label`、把 `public_note` 映射为 `note`。
3. 首页和自由创作必须从 `/billing/catalog` 读取模型元数据。
4. 画布和短剧工厂必须从 `/canvas/model-catalog` 读取展示元数据。
5. 短剧工厂供应商调用必须继续使用原始模型 ID。
6. 公开目录必须保留验证、启用和正价过滤条件。
7. 生产预检不得重新依赖固定模型名称。

门禁测试使用源码变异分别删除备注映射、公开目录调用和启用价格过滤，确认门禁会失败；恢复代码后门禁必须通过。

## 9. 测试与验收

### 后端自动化

- 模型价格服务新增、更新、回读和长度校验测试。
- 管理员接口保存备注并回读测试。
- 普通用户目录只返回已验证、启用、定价模型，并包含展示名称和备注。
- 画布目录正确映射 `label` 与 `note`。
- 管理员停用历史模型后，预检仍在同类别存在其他公开模型时通过；最后一个核心类别模型停用时预检失败。

### 前端自动化

- 首页模型选择显示管理员名称并实时显示备注。
- 自由创作显示名称与备注。
- 画布所有生成节点选项使用目录名称，选择后显示备注。
- 短剧工厂三个视频模型入口显示统一名称和备注，任务提交仍使用原始模型 ID。
- 管理后台备注可保存、刷新回读并参与搜索。

### 线上验收

1. 管理员为一个启用模型修改展示名称和备注。
2. 刷新首页、自由创作、画布和短剧工厂，逐页确认名称和备注完全一致。
3. 在各入口选择该模型，确认请求审计中的模型 ID 未改变。
4. 管理员停用该模型，确认普通用户目录不再返回它，生成接口拒绝直接构造的调用。
5. 恢复原状态时只通过管理员接口操作，不直接修改数据库。

## 10. 发布与回滚

发布候选必须从实时 `/opt/moli-drama/current` 克隆，只合入本功能及已验证的 USMercari 502 上传重试提交。候选通过全量测试、前端构建、模型 UI 门禁、积分卡片合同门禁和生产预检后，使用共享受保护激活脚本切换。

数据库变更只新增带默认值的列。代码回滚到上一 release 后旧代码会忽略该列，不需要破坏性数据库回滚。发布前后必须核对活动任务、备份、健康检查、错误日志和 AI 音乐进程 PID 隔离。
