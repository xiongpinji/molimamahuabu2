# 画布自动保存容灾与消息去重设计

## 状态

- 设计日期：2026-08-24
- 设计状态：方案已获用户批准，等待书面规格复核
- Git 基线：`523ac09eeed7da427cf69d3c91cd16eb78e29994`
- 后续交付：独立实现计划、独立业务 PR、独立增量候选
- 本文档只定义设计，不授权实现、推送、部署、生产写入或付费调用。

## 背景与已确认事实

2026-08-24 的生产发布窗口内，后端短暂停止后，浏览器对
`PUT /api/v1/dramas/:id/canvas-layout` 的自动保存连续收到 `502`。全局 Axios
拦截器和 `DramaCanvas.vue` 的局部 `catch` 同时提示错误，多次自动保存又各自重复提示，
最终形成多条“服务暂时不可用，请稍后重试”。

当前实现已经具备两个重要基础：

1. `createCanvasLayoutPersistence` 串行发送快照，失败后保留 `dirty`，人工再次调用
   `flush()` 可以恢复。
2. 保存请求携带项目 `updated_at` 作为 `base_updated_at`，后端可用并发基线拒绝旧快照。

缺口是：失败后没有自动重试；同一故障会被全局和局部两层重复提示；重试等待期间的新改动
没有明确的“只保留最新快照”合同。

## 目标

1. 短暂断网或网关 `502/503/504` 时，画布布局保留为未保存状态并自动恢复保存。
2. 重试期间继续接受用户操作，只提交最新画布快照，不让旧快照覆盖新快照。
3. 同一连续故障最多提示一次；恢复后最多提示一次，不再堆叠错误消息。
4. `400/401/409` 等非瞬时错误不自动重试，不掩盖权限、参数或并发冲突。
5. 保留现有布局、工作流分组、并发基线和刷新回读语义，不修改生成、积分或供应商逻辑。

## 非目标

- 不把所有 API 请求统一改成自动重试。
- 不重试图片、视频、文本或其他可能产生费用的生成请求。
- 不修改后端画布接口、数据库结构或并发冲突规则。
- 不承诺浏览器标签页已经关闭后仍能完成异步保存。
- 不用无限错误弹窗代替明确的顶部保存状态。
- 不顺带重构画布历史、工作流、节点编辑器或素材逻辑。

## 方案选择

采用“单写入协调器 + 仅布局自动重试 + 单一消息所有者”。

未采用以下方案：

- **Axios 全局重试：** 无法可靠区分幂等布局保存与付费生成，存在重复提交风险。
- **每次失败立即重试：** 发布或网络故障期间会形成请求风暴，并继续堆叠提示。
- **只隐藏错误消息：** 虽然界面安静，但未保存内容仍可能在刷新后丢失。

## 范围与组件边界

### `frontweb/src/utils/canvasLayoutPersistence.js`

继续作为画布保存的唯一协调器，负责：

- 保存 `revision`、`savedRevision` 和最新布局快照；
- 任意时刻最多一个保存请求在途；
- 瞬时失败后的退避定时器；
- 重试等待期间用新快照替换待提交旧快照；
- 成功、等待重试、永久失败和销毁状态通知；
- 组件销毁时清除定时器，不在后台继续访问已销毁页面。

协调器不得引用 Vue、Element Plus、路由或具体 API，以便使用 Node 内置测试完整验证。

### `frontweb/src/api/drama.js`

`saveCanvasLayout` 增加可选请求配置透传。画布保存调用固定传入
`{ silentError: true }`，只禁止全局错误弹窗；`401` 的会话清理和登录跳转继续由全局拦截器执行。

### `frontweb/src/views/DramaCanvas.vue`

负责组装当前布局快照、将协调器状态映射到顶部状态文字，以及显示一次性故障/恢复消息。
页面不再为同一保存错误同时触发全局与局部提示。

工作流分组的新增、删除、排序属于需要即时确认的显式操作。其失败仍由调用方回滚，不能被后台
重试悄悄重新写回。自动重试只适用于不包含 `workflowGroups` 的画布布局快照。

## 保存状态机

| 状态 | 含义 | 界面 | 后续动作 |
| --- | --- | --- | --- |
| `idle` | 无待保存修改 | 不显示 | 等待修改 |
| `saving` | 一个布局请求在途 | “保存中…” | 禁止并发发送，允许更新待提交快照 |
| `retry_wait` | 瞬时失败且已安排重试 | “连接中断，等待重试…” | 到期后提交最新快照 |
| `saved` | 最新 revision 已确认保存 | “已保存” | 2 秒后回到 `idle` |
| `error` | 非瞬时错误或并发冲突 | “保存失败” | 停止自动重试，保留 dirty |
| `disposed` | 页面已卸载 | 不显示 | 清除定时器，禁止新请求 |

状态只能由协调器的单一写入循环推进。Vue 层不能另建第二条 Promise 队列，否则重试期间的新快照
无法及时进入协调器。现有 `canvasPersistQueue` 在实现阶段应由协调器职责取代，而不是与其并存。

## 数据流与“最新快照”合同

1. 画布交互产生布局变化，先同步当前渲染节点到完整图数据。
2. 组件生成不含本地预览 URL 的可持久化快照，递增 revision，并立即交给协调器。
3. 若没有请求在途且不在退避期，协调器发送当前最新 revision。
4. 若请求在途或等待重试，新快照只更新待提交值和 revision，不创建第二个并发请求。
5. 请求成功时，仅将该次发送的 revision 标记为已保存；如果期间 revision 已增加，立即继续发送
   最新快照。
6. 瞬时失败时保持 `savedRevision < revision`，进入退避；重试发送退避结束时的最新快照，而不是
   原失败快照。
7. 显式工作流分组保存失败后，调用方恢复旧分组；协调器不得保留或后台重放已经回滚的分组值。

任何时刻都必须满足：`savedRevision <= revision`；只有 `savedRevision === revision` 才能清除
`dirty` 并显示“已保存”。

## 重试规则

### 允许自动重试

- 请求没有收到 HTTP 响应，例如断网、连接重置或代理连接中断；
- HTTP 状态为 `502`、`503` 或 `504`；
- 请求是只包含画布布局的幂等 `PUT`，不包含工作流分组写入，也不触发任何生成或扣费。

### 禁止自动重试

- `400`：参数或合同错误；
- `401`：认证失效，继续执行既有登录跳转；
- `403`：权限错误；
- `409`：`base_updated_at` 并发冲突；
- 其他明确的 `4xx/5xx`；
- 页面已卸载；
- 显式工作流分组保存。

### 退避序列

连续瞬时失败按 `2 秒 → 4 秒 → 8 秒 → 15 秒` 退避，此后每次保持 15 秒。成功后计数归零。
每个画布实例最多一个定时器和一个在途请求。新的用户操作不能绕过当前退避立即形成请求风暴，
但会替换等待中的旧快照。

这里的重试安全依赖后端 `base_updated_at` 并发基线：若先前请求实际已经写入但响应丢失，旧基线
的重试会得到 `409` 并停止，不能覆盖服务端更新。该情况不自动拉取合并，避免未经确认的冲突覆盖。

## 消息与用户体验

- 画布保存请求固定使用 `silentError`，全局拦截器不弹保存错误；认证跳转不受影响。
- 连续瞬时故障第一次发生时，最多显示一次：“网络暂时不可用，画布将在后台自动重试保存”。
- 同一故障周期的后续失败不再弹窗，顶部状态持续显示“连接中断，等待重试…”。
- 最新快照最终保存后，最多显示一次：“画布已恢复并保存”。随后故障周期结束。
- 非瞬时错误最多显示一次具体可读错误，顶部保持“保存失败”，不自动假装恢复。
- 用户继续编辑时不清除错误事实；只有最新 revision 成功才显示“已保存”。

## 测试设计

### 协调器单元测试

1. 首次无响应失败后按 2 秒重试并成功，dirty 从 true 变为 false。
2. 连续失败严格使用 `2/4/8/15/15` 秒序列，成功后重置。
3. 退避期间产生多个 revision，只发送最新快照，不发送中间旧快照。
4. 任意时刻只有一个请求在途、一个重试定时器。
5. `502/503/504` 和无响应可重试；`400/401/403/409/500` 不重试。
6. 销毁协调器会取消定时器，之后不再发送。
7. 工作流分组失败后不会在后续布局重试中重新出现。
8. 现有交错布局与导演状态合并、失败保持 dirty、并发基线测试继续通过。

测试使用可注入的定时器或假时钟，不等待真实 15 秒，也不访问网络。

### 组件与 API 合同测试

1. `saveCanvasLayout` 可透传 `silentError`，画布调用确实启用它。
2. 同一连续故障只有一个失败通知，恢复只有一个成功通知。
3. 顶部状态覆盖 `saving/retry_wait/saved/error`。
4. 多次拖拽或缩放期间的自动保存不产生并发 PUT。
5. 工作流分组失败仍回滚，布局自动重试不恢复被回滚分组。
6. `401` 仍清理会话并跳转登录；`409` 停止重试并显示冲突错误。

### 浏览器回归

在本地可控代理中让 `canvas-layout` 依次返回瞬时错误和成功，验证：

- 画布操作不中断；
- 错误消息不堆叠；
- 恢复后刷新页面仍能读取最后一次布局；
- Network 中没有并发保存或退避期请求风暴；
- 非瞬时错误不会自动重试。

该回归不调用图片、视频、文本或其他付费模型。

## 完成标准

- 瞬时故障能够自动退避并最终保存最新布局；
- 旧快照不能覆盖新快照，被回滚的工作流分组不能被后台重放；
- 同一故障周期最多一次失败提示和一次恢复提示；
- 非瞬时错误不自动重试；
- 现有画布保存、工作流、并发基线和刷新回读回归全部通过；
- 没有新增生成请求、积分变化或供应商调用。

满足这些条件只代表画布自动保存改动可进入独立发布审查，不代表共享发布门禁优化已经完成。
