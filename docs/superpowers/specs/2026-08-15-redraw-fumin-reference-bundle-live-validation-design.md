# 一键转绘 Fumin Mini 参考包真实样片验证设计

日期：2026-08-15

状态：设计方案、`30–35 秒` 片段选择和书面规格均已批准

范围：仅本地集成、预检与单次真实供应商验证；不部署、不写生产数据库、不恢复线上入口

## 1. 背景

当前分支已经使用合成 fixture 完成供应商无关的 `redraw-reference-bundle-v1` 本地门禁：

- fixture 中的 2 张可辨认人脸均绑定到唯一、已批准的虚构 AI 美国成年角色身份包；
- fixture 中的 2 个文字区域分别由字幕净景和屏幕文字净景证据覆盖；
- 目标语言和市场固定为 `en-US` / `US`；
- fixture 角色姓名固定为 `Ethan` 和 `Maya`；
- 运动参考为 5 秒 H.264 视频，尺寸为 864 × 496，音频流数量为 0；
- 供应商投影只产生已批准的身份图、净化运动参考、英文提示词及哈希快照；
- 本地回归为 353 项测试、352 项通过、0 项失败、1 项跳过。

该 fixture 不能作为用户源片的真实人物、文字或运动参考。现有证据只证明本地合同可以进入供应商集成阶段，不证明 Fumin 能完成全人物转绘、英文对白、中文文字清除或可下载成片。此前真实 5 秒样片还暴露过两类问题：源片中文音轨可能随视频参考进入请求；两句英文对白可能在 5 秒内被改写或截断。因此，本阶段必须先为用户源片重新建立真实参考包，再把参考包门禁、单句对白和唯一付费提交放入同一条可审计链路。

## 2. 已批准的成功标准

用户选择“完整验收”。供应商返回 `completed` 不是最终通过，只有以下条件全部满足才标记本阶段通过：

1. 供应商只受理 1 次 `seedance-2.0-mini`、480p、16:9、5 秒请求；
2. 任务到达明确成功终态，成品 MP4 可下载并读取；
3. `ffprobe` 确认视频时长约 5 秒、分辨率属于 480p 请求档，并包含音频流；
4. 本地 ASR 确认主要语言为英语，目标台词经标准化后没有改写、遗漏或新增对白；
5. 可辨认人物不再保留源身份，且与已批准的目标身份包一致；
6. 发型、身体外观和服装按目标角色约束完成替换，不把转绘降级为换脸；
7. 字幕和场景中的中文可读文字已清除；
8. 剧情动作、镜头构图、运动方向和 5 秒时间节奏仍与源镜头对应；
9. 请求、任务、成品、费用和参考包哈希证据完整，且不包含 Key、Authorization 或本地绝对路径；
10. 人工视觉审核明确通过。

任一内容验收项失败时，供应商成品只能记为候选，不得写成“一键转绘已通过”。

## 3. 方案选择

### 3.1 采用方案

采用“当前参考包分支 + 选择性 Fumin 集成 + 单次真实验证”：

1. 以当前参考包分支为唯一实现基线；
2. 在独立工作树中选择性移植或重新实现已审计的 Fumin 客户端能力；
3. 不整体合并旧 Fumin 分支；
4. 先完成本地单元测试、Stub 同链和真实请求 dry-run；
5. 完成价格、余额、素材和单次锁门禁后，才允许执行唯一一次真实 POST；
6. 对同一个供应商任务轮询、下载、媒体检测、ASR 和视觉验收。

### 3.2 未采用方案

- 独立直调脚本：只能证明供应商接口，不能证明一键转绘产品链路。
- 整体合并旧 Fumin 分支：两条分支历史差异过大，会带入大量无关改动和删除。
- 继续只增强提示词：既有真实样片已经证明这不能约束人物替换和完整对白。
- 自动重试：创建请求结果不确定时可能造成重复扣费，明确禁止。

## 4. 固定输入

### 4.1 源镜头

- 本地源文件：只在运行时读取用户指定 MP4，不在文档、日志或证据中记录绝对路径；
- 源媒体只读检查：HEVC、720 × 1280、约 68.733 秒，包含 AAC 音轨；
- 取样范围：源文件 `30.000–35.000 秒`；
- 用户已在抽帧比较后选择该片段，替代原先人物过多的前 5 秒；
- 该片段固定抽帧显示 1 位可辨认前景角色，并同时包含中文字幕和电视屏幕文字；
- 源文件和分段文件均记录 SHA-256；
- 原始源视频不得直接作为 Fumin 参考；
- 供应商只能接收由该片段派生并通过审核的净化运动参考；
- 若逐帧覆盖审核发现第 2 位可辨认人物，本轮直接进入 `blocked_before_submit`，必须重新选择片段或另行批准扩大身份范围；禁止忽略背景人物，也不得临时增加本次请求的身份数量。

源片为 9:16，当前已验证的 Fumin 请求合同固定为 16:9。净化运动参考必须把完整竖屏画面确定性适配到 16:9 画布，不得通过中心裁剪丢失人物、动作或文字区域。本阶段的“1:1”指剧情、动作、镜头顺序和时间节奏对应，不代表像素级或画幅级一致。

### 4.2 净化运动参考

真实源片参考不得复用合成 fixture。必须针对 `30.000–35.000 秒` 新建：

1. 对每一帧建立完整人物区域和文字区域覆盖；
2. 对人物的脸、头发、身体和服装整体做不可识别化处理，只保留动作轮廓、位置、遮挡关系和相机运动；
3. 对中文字幕和电视屏幕中文字做净景或不可读化处理；
4. 移除全部音轨；
5. 编码为 H.264，并适配到固定 16:9 参考画布；
6. 固化源片段哈希、覆盖哈希、输出哈希和审核结果。

固定抽帧、OCR 和人工审核必须确认：看不出源人物身份、发型和服装，不存在可读中文，且动作和镜头运动仍可辨认。未通过时不得创建 Fumin 请求。

### 4.3 角色身份

- 角色数量：1；
- 稳定角色：`character-001`；
- 目标姓名：`Ethan`；
- 身份来源：`fictional_ai_generated`；
- 成年状态：`verified_18_plus`；
- 目标国家：`US`；
- 每个身份包必须包含正面、侧面和全身三视图，并已通过一致性审核；
- Fumin 请求中只投影 1 张已批准的三视图合成身份图。

不得使用真实自然人的身份资料。本轮只允许上述 1 个角色；若覆盖审核发现新增人物，按付费前门禁停止，不得让新增人物复用 `Ethan` 身份。

### 4.4 文字净景

- 文字类型数量：2；
- 类型：`text_subtitle`、`text_screen`；
- 物理区域数量不预设；字幕、电视画面中的每个独立可读区域均须单独记录多边形和时间范围；
- 区域时间范围必须覆盖文字实际出现的全部帧，不要求每个区域单独覆盖整个 0–5000 ms；
- 两类区域覆盖的并集必须能解释所有可读中文字幕和所有电视屏幕文字；
- 净景资产、区域时间范围和审核状态必须包含在参考包哈希中；
- 净景资产用于证明运动参考已清除中文文字，不额外作为 Fumin `reference_image` 发送。

### 4.5 对白

- 目标语言固定为 `en-US`；
- 只允许 1 条已审核英文台词；
- 台词必须绑定稳定 `speaker_id` 和对应美国姓名；
- 词数必须满足既有每秒 2.5 个英文单词的安全门禁；
- 提示词要求逐字说出台词，不得翻译、改写、遗漏或新增；
- 源中文台词、源角色姓名和中文音轨不得进入供应商请求；
- 本阶段不发送 `reference_audio`。

有声验收依赖 Fumin 根据英文提示词生成音轨，不虚构未验证的供应商音频开关参数。

本片段固定对白合同：

| 字段 | 值 |
| --- | --- |
| speaker_id | `character-001` |
| target_character_name | `Ethan` |
| delivery | `voice_over` |
| relative_start_ms | `200` |
| relative_end_ms | `3800` |
| target_text | `But now he doesn't even have any capital.` |

提示词中的 `Ethan` 是角色绑定标签，不要求把姓名作为台词内容说出。`voice_over` 表示生成英语画外音，不应强迫源镜头中闭口角色产生与原动作冲突的说话口型。3800–5000 ms 不得新增可辨识对白，只保留自然环境声。

## 5. Fumin 请求合同

本地模型别名和供应商模型名必须分开：

- 本地别名：`fumin-seedance-2.0-mini`；
- 上游模型：`seedance-2.0-mini`。

固定请求参数：

| 字段 | 固定值或约束 |
| --- | --- |
| model | `seedance-2.0-mini` |
| resolution | `480p` |
| ratio | `16:9` |
| duration | `5` |
| watermark | `false` |
| text content | 服务端参考包生成的英文提示词 |
| image references | 恰好 1 张已批准身份合成图 |
| video references | 恰好 1 个净化、无音轨运动参考 |
| audio references | 0 |

请求不得包含原始源视频、原人物身份图、中文台词、中文姓名、客户端提供的媒体 URL、Key 或本地路径。

## 6. 本地集成边界

### 6.1 工作树

实现阶段从当前参考包 HEAD 创建独立分支和工作树。旧 Fumin 分支只作为只读代码来源，禁止执行整体 merge。

允许修改的范围必须在实施计划中逐文件列出，至少分为：

- Fumin 请求构造、提交和查询客户端；
- 参考包到 Fumin 请求的适配层；
- 单次真实验证运行器；
- 对应测试和脱敏证据文档。

不得顺手修改前端入口、生产配置、价格表、其他供应商或部署脚本。

### 6.2 本地验证顺序

1. 为参考包到 Fumin body 的投影编写失败测试；
2. 实现最小适配；
3. 使用本地 Stub 完成创建、轮询、下载和状态回写；
4. 对完整目标测试组执行新鲜回归；
5. 生成不含 Key 的真实请求 dry-run；
6. 通过付费前门禁后才进入真实 POST。

本地 Stub、单元测试和 dry-run 均不得被写成真实供应商成功证据。

## 7. 付费前门禁

真实 POST 前必须在同一次运行中逐项通过：

1. 本地 Key 文件存在、非空，只注入当前进程环境；
2. 使用 Key 执行只读模型目录请求，确认 `seedance-2.0-mini` 可见；
3. 重新读取 Fumin 当前公开定价；
4. 取得当前账号的精确预估费用和可用余额证据；
5. 当前余额大于本次精确预估费用；
6. 在 POST 前向用户展示精确预估费用；由于当前授权没有金额上限，必须取得该金额的最终确认；
7. 1 张身份图和 1 个运动参考的公网地址均能读取，MIME、字节数和 SHA-256 与本地证据一致；
8. 运动参考经 `ffprobe` 复核为 5 秒、H.264、0 个音频流；
9. 参考包重新计算后与冻结哈希完全一致；
10. Git HEAD、请求 body 哈希、输入资产哈希和运行 ID 已写入本地状态；
11. 本次运行尚未执行过供应商 POST；
12. 本地单次提交锁以原子方式取得。

任一门禁失败时，在读取 Key 或供应商提交前能停止的步骤应尽早停止。余额或精确报价无法读取时，状态为 `blocked_before_submit`，不得猜测价格。

## 8. 唯一提交与恢复

运行状态保存在仓库外的私有本地目录，至少包含：

- `run_id`；
- `request_sha256`；
- `reference_bundle_hash`；
- 输入资产 SHA-256；
- `submit_status`；
- 脱敏供应商任务 ID；
- 创建时间和最后查询时间。

状态转换：

```text
preflight
  -> submitting
  -> submitted
  -> polling
  -> completed_candidate
  -> accepted | rejected
```

异常规则：

- HTTP 明确拒绝：`provider_rejected`，不重试；
- 已取得任务 ID：只查询同一任务，不再次 POST；
- 连接中断、超时、非 JSON 或无法确认供应商是否受理：`submission_unknown`；
- `submission_unknown` 必须人工核对供应商控制台和账单，禁止自动重试；
- 进程重启后只恢复已保存任务，不根据相同请求重新创建任务。

## 9. 成品验证

### 9.1 下载与媒体合同

- 只从成功终态返回的 HTTPS 地址下载；
- 下载结果写入仓库外的私有目录；
- 记录文件字节数和 SHA-256；
- `ffprobe` 必须能读取视频流和音频流；
- 时长容差为 4.5–5.8 秒；
- 输出尺寸必须属于 Fumin 480p 请求档的实际返回尺寸；
- 音频流数量必须至少为 1。

### 9.2 英语与台词

- 使用本地 Whisper 对成品音轨执行 ASR；
- 主要语言必须为英语；
- 目标台词与 ASR 文本统一小写、去标点并规范空白后必须逐词一致；
- 不允许额外出现可辨识的中文或其他新增对白；
- ASR 结果只在私有证据中保存，提交到仓库的报告只记录语言、词数和一致性结论，不记录完整台词。

### 9.3 视觉验收

从成品固定抽取 0.5、1.5、2.5、3.5、4.5 秒帧，生成仓库外联系表。审核必须确认：

- 所有可辨认人物均与目标身份包一致；
- 源人物身份不再可辨认；
- 发型、身体外观和服装完成目标化替换；
- 没有可读中文、字幕残留、Logo 或水印；
- 动作顺序、镜头构图、运动方向和节奏与源镜头对应；
- 没有明显的人脸漂移、肢体畸变、身份交换或画面闪烁。

自动抽帧和 OCR 只能形成候选证据，最终仍要求人工视觉审核。人工审核未完成时状态保持 `completed_candidate`。

## 10. 费用证据

只记录以下脱敏字段：

- 定价版本或采集时间；
- 模型、分辨率、时长和是否包含视频输入；
- 提交前余额、提交后余额和实际差额；
- 供应商任务 ID；
- 是否与预估费用一致。

报告不得记录 Key、Authorization、完整响应头、账号邮箱、用户 ID 或充值信息。

## 11. 结果分类

| 状态 | 含义 |
| --- | --- |
| `blocked_before_submit` | 价格、余额、素材、哈希或锁门禁未通过，没有 POST |
| `provider_rejected` | 供应商明确拒绝，没有自动重试 |
| `submission_unknown` | 可能已受理但未取得可靠任务 ID，必须人工核账 |
| `provider_failed` | 已有任务到达明确失败终态 |
| `completed_candidate` | 成品已下载，但内容或人工验收尚未全部通过 |
| `rejected` | 成品可读，但至少一项完整验收失败 |
| `accepted` | 供应商、媒体、英语、台词、人物、文字、运动和人工审核全部通过 |

只有 `accepted` 可以报告“Fumin 5 秒完整样片验收通过”。其他状态必须如实保留边界。

## 12. 安全与非目标

本阶段明确禁止：

- 第二次真实供应商提交；
- 自动重试未知提交；
- 15 秒或整集付费生成；
- 720p、1080p 或其他模型；
- 使用真实自然人身份素材；
- 把 Key 写入代码、配置、数据库、日志、报告或 Git；
- 写生产数据库、SSH、制作生产候选、部署或恢复线上入口；
- push、PR 或合并到其他分支；
- 用本次单镜结果宣称整集 1:1 复刻完成。
