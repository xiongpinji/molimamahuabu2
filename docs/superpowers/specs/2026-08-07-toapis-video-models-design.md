# ToAPIs Seedance 2 视频模型全站接入设计

## 1. 已锁定范围

新增独立供应商协议 `toapis_video`，不修改或复用现有 `usmercari_media` 协议。接入以下真实模型 ID：

- `seedance-2-fast`：只开放 480P、720P；
- `seedance-2-mini`：只开放 480P、720P。

新增模型默认全站同步，不再逐入口询问。统一目录必须覆盖：

- 管理员 AI 配置和模型收费；
- 首页快速生成；
- 独立画布和项目画布的视频节点；
- 短剧工厂的单分镜、批量、一键生成和失败修复路径。

本轮生产发布还要包含尚未上线的 USMercari 图片模型候选：

- `gpt-image-2-2-4k`：只开放 1K、2K；
- `nano-banana-2`：开放 1K、2K、4K。

视频与图片分别通过真实供应商门禁后，才从实时线上 `current` 制作一个合并候选并一次发布。

## 2. 选定架构

采用独立 `toapis_video` 适配器，而不是把 ToAPIs 模型塞入 USMercari 客户端：

- ToAPIs 使用 `POST /v1/videos/generations` 和 `GET /v1/videos/generations/{task_id}`；
- USMercari 使用 `/cpa-file/submit/video` 和 `/cpa-file/fetch`；
- 两者的任务字段、参考素材结构、错误格式和结果地址合同不同；
- 独立协议能保留供应商级停用、验证、计费和故障隔离。

前端只消费后端统一模型目录。展示名称和公开备注由管理员维护，生成时始终提交真实模型 ID，不为分辨率拆伪模型名。

## 3. 供应商请求合同

### 3.1 创建和轮询

```text
POST https://toapis.com/v1/videos/generations
Authorization: Bearer <服务端密钥>
Content-Type: application/json

GET https://toapis.com/v1/videos/generations/{task_id}
Authorization: Bearer <服务端密钥>
```

创建请求的公共字段为：

```json
{
  "model": "seedance-2-fast",
  "prompt": "镜头提示词",
  "duration": 4,
  "aspect_ratio": "16:9",
  "resolution": "480p",
  "generate_audio": false
}
```

后端同时保存供应商 `task_id` 和本平台任务 ID。状态只接受 `queued`、`in_progress`、`completed`、`failed`。完成态从 `result.data[0].url` 取得候选 MP4；候选地址必须下载、验媒体并落入本站资产后，平台任务才可写为成功。

创建请求发生网络中断且无法确认供应商是否受理时，不得自动重新 POST。只能按本平台幂等键和已保存任务号恢复轮询，避免重复付费。

### 3.2 时长、比例和数量

- 两模型数量固定为 1；
- 两模型只允许 480P、720P；1080P 必须在前端、目录和后端预扣前同时拒绝；
- `seedance-2-fast` 允许 4 至 15 秒整数，本平台不开放自动时长；
- `seedance-2-mini` 先按官方保守离散集合 4、8、10、12、15 秒开放；
- 首轮真实验证统一使用 4 秒、16:9、`generate_audio=false`，控制费用并减少变量；
- 用户显式勾选同步音频时才发送 `generate_audio=true`，该能力须单独通过真实验证。

现有全局“视频最短 5 秒”校验不得直接放宽给所有模型；只对目录明确声明 4 秒能力的 ToAPIs 模型开放。

## 4. 参考素材合同

两个模型都按官方角色字段接入：

- 首帧：`image_with_roles[].role = first_frame`；
- 尾帧：`image_with_roles[].role = last_frame`；
- 多图参考：`image_with_roles[].role = reference_image`；
- 参考视频：`video_with_roles[].role = reference_video`；
- 参考音频：`audio_with_roles[].role = reference_audio`。

首尾帧模式与全能多模态参考模式是互斥场景，不混发。前端切换模式时保留各自草稿，但请求构造器只能选择一类合同；后端再次校验，禁止绕过。

参考素材必须先解析为供应商匿名可读取的公网 HTTPS URL。拒绝本机路径、相对地址、私网地址、带认证信息 URL 和未通过租户归属校验的素材。密钥、Cookie 和用户登录令牌不得转发给供应商。

首版只允许经本站归属校验后的 HTTPS 公网 URL；不启用 `asset://`、base64 直传或 ToAPIs 私域素材上传。它们若要开放，必须作为独立变更重新验证租户隔离、生命周期和供应商合同。

能力上限以真实验证结果和官方限制交集为准：Mini 最多 9 张图片、3 条视频、3 段音频；Fast 图片官方上限为 9 张，但视频和音频上限依通道而定，因此首版全能参考只开放 1 张参考图 + 1 条参考视频 + 1 段参考音频。Fast 扩大任一上限前必须重新真实验证并更新 `verified_capabilities`。

## 5. 管理员、目录和门禁

管理员配置新增：

- 供应商：ToAPIs 视频；
- Base URL：`https://toapis.com`；
- 提交 Endpoint：`/v1/videos/generations`；查询 Endpoint：`/v1/videos/generations/{task_id}`；
- 协议：`toapis_video`；
- 模型 ID、展示名称、公开备注；
- 480P/720P 的人民币成本每秒和用户积分每秒；
- 已验证的分辨率、时长、首尾帧、多图、参考视频、参考音频、同步音频能力；
- `pending`、`verified`、`failed` 状态和启停开关。

用户目录必须同时满足：配置启用、服务端存在密钥、模型验证状态为 `verified`、当前入口所需能力已实测、当前分辨率已定价、积分为正整数。任何一项缺失时不显示或禁止提交，并在后端再次阻断。

所有可生成节点继续保留 `canvas-credit-callout-v1`：已定价时醒目加粗显示“本次预计扣除 X 积分”，缺价时显示“积分待管理员配置”并禁用提交。

## 6. 成本和积分

供应商原始成本按官方 ToAPIs credits/USD 记录证据，经营台账继续使用人民币微元/秒。发布时采用以下统一规则，不把美元数值误当人民币：

1. `1 USD = 200 ToAPIs credits`；
2. 会计换算率固定记录为 `1 USD = 7.30 CNY`，后续供应商或财务调整时由管理员修改；
3. 有参考视频与无参考视频价格不同时，当前只支持“模型 + 分辨率”档位，因此用同分辨率较高成本，避免低估；
4. 用户积分沿用已批准图片模型的约 875 积分/人民币元规则，向上取整；
5. 真实账户扣费高于公开价时，以真实账户较高值覆盖并重新计算积分，低于公开价时不自动降价。

按 2026-08-07 官方公开价形成的首版候选值如下，发布前仍须用实际账户证据复核：

| 模型 | 分辨率 | 供应商公开价 | 人民币成本/秒 | 用户积分/秒 |
|---|---:|---:|---:|---:|
| `seedance-2-fast` | 480P | 16 credits / $0.08 | ¥0.584 | 511 |
| `seedance-2-fast` | 720P | 16 credits / $0.08 | ¥0.584 | 511 |
| `seedance-2-mini` | 480P | $0.046 | ¥0.3358 | 294 |
| `seedance-2-mini` | 720P | $0.093 | ¥0.6789 | 595 |

预扣金额为“当前分辨率积分/秒 × 时长 × 数量”。供应商失败、成品下载失败、媒体校验失败或资产回填失败都进入现有幂等退款链。

## 7. 真实验证门禁

供应商模型列表、连接测试、任务已受理和 HTTP 200 都不能作为可用性证明。每个开放组合必须同一轮完成：

1. 使用目标 Key 创建任务；
2. 等待 `completed`；
3. 下载返回 MP4；
4. 用 ffprobe 校验容器、视频流、尺寸档位、时长，按声明能力校验音频流；
5. 记录不含密钥的任务号、时间、模型、请求参数、实际尺寸、时长、字节数、SHA-256 和可见计费证据；
6. 把成品保存为本站可长期读取的测试资产；
7. 只有通过的模型、分辨率和参考模式才能写入 `verified_capabilities`。

最低验证矩阵：

- 文生视频：2 模型 × 480P/720P，共 4 次；
- 首尾帧：2 模型 × 480P，共 2 次；
- 全能参考：2 模型 × 480P，共 2 次，每次同时验证参考图片、参考视频和参考音频；
- 同步音频：若作为用户能力开放，至少每模型 1 次；否则保持关闭。

当前已有三项文生视频候选完成了终态、下载和本地媒体校验：Mini 480P、Fast 480P、Fast 720P。脱敏任务号、实际尺寸、时长、字节数、SHA-256 和证据边界绑定在 `docs/TOAPIS_VIDEO_MODELS_VERIFICATION_20260807.md`。它们只能计入对应三项，不替代 Mini 720P，也不证明任何参考能力；缺少费用证据和本站长期资产前仍不得进入生产用户目录。

## 8. 测试和全站实操

实现采用测试先行，至少覆盖：

- `toapis_video` 的请求体、Bearer 鉴权、任务号解析、轮询状态和错误脱敏；
- 480P/720P 与模型特定时长在预扣前校验，1080P 不可绕过；
- 首尾帧与全能参考互斥，素材角色和顺序不丢失；
- 未验证、停用、缺 Key、缺价或能力不匹配时目录和后端共同阻断；
- 首页、两类画布和短剧工厂共享展示名、备注、能力、分辨率与价格；
- 单分镜、批量、一键和修复路径都传递相同模型快照；
- 异步恢复不重复提交、不重复扣分或退款；
- 成品下载、媒体校验、本站资产落库和节点/分镜回填闭环；
- 现有 USMercari 视频、图片分档和 `canvas-credit-callout-v1` 不回归。

浏览器验收必须实际操作每个入口的模型选择、分辨率、时长、参考模式、扣分提示、提交、运行态、完成态、成品播放、下载和刷新后持久化。静态按钮、单测或构建不算实用性通过。

## 9. 合并和生产发布

现有图片候选有大量未提交改动且落后主线，禁止直接 merge、rebase、stash 或整体覆盖。安全顺序为：

1. 审计图片候选并建立本地备份分支；
2. 将已确认的图片改动形成可恢复 checkpoint 提交；
3. 从最新主线形成合并分支，依次叠加 ToAPIs 视频和图片候选；
4. 跑后端全量、前端定向与全量、生产构建、浏览器 E2E、真实供应商和账务审计；
5. SSH 读取实时 `/opt/moli-drama/current`，从实时 release 克隆生产候选；
6. 仅复制审计 allowlist 文件，执行备份、部署锁、活动任务、健康、日志、AI 音乐隔离和 CAS 检查；
7. 只用共享 `activate-protected-release.sh CANDIDATE EXPECTED_CURRENT` 激活；
8. 激活后复核模型目录、四类前端入口、积分、成本、成品和错误日志。

任一真实生成、计费、回归或共享门禁失败时停止发布，不以部分成功替代完整接入。
