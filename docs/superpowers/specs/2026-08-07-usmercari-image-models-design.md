# USMercari 两个图片模型全站接入设计

## 1. 目标与范围

接入供应商 `https://chat-ai.mercarimx.com/` 的两个图片模型：

- `gpt-image-2-2-4k`
- `nano-banana-2`

两个模型进入同一套管理员配置、模型目录、计费和生成链，并在以下用户入口保持一致：

- 首页快速生成；
- 画布图片节点与图片派生节点；
- 短剧工厂的角色、场景、道具和分镜图片生成；
- 管理员模型配置、展示名、用户备注、启停状态、验证状态和计费配置。

本阶段同时支持文生图和参考图生图。局部蒙版重绘不在范围内，因为供应商文档明确说明 `mask` 会被忽略。

## 2. 选定方案

采用“单一真实模型 ID + 1K/2K/4K 分辨率档位”的方案，不拆分六个伪模型名，也不对所有分辨率统一按 4K 收费。

每个模型在管理员后台只保留一条模型配置，真实提交字段仍为原始模型 ID。管理员展示名和用户备注只影响用户界面，不改变供应商请求中的 `model`。

图片分辨率价格复用现有 `model_resolution_prices` 思路，但将档位能力从视频专用扩展为按模型类别声明。视频现有 480P/720P 行为不得改变。

## 3. 供应商协议与数据流

### 3.1 文生图

后端调用：

```text
POST https://chat-ai.mercarimx.com/v1/images/generations
Authorization: Bearer <服务端密钥>
Content-Type: application/json
```

请求只包含受支持字段：`model`、`prompt`、`n`、`aspect_ratio` 和 `resolution`。前端不接触或保存供应商密钥。

### 3.2 参考图生图

站内 `/static/projects/...` 素材需要登录，供应商无法匿名拉取，因此不得把站内受保护 URL 直接放入 `image_url`。

后端先把每张站内参考图读取为受限大小的图片数据，调用 `POST /v1/media/upload/image` 换取供应商 media id，再以 JSON 调用 `POST /v1/images/edits`，发送 `model`、`prompt`、`n`、`aspect_ratio`、`resolution` 和 `image_ids`。按供应商文档最多接受六张参考图；前后端都必须在预扣前阻断第七张，禁止静默裁剪。

后端读取参考素材时继续执行租户、项目归属、文件类型、大小和路径安全校验。不得向供应商转发用户 Cookie、登录令牌或本机文件路径。

### 3.3 结果处理

供应商成功响应中的 `data[].url` 只是候选结果。后端必须在任务成功前完成：

1. 下载结果；
2. 确认 HTTP 成功、内容类型为图片且内容非空；
3. 保存进当前租户和项目的素材目录；
4. 写入图片生成记录、资产记录和画布/短剧工厂原有回填链；
5. 返回本平台稳定素材地址。

供应商 HTML 错误页、空数组、不可读 URL、超时或下载失败都属于生成失败，不得写成成功。

## 4. 模型目录与管理员同步

新增 USMercari 图片协议标识，和既有 USMercari 视频协议分开路由，避免同名 `nano-banana-2` 被送往项目已有的 NanoBanana 独立协议。

管理员后台需要支持：

- 供应商：USMercari 图片；
- Base URL：`https://chat-ai.mercarimx.com`；
- 模型 ID、展示名和用户备注；
- 文生图、参考图生图能力；
- 1K、2K、4K 可选分辨率；
- 每个分辨率独立的供应商成本和用户积分；
- `pending`、`verified`、`failed` 验证状态；
- 启用和停用。

首页、画布和短剧工厂只消费后端模型目录，不各自维护硬编码模型名单。用户界面显示管理员展示名和备注，生成请求始终提交真实模型 ID。

模型进入用户目录必须同时满足：

- AI 配置已启用且密钥存在；
- 管理员计费已启用；
- 当前分辨率已配置正整数积分；
- 模型验证状态为 `verified`；
- 当前入口需要的能力已通过真实生成验证。

## 5. 成本与积分

两个模型采用相同分辨率成本和扣分：

供应商定价截图中的金额就是人民币成本价，管理端按人民币元直接录入，不做美元换算：

| 模型 | 分辨率 | 后台成本（元/张） | 用户扣分 |
|---|---:|---:|---:|
| `gpt-image-2-2-4k` | 1K | ¥0.08 | 70 积分/张 |
| `gpt-image-2-2-4k` | 2K | ¥0.10 | 87 积分/张 |
| `gpt-image-2-2-4k` | 4K | ¥0.12 | 105 积分/张 |
| `nano-banana-2` | 1K | ¥0.08 | 70 积分/张 |
| `nano-banana-2` | 2K | ¥0.10 | 87 积分/张 |
| `nano-banana-2` | 4K | ¥0.12 | 105 积分/张 |

经营台账按上述人民币成本计算。供应商调价时由管理员更新成本和用户备注。

生成前按“模型 + 分辨率 + 数量”计算并预扣积分。页面继续展示受保护合同 `canvas-credit-callout-v1`：已定价显示醒目加粗的“本次预计扣除 X 积分”，缺少当前档位价格时显示“积分待管理员配置”且禁止提交。

## 6. 失败、退款与幂等

- 参数和能力校验必须发生在任务入库、积分预扣和供应商调用之前。
- 成功预扣后，供应商拒绝、网络失败、返回结构错误、结果下载失败或本地保存失败都进入现有终态退款链。
- 不得因连接中断自动重复提交付费生成；无法确认供应商是否已受理时标记为待人工核对，避免重复扣费。
- 同一任务的成功、失败和退款写入保持幂等；重复轮询或重试不得重复扣分或退款。
- 管理员停用模型后，新任务立即被目录和后端同时阻断，运行中的既有任务按原任务快照完成或退款。

## 7. 真实生成开放门禁

模型配置和通用客户端代码可以先存在，但模型不得在用户目录显示，直到完成以下同一轮验证：

1. 使用目标生产 Key；
2. `gpt-image-2-2-4k` 分别生成 1K、2K、4K；
3. `nano-banana-2` 分别生成 1K、2K、4K；
4. 至少各完成一次文生图；参考图能力另做真实图生图验证；
5. 每次等待真实成功终态；
6. 下载并打开结果文件，校验图片内容和实际尺寸档位；
7. 记录不含密钥的任务号、时间、模型、请求档位、实际尺寸、文件哈希和供应商计费证据；
8. 只有通过的“模型 + 能力 + 分辨率”组合才能写为 `verified` 并开放。

模型列表或只读连接测试不能替代上述真实生成。

## 8. 测试与验收

实现采用测试先行，至少覆盖：

- 两个模型被正确路由到 USMercari 图片协议；
- 文生图请求字段和鉴权头正确且不泄露密钥；
- 私有站内参考图走后端二进制上传，不传受保护 URL；
- 同名 `nano-banana-2` 不会误入旧 NanoBanana 协议；
- 图片 1K/2K/4K 分档成本和积分计算正确；
- 未验证、未定价、停用或缺少密钥时，三个用户入口均不显示或不能提交；
- 首页、画布和短剧工厂使用同一管理员展示名、备注和能力目录；
- 供应商失败、结果不可读和本地保存失败均完整退款；
- 成功结果进入资产、历史和对应节点/分镜回填链；
- 既有视频 480P/720P 分档价格和 USMercari 视频协议不回归。

发布候选还必须通过后端专项测试、前端专项测试、后端全量测试、前端构建、共享发布审计器和生产保护门禁。

当前 `origin/main` 基线的前端全量测试为 583 项中 573 通过、10 项既有画布交互契约失败；后端全量测试退出码为 0。该既有失败不在本任务中修复，但最终结果必须证明本任务没有增加新的失败，并单独报告全量基线差异。

## 9. 发布边界

本设计批准和本地实现都不等于授权生产切换。

如后续收到明确部署指令，必须通过 SSH 重新读取实时 `/opt/moli-drama/current`，从该实时 release 克隆候选，仅叠加本任务审计过的 allowlist 文件，完成备份、锁、活动任务、健康、日志、AI 音乐进程隔离和 CAS 检查，最后只使用共享 `activate-protected-release.sh` 激活。禁止从本地工作树整体覆盖线上版本。
