# 供应商任务不可变凭证与普通视频安全对账设计

## 状态

- 设计日期：2026-08-22
- 设计状态：方案 A 已获用户确认，等待书面规格复核
- 文档基线：`f17f87472b48668e5854969f445c916826eb40ac`
- 本文档只定义设计；不授权真实供应商请求、付费生成、生产数据库写入、推送、PR、合入或部署。

## 背景

平台已经具备统一供应商路由、供应商尝试记录、异步视频任务号、积分预扣与终态结算，以及巡检任务的单次状态查询能力。当前缺口是普通用户生成任务没有一份足以跨进程、跨重启和跨配置轮换进行安全对账的固定凭证。

生产只读盘点显示：

- 图片 `submission_unknown` 记录没有可查询的供应商任务号；
- 一条历史 ToAPIs 视频没有供应商任务号；
- 一条历史飞拓视频虽有任务号，但没有固定配置 ID 与配置版本指纹；
- 仅凭供应商名和模型名套用当前 Key 或端点会把不同账户、不同配置版本的查询结果误认为原任务结果。

因此，历史缺失证据不能通过猜测自动退款、重试或查询。本设计只解决未来任务证据完整性，以及证据完整的普通异步视频任务安全对账。

## 已确认决策

1. 采用方案 A：扩展现有 `generation_route_attempts`，不新建第二套供应商任务账本。
2. 自动对账第一版只覆盖同时具有供应商任务号、固定配置 ID 和固定配置指纹的异步视频任务。
3. 图片 `submission_unknown`、缺任务号的视频、缺配置指纹的历史视频只保留凭证并保持积分冻结。
4. 不从当前配置反向回填历史配置指纹，不按供应商名或模型名猜测配置。
5. 每次人工触发最多执行一次供应商状态查询；禁止重新提交、自动重试和自动切换线路。
6. 只有供应商明确终态和可信产物证据才能改变任务与积分终态。

## 目标

1. 供应商请求发出前，固定记录实际线路、配置指纹、查询协议、上游模型和积分预扣关系。
2. 获得供应商任务号后，将任务号绑定到同一次尝试，且身份字段不可再被改写。
3. 管理员能够通过内部请求 ID 对普通异步视频执行一次安全状态查询。
4. 成功、明确失败和未知三种结果分别形成一致的任务、路由、积分、成本和审计状态。
5. 并发点击、服务重启和迟到响应不能造成重复查询、重复退款、重复确认或状态倒退。
6. 普通用户与管理员响应均不泄露 Key、任务号、供应商 URL、提示词或原始上游响应。

## 非目标

- 不为缺失任务号或配置指纹的历史记录推断上游状态。
- 不自动退款结果未知任务。
- 不自动重新提交、重试或切换供应商。
- 不给同步图片协议虚构任务查询接口。
- 不保存明文 Key、Authorization、完整签名 URL、提示词或上游响应体。
- 不改变现有主动巡检任务的独立对账合同。
- 不触碰 AI 音乐项目、生产配置或生产数据。

## 方案比较

### 方案 A：扩展现有路由尝试表（采用）

`generation_route_attempts` 已经保存请求、尝试序号、配置 ID、供应商、上游模型、任务号和错误分类。增加凭证与对账字段后，路由、任务和积分仍以同一个尝试为事实来源。

优点：改动最小、没有双写账本、直接复用现有幂等路由和健康记录。缺点：必须明确区分不可变身份字段与可变生命周期字段。

### 方案 B：新建 `provider_task_receipts`

独立表的概念边界清晰，但会与路由尝试表重复保存配置、任务号和状态，需要额外解决双写失败与一致性修复。

### 方案 C：只扩展图片与视频业务表

初期改动较少，但每种业务会形成不同凭证和对账实现，不能统一约束身份、并发和审计，后续更容易漏接。

## 数据模型

在新的单一迁移中为 `generation_route_attempts` 增加：

| 字段 | 用途 |
| --- | --- |
| `config_fingerprint` | 提交时配置指纹；包含 Key、Base URL、协议、供应商、上游模型和能力配置的哈希，不含明文秘密 |
| `query_protocol` | 提交时解析出的规范化查询协议 |
| `reconcile_claim_token` | 对账所有权随机令牌 |
| `reconcile_lease_until` | 崩溃恢复租约到期时间 |
| `reconcile_checked_at` | 最近一次状态查询时间，用于去抖 |

约束：

- 新尝试必须在供应商请求前写入 `config_id`、`provider`、`upstream_model`、`config_fingerprint` 和 `query_protocol`。
- 任务号可以在供应商接受后由空值写入一次；已写入的非空任务号不得替换。
- 配置 ID、供应商、上游模型、配置指纹和查询协议一旦写入不得修改。
- 生命周期字段、错误分类、claim 和检查时间可以按状态机更新。
- 迁移重复执行必须幂等；旧行保持空指纹，不做不安全回填。

积分结算只以既有 `usage_reservations` / `tenant_usage_reservations` 和积分账本为权威事实源。路由尝试表不新增第二份结算状态；管理员响应中的积分状态必须在读取时从关联预扣记录计算，终态更新必须调用既有积分结算服务并与业务状态写入处于同一事务。

配置指纹复用现有 `providerCanaryEvidenceService.configFingerprint`，避免产生第二种配置身份算法。

## 提交数据流

1. 路由器选择候选配置。
2. `startAttempt` 在供应商请求前读取实际配置并计算配置指纹与规范化查询协议。
3. 尝试记录通过既有路由请求关联已经处于 `held` 的积分预扣；不复制积分状态。
4. 调用现有供应商适配器，不改变请求格式。
5. 若返回任务号，将其一次性绑定到该尝试和对应视频生成记录。
6. 若同步返回可信产物，沿用现有产物验证与积分确认路径。
7. 若提交结果未知且无任务号，路由进入 `needs_attention`、积分继续 `held`；禁止自动重提。
8. 若获得任务号但后续状态未知，保留任务号、固定凭证和 held 积分，等待管理员对账。

图片与文本同样记录配置指纹和协议；第一版对账器仍只允许异步视频进入网络查询。

## 管理员对账接口

新增普通生成任务对账端点，挂在现有管理员供应商稳定性路由下：

现有路由器内部路径为：

`POST /admin/provider-stability/requests/:requestId/reconcile`

按当前应用统一挂载后，对外完整路径为：

`POST /api/v1/admin/provider-stability/requests/:requestId/reconcile`

权限继续使用管理员与计费管理权限。请求体为空，不接受任务号、配置 ID、供应商、URL、`internal` 或绕过标志。

响应只包含：

- 内部请求 ID；
- 安全任务状态；
- 安全错误分类；
- 是否已完成对账；
- 是否仍可对账；
- 积分状态；
- 最近检查时间。

响应不得包含任务号、配置指纹、供应商、配置 ID、Key、Base URL、查询 URL、提示词、用户素材地址或原始上游响应。

## 可对账门禁

进入任何网络请求前必须同时满足：

1. 请求服务类型为 `video`。
2. 路由处于 `needs_attention`。
3. 最新尝试具有非空供应商任务号。
4. 尝试具有固定配置 ID、配置指纹和查询协议。
5. 对应视频生成记录存在且未删除，并与同一积分预扣关联。
6. 关联积分预扣的权威状态仍为 `held`。
7. 当前配置存在、未删除且具有查询凭据。
8. 当前配置指纹与提交时完全一致。
9. 当前解析出的查询协议与固定协议一致。
10. 没有未到期的对账 claim，且不在去抖窗口内。

任一条件不满足时返回安全的不可对账结果；不得访问 DNS、TLS 或供应商接口。

## 并发与幂等

- 使用 SQLite immediate transaction 原子取得随机 claim。
- 租约为 120 秒；最近查询去抖为 60 秒，与现有巡检人工对账保持一致。
- 未取得 claim 的并发请求返回当前安全状态，网络请求次数为零。
- 每个 claim 最多调用一次现有 `queryVideoTaskStatusOnce`。
- 最终写入使用 claim token、请求 ID、尝试序号和供应商任务号进行 CAS。
- 迟到响应、旧 claim 或已变化任务不能覆盖新状态。
- 已确认或已退款的重复请求返回相同终态，不查询供应商、不重复写审计。

## 查询结果与结算

### 明确成功

只有状态查询返回可信 HTTP/HTTPS 产物地址，并且现有下载器成功落盘、验证视频容器可读取后，才允许：

- 视频生成与异步任务转为 `completed`；
- 路由请求与尝试转为成功并记录产物验证；
- 积分预扣转为 `confirmed`；
- 成本按现有视频成本路径登记；
- 写入一次安全审计事件。

下载、校验或落盘失败归 `artifact_unreadable`，保持冻结，不伪造成功。

### 明确失败

只有供应商任务查询返回明确失败终态时，才允许在同一事务中：

- 视频生成与异步任务转为 `failed`；
- 路由请求与尝试转为失败；
- 积分预扣转为 `refunded`；
- 写入一次安全审计事件。

HTTP 4xx/5xx、鉴权异常、限流、网络异常或协议解析异常都不是供应商任务明确失败。

### 未知或查询故障

处理中、超时、网络异常、非 JSON、重定向、查询限流、鉴权异常、任务不存在、完成但无可信产物等结果继续保持：

- 路由、视频与异步任务为 `needs_attention`；
- 积分为 `held`；
- 只更新安全错误分类与检查时间；
- 不重新提交、不退款、不确认积分。

## 事务边界

- 供应商状态查询与产物下载发生在数据库事务外。
- claim 获取、终态校验和最终状态写入分别使用短事务。
- 最终成功或明确失败必须在一个数据库事务内完成路由、尝试、媒体任务、异步任务、积分和审计状态更新。
- 任一数据库写入失败必须整体回滚，保留原 held 状态与可恢复 claim 语义。
- 产物已经下载但 CAS 失败时只保留隔离临时文件并安全清理，不覆盖当前任务。

## 历史数据

- 迁移不为旧记录填充配置指纹或查询协议。
- 有任务号但缺指纹的历史记录仍不可自动查询。
- 没有任务号的图片或视频仍不可自动查询。
- 管理员可继续查看安全摘要和 held 积分，但系统不得建议连续重试。
- 历史任务只有取得供应商订单、任务归属或扣费证据后，才能通过单独的人工证据流程处理；该流程不属于本设计。

## 安全与隐私

- 配置指纹只保存 SHA-256 结果，不保存明文 Key。
- 普通用户 DTO 不增加任何供应商字段。
- 管理员 DTO 也不返回任务号、配置指纹、URL、提示词或原始响应。
- 日志只记录内部请求 ID、安全分类、状态和计数。
- 上游状态查询继续强制单请求、30 秒超时和禁止重定向。
- HTTP 请求体、query、header、Authorization 和上游响应体不得进入审计或错误消息。

## 测试与验收

实现必须先取得以下红灯，再以最小代码转绿：

1. 迁移重复执行和旧行不回填。
2. 凭证身份字段不可变，任务号只能由空写入一次。
3. 供应商请求前已经持久化配置指纹与查询协议。
4. 配置 ID、Key、Base URL、协议、模型或能力任一变化均在网络前阻断。
5. 缺任务号、缺指纹、图片请求和非 `needs_attention` 请求的网络调用次数为零。
6. 同一请求并发对账只发生一次上游查询。
7. 单次对账的网络请求数不超过一；不会调用供应商提交函数。
8. 成功且产物可读时任务完成、积分确认、成本和审计一致。
9. 明确失败时任务失败、积分退款且重复请求幂等。
10. 处理中、网络异常、协议异常和产物不可读时积分继续 held。
11. 任一终态数据库写入失败时全部回滚。
12. 迟到 claim 不能覆盖新任务状态。
13. 普通用户目录、管理员响应、日志和审计均不泄露敏感字段。
14. 现有视频恢复、统一路由、主动巡检对账、图片生成、计费与管理员 RBAC 回归继续通过。
