# 飞拓 MiniMax H3-2K 与 Seedance 2.5 接入设计

## 目标与范围

在不替换、不删除历史模型数据的前提下，接入飞拓中转站的两个上游模型：

| 上游模型 ID | 公开展示名 | 公开档位 | 成本 | 初始扣分 |
| --- | --- | --- | --- | --- |
| `xuan-video-v1-6e7b4763634e6206` | MiniMax H3-2K（飞拓） | 2K | ¥1.50/次 | 1313 积分/次 |
| `xuan-seedance-2.5` | Seedance 2.5（飞拓） | 480P、720P | ¥0.40/秒 | 350 积分/秒 |

积分按现行换算 `ceil(人民币成本 × 875)` 计算。`seedance-2.5` 不接入，避免同系列双渠道在前端重复和路由混淆。

本次一并发布已完成的画布图片预览修复：图片节点双击全屏后，`Ctrl`/`Command` + 鼠标滚轮可在 25%~500% 之间缩放，关闭时恢复 100%。

## 方案选择

采用“新上游 ID 新建公开模型，历史模型保留但不自动启用”的方案。

不直接把新 ID 替换到旧飞拓配置，因为这会使历史任务、价格记录和供应商任务 ID 失去精确归属。也不为新模型建立旧名别名，避免通用配置抢占飞拓专用路由。

## 配置与路由

1. 飞拓客户端仅接受显式列入能力表的模型 ID，未列入的飞拓模型在提交之前拒绝。
2. 新配置使用现有 `feituo_open` 协议和现有密钥；密钥不进入源码、文档、测试输出或发布证据。
3. 两个模型使用独立价格行和能力记录，不与旧 `sdas-lm-hailuo-h3-2k` 或其他 Seedance 模型共用验证状态。
4. 首页、画布和短剧工厂统一从 `/canvas/model-catalog` 读取展示名、备注、能力和价格，禁止为某个页面额外硬编码模型列表。

## 真实生成门禁

每个新模型初始状态为 `pending`，价格初始状态为 `disabled`。只有当该精确上游 ID 完成一次真实生成后，才允许同一事务内写入验证能力并启用价格。

每份真实证据必须同时包含：

- 精确上游模型 ID、脱敏供应商配置 ID 和供应商任务 ID；
- 请求参数摘要，不含 API Key；
- 建任务耗时、到成功终态耗时和成品下载耗时；
- 可读成品、SHA-256、实际尺寸、时长和视频编码；
- 供应商返回的费用或可对账的前后余额记录；
- 验证时间与候选发布版本。

连接测试、模型列表、提交成功或历史旧任务都不等于真实验证。生成失败、超时、结果无法下载或无法解析时，该模型继续隐藏。建任务结果不确定时禁止自动重试，避免重复扣费。

## 能力边界

- MiniMax H3-2K 公开为固定 2K 档，按次计费；不伪造 480P/720P 档位。
- Seedance 2.5 仅公开 480P 和 720P，两档相同秒单价；不公开 1080P。
- 时长、画幅、首尾帧、参考图/视频/音频和同步音频只按飞拓协议声明且实际请求验证的交集对外公开。
- 任何超出 `verified_capabilities` 的参数必须在创建任务、积分预扣和供应商请求之前拒绝。

## 管理员与公开展示

管理员可编辑展示名和公开备注。默认备注说明计费方式、开放分辨率与实测速度，不显示内部配置 ID、供应商密钥或证据本地路径。前端展示名与备注完全以统一目录为准。

## 测试与验收

### 自动化验收

1. 飞拓请求构造器对两个新 ID 产生正确请求，对 `seedance-2.5`、1080P 和超能力参数拒绝。
2. 未验证、未定价或协议不匹配的同名模型不得进入统一目录。
3. H3 按次扣 1313 积分；Seedance 480P/720P 按实际时长每秒扣 350 积分；无定价按钮不可运行。
4. 首页、独立画布、项目画布和短剧工厂对同一目录条目显示同一名称、备注、分辨率、时长和预计扣分。
5. 管理员修改展示名/备注后，四个前端入口无需发布新代码即同步。
6. 画布图片预览自动化测试覆盖放大、缩小、边界值、非图片不响应以及重新打开恢复 100%。

### 真实验收

1. 两个上游 ID 各完成一次付费生成，记录建任务、终态和下载耗时。
2. 成品可从公网和线上产品资产链路读取，`ffprobe` 可解析，哈希与证据记录一致。
3. 从首页、画布和短剧工厂分别执行至少一条真实产品请求链；如共享同一个已验证任务，必须另行验证每个入口的请求快照和成品回写。
4. 图片节点双击后，在真实浏览器中实测 `Ctrl` + 滚轮改变缩放百分比且图像尺寸随之变化。

## 发布与回滚

1. 发布候选必须从当时线上 `/opt/moli-drama/current` 新鲜复制，只合入审计过的差异。
2. 发布前运行单测、集成测试、前端构建、共享审计器、数据库备份、活动任务和健康检查。
3. 只能通过已安装的 `activate-protected-release.sh CANDIDATE EXPECTED_CURRENT` 切换，禁止直接修改 `current` 或替换共享门禁。
4. 模型配置与价格使用带备份的单事务写入；验证失败时回滚配置和价格，不删除历史任务。
5. 切换后如健康、日志、目录门禁或产品浏览器验收失败，按共享门禁恢复上一个 release，保留证据用于定位。
