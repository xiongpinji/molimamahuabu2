# 一键短剧转绘：真实英文本地化与资产批量生成设计

**日期：** 2026-08-07

**范围：** 一键短剧转绘阶段 2A/2B

**决策：** 采用 B 方案——第二次确认执行真实英文本地化；进入资产页后展示全量服务端报价，再由用户一次确认批量生成资产。

## 1. 背景与问题

当前转绘链路已经具备源视频上传与分析、资产审核门禁、单镜视频生成、任务记录和积分账本等基础能力，但分析完成后的前半链仍不完整：

- 分析任务完成后，工作可能直接进入 `asset_review/current_step=2`，尚未经过用户对分析结果和本地化费用的第二次确认。
- `POST /redraw/works/:id/versions` 接受客户端提供的本地化内容并直接创建版本，没有真实文本模型任务、供应商任务证据和独立结算。
- 资产路由虽然已有服务端计价与防客户端篡改，但应用启动时没有注入真实资产报价和生成供应商，无法完成真实人物、场景、道具和英文配音生成。
- `redraw_works.task_id` 当前承担源片分析任务关联，不能再被本地化或资产任务覆盖，否则会破坏分析证据和恢复能力。

本设计只修复从“分析完成”到“资产审核完成”的链路，不改造已存在的单镜视频生成、合成与导出体系。

## 2. 目标与非目标

### 2.1 目标

1. 分析完成后停留在明确的分析确认状态，由用户确认内容和英文本地化报价。
2. 第二次确认触发真实、可恢复、可计费的英文剧本本地化异步任务。
3. 本地化成功后创建目标版本，保留剧情事实、镜头时间、说话人和中英文台词映射。
4. 目标版本生成可编辑的外国人物、海外场景、道具和英文配音资产草稿。
5. 资产页展示全量服务端报价，用户一次确认后批量生成全部待生成资产。
6. 每项资产独立结算；失败项退款并可单独或批量重试，成功项不重复生成。
7. 未通过真实生成验证的模型不能被选择、展示或调用。

### 2.2 非目标

- 不承诺像素级逐帧复制原视频；“1:1”指剧情事实、镜头顺序、时间轴和台词语义保持一致。
- 不在本阶段重写单镜视频、合成、字幕导出或归档实现。
- 不新增未要求的人工团队协作、版本分支合并或跨项目资产共享。
- 不在开发和自动化测试中擅自调用付费供应商、修改生产配置或发布 `/opt/moli-drama`。

## 3. 用户流程与状态边界

### 3.1 完整流程

1. 用户上传源短剧并确认源片分析报价。
2. 服务端完成真实源片分析并写入源版本事实。
3. 工作停留在“分析结果待确认”，页面展示人物、场景、道具、分镜和台词分析结果，以及英文本地化报价。
4. 用户第二次确认后，服务端重新报价、验证余额、冻结积分，并创建一个不对用户开放的 `draft` 目标版本承载本地化异步任务。
5. 本地化成功且结构校验通过后，服务端在同一事务内物化并提升目标英文版本及资产草稿，工作进入资产审核页。
6. 用户可修改资产名称、描述、提示词和语音选项。此时只报价，不调用供应商。
7. 用户点击“一键批量生成全部资产”。服务端重新计算总价；价格或模型变化时要求用户重新确认。
8. 确认后服务端先为整批资产建立独立冻结记录，再按受控并发调用真实供应商。
9. 成功资产展示可读取产物并等待人工审核；失败资产显示失败原因和退款状态。
10. 所有必需资产审核通过后，现有审核门禁才允许进入视频生成。

### 3.2 状态语义

产品层状态按以下顺序推进：

`分析中 → 分析待确认 → 英文本地化中 → 资产审核 → 资产批量生成 → 视频生成`

数据库现有 `status/current_step` 继续承担向后兼容的粗粒度状态；分析、本地化和资产批次的精确进度由各自任务记录派生。不得通过覆盖 `redraw_works.task_id` 来切换阶段。

规则如下：

- 源片分析成功后仍保持 `current_step=1`，直到目标版本真实创建。
- 本地化任务运行期间保持 `current_step=1`，页面依据独立任务类型显示“英文本地化中”。
- 只有本地化成功、目标版本和资产草稿在同一事务内写入成功后，才设置 `current_step=2/status=asset_review`。
- 资产部分失败仍停留在 `current_step=2/status=asset_review`。
- 只有所有必需资产生成成功且人工审核通过，现有审核服务才推进到 `current_step=3/status=ready_to_generate`。

## 4. 组件职责

### 4.1 本地化能力解析器

扩展现有 `redrawCapabilityService` 的内部解析能力，为指定 `locale + market + capability` 返回经过验证的供应商、模型和证据快照。转绘完整输出所需能力明确为 `text`、`subtitles`、`character_image`、`clean_plate_image`、`tts` 和 `video`；公开能力目录据此计算阻断项，但仍只返回可展示的能力摘要，不泄露供应商密钥。

文本能力必须同时满足：

- 能力条目标记为 `verified`；
- 证据包含供应商、模型、真实任务 ID 和成功终态；
- 证据产物可读取；
- 能力的语言和市场与目标版本精确匹配。

任何一项不满足时，本地化报价与提交均返回能力阻断，不回退到未经验证的通用文本模型。

`character_image` 的证据必须覆盖角色参考一致性；`clean_plate_image` 的证据必须覆盖无原演员、无蒙版残留的场景空镜或道具净物输出。缺少这两类图像能力时可以完成文本本地化，但资产批量生成保持阻断，完整能力状态不能标记为 `full_output`。

### 4.2 本地化编排服务

新增专用编排服务，职责仅包括：

- 从已确认源版本构造稳定的结构化输入；
- 服务端计算报价并创建积分冻结；
- 创建 `redraw_localization` 异步任务并记录所有权、模型、输入哈希和供应商任务 ID；
- 调用现有文本生成客户端的受控适配层；
- 校验模型返回的结构、镜头映射和台词完整性；
- 在单个数据库事务内物化目标版本、镜头和资产草稿；
- 成功结算或失败退款。

路由不得直接调用供应商，也不得接受客户端生成的台词、人物映射或文化映射。

### 4.3 资产报价与批次编排服务

资产报价服务读取当前目标版本内尚未生成或已失败的资产草稿，按资产类型解析已验证模型并分别报价。报价快照至少包含：

- `version_id`、资产 ID 和资产版本号；
- 资产类型、模型、尺寸或语音参数；
- 提示词或语音输入哈希；
- 单项金额、总金额和报价生成时间；
- 能力证据版本。

批次服务负责幂等创建批次、原子冻结全部单项费用、受控并发派发、聚合进度和失败项重试。具体图片和 TTS 调用继续复用现有生成服务，不在批次服务内复制供应商协议。

### 4.4 前端工作区

- 源片步骤增加“分析结果待确认”和“英文本地化中”视图。
- 第二次确认只提交目标语言、市场、本地化级别、报价哈希和幂等键。
- 资产步骤显示按类型分组的草稿、单价、总价和阻断原因。
- 批量按钮只在所有必需资产均可报价时启用。
- 批次运行时展示总进度以及每项资产的生成、退款和审核状态。
- 页面刷新后完全从工作详情和任务接口恢复，不以内存布尔值决定是否重复提交。

## 5. 本地化数据合同

模型输入以已经持久化的源版本事实为唯一事实源，至少包括：

- 剧情事实和不可改变的因果关系；
- 角色稳定标识、人物关系和源名称；
- 场景、道具和文化元素；
- 镜头 ID、起止时间、时长、说话人和源台词；
- 目标 `locale`、`market` 和 `localization_level=faithful`。

模型输出必须为结构化对象，至少包含：

- 角色名称映射和文化映射；
- 每个镜头对应的英文台词、说话人和语义说明；
- 外国人物、海外场景、道具和英文语音资产草稿；
- 不得改写的事实确认清单。

服务端校验：

1. 每个源镜头恰好存在一个目标镜头，顺序、`start_ms/end_ms/duration_ms` 不变。
2. 每条源台词具有目标映射；新增或删除台词必须被拒绝。
3. 说话人必须引用已知角色稳定标识。
4. 目标台词不能为空，且不得把模型说明文字混入台词。
5. 角色、场景、道具引用必须能解析到同一目标版本。
6. 剧情事实哈希仍绑定源版本；本地化不得覆写源事实。

结构校验失败视为本地化失败，不创建半成品目标版本。

## 6. 数据持久化

### 6.1 目标版本任务字段

在 `redraw_versions` 增加最小必要字段：

- `localization_task_id TEXT`；
- `localization_credit_reservation_id TEXT`；
- `localization_input_hash TEXT`；
- `localization_model_snapshot_json TEXT NOT NULL DEFAULT '{}'`。

第二次确认时先创建 `status=draft` 的隐藏目标版本并写入以上字段；它不更新 `redraw_works.current_version`，也不进入普通版本列表。任务成功后，服务端在同一事务内写入镜头和资产草稿、更新版本状态并切换 `current_version/current_step`。任务失败时保留该草稿行作为审计记录，但后续重试创建新版本号，不复用可能含有旧模型快照的失败草稿。

源片分析继续使用 `redraw_works.task_id/provider_task_id/credit_reservation_id`。目标版本字段只关联本地化，不复用或覆盖分析字段。

### 6.2 资产批次表

新增 `redraw_asset_batches`：

- 所有权：`tenant_id`、`user_id`、`version_id`；
- 任务：`task_id`、`idempotency_key`；
- 快照：`quote_snapshot_json`、`asset_ids_json`；
- 进度：`status`、`total_count`、`success_count`、`failed_count`；
- 审计：`created_at`、`updated_at`、`completed_at`、`error_code`、`error_message`、`deleted_at`。

建立 `(tenant_id, user_id, version_id, idempotency_key)` 唯一索引。每项资产的真实任务和冻结记录继续写入现有 `redraw_assets.generation_task_id/credit_reservation_id`。

批次表不保存供应商密钥，不复制单项资产的完整生成结果。

## 7. 接口合同

### 7.1 本地化报价

`POST /api/redraw/works/:id/localization-quote`

请求只接受：

```json
{
  "locale": "en-US",
  "market": "US",
  "localization_level": "faithful"
}
```

响应包含金额、模型公开标识、输入哈希、报价哈希和阻断原因。未配置价格或没有已验证文本能力时返回 `409`，不得创建任务或冻结积分。

### 7.2 创建目标版本

保留 `POST /api/redraw/works/:id/versions`，但收紧为：

```json
{
  "locale": "en-US",
  "market": "US",
  "localization_level": "faithful",
  "quote_hash": "sha256:server-issued-quote-hash",
  "idempotency_key": "localization-confirm-7f4b2c"
}
```

服务端重新报价并比较哈希。价格或能力快照变化时返回 `409 quote_changed` 和新报价；请求中出现客户端生成的台词、映射、资产、模型或积分金额时返回 `400 REDRAW_LOCALIZATION_CLIENT_CONTROL_FORBIDDEN`。

成功响应返回本地化任务 ID。隐藏的 `draft` 目标版本只在任务成功后才提升为当前版本并对用户可见。相同幂等键返回原任务，不重复冻结或调用供应商。

### 7.3 资产批量报价

`POST /api/redraw/versions/:id/assets/batch-quote`

默认报价全部处于 `draft/failed` 且未生成有效产物的必需资产；可传资产 ID 子集用于重试。服务端忽略任何客户端金额和模型字段。

### 7.4 资产批量生成

`POST /api/redraw/versions/:id/assets/batches`

请求只接受资产 ID、报价哈希和幂等键。服务端重新报价并原子冻结所有单项金额，任一项不可报价或余额不足时整批不派发。

同一批次允许部分成功；重复提交相同幂等键返回现有批次。重试失败项创建新批次，但不得重置已成功资产或再次收取其费用。

### 7.5 工作详情

工作详情增加派生字段：

- `analysis_task`；
- `localization_task`；
- `asset_batch`；
- `workflow_phase`；
- `localization_quote` 或明确的报价阻断信息。

所有查询同时校验租户、用户、工作和版本关系。

## 8. 计费与幂等

### 8.1 本地化

- 第二次确认时由服务端重新报价并冻结积分。
- 供应商成功且结构校验、事务物化均成功后结算。
- 供应商失败、超时、结果不可读或结构校验失败时，全额释放本地化冻结。
- 供应商状态未知时保持冻结并进入 `needs_attention`，在查询到确定终态前不得退款后重提。

### 8.2 资产批次

- 派发前先在一个数据库事务内为每项资产创建独立冻结记录。
- 任一冻结失败时回滚本次新建冻结，且不调用任何供应商。
- 单项产物可读取并写入资产记录后结算该项。
- 单项失败、超时或没有可读取产物时释放该项冻结。
- 部分成功时保留成功资产和扣费；失败项退款并可重试。
- 已经成功且输入哈希未变化的资产不进入后续重试报价。

幂等键只用于同一租户、用户、资源和输入快照。输入变化时必须使用新幂等键；服务端同时使用数据库唯一约束和账本操作键防止双重扣费。

## 9. 失败、恢复与人工处理

- 进程重启前已获得供应商任务 ID 的任务应查询供应商终态后恢复，不能直接重新提交。
- 没有供应商任务 ID 且确定未派发的孤儿任务可标记失败并退款。
- 供应商返回状态未知时标记 `needs_attention`，保留冻结并提示“请勿重新提交”。
- 本地化失败保留源分析结果，用户可在同一页面重试，不重新分析源片。
- 资产部分失败保留所有成功产物，用户可以批量重试失败项或修改某项后单独重生成。
- 人工修改提示词、语音或资产版本后，旧报价立即失效，必须重新报价。
- 任何恢复和重试都必须校验任务、账本和资源的租户所有权。

## 10. 安全与模型开放门禁

- API 禁止接受客户端 `model`、`provider`、`credit_amount`、供应商任务 ID 或生成结果 URL。
- 供应商密钥只从服务端配置读取，不写入任务结果、日志和前端响应。
- 新模型只有使用目标 Key 完成真实生成、成功终态和可读取产物验证后，才能写入可选择能力配置。
- 人物图片至少验证文件可读和角色参考绑定；场景和道具必须验证空镜/净物产物，不得把原演员或蒙版残留作为合格结果；TTS 必须验证音频可读和有效时长。
- 自动验证只决定“产物可进入审核”，不能替代资产人工批准。

## 11. 测试与验收

### 11.1 自动化合同测试

后端必须覆盖：

- 分析成功仍停在第 1 步，未经确认不能创建目标版本；
- 客户端本地化内容、模型和金额注入被拒绝；
- 未验证能力和未配置价格不会冻结或调用供应商；
- 本地化报价变化、余额不足和幂等重放；
- 本地化成功事务物化及所有结构校验失败分支；
- 资产批量报价、原子冻结、部分成功、失败退款和失败项重试；
- 刷新/重启恢复、未知供应商状态和防重复提交；
- 工作、版本、任务、资产和账本的租户隔离；
- 所有必需资产批准前，视频生成门禁持续关闭。

前端必须覆盖：

- 分析结果确认、报价变化和本地化进度恢复；
- 资产总价、阻断原因、批次进度和部分失败展示；
- 重复点击、刷新和返回页面不会重复提交；
- 资产未全部生成并批准时不能进入视频步骤。

### 11.2 真实供应商验收

在获得明确的付费调用授权和目标 Key 后，用同一目标环境完成：

1. 一次真实英文剧本本地化，验证供应商任务、成功终态、结构结果和账本结算。
2. 至少一项真实人物图、场景空镜、道具图和英文语音生成，验证文件可读取、类型特定质量门禁和逐项计费。
3. 一次可控失败或供应商测试失败，验证冻结释放和失败项重试不重复扣费。

模型列表、只读连接测试、模拟供应商或历史成功记录均不能替代上述验收。

### 11.3 浏览器完整链路

使用真实短剧从浏览器完成：

`上传 → 源片分析 → 第二次确认 → 英文本地化 → 资产批量报价与生成 → 资产审核 → 视频生成 → 成片可播放与下载`

验收证据应包含同一运行中的任务 ID、供应商任务 ID、账本记录、可读取资产、最终视频和下载结果。缺失任一环节时只能标记为部分完成或阻塞。

## 12. 完成标准与实施边界

本阶段代码完成标准是：自动化合同全部通过，构建和浏览器非付费流程通过，且没有引入未验证模型或客户端计费控制。

产品“1:1 完全替换链路完成”标准更高：第 11.2 节真实供应商验收和第 11.3 节同次浏览器完整链路都必须通过。没有明确付费调用授权、目标 Key、可读取真实产物或生产发布证据时，不得声称产品已经完成或上线。

本设计获批后，下一步仅编写详细实现计划；实现、真实付费调用和生产发布分别需要遵守各自验证与授权门禁。
