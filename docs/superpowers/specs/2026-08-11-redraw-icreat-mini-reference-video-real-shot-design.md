## 3. 目标与非目标

### 3.1 目标

1. 为 iCreat Mini 增加严格的参考视频请求合同。
2. 使用 A 镜头、固定拉美演员参考图和英文原生音轨完成一次真实候选生成。
3. 证明成品可下载、可读取、媒体参数正确，并保留不含密钥的完整证据。
4. 独立验收人物替换、镜头保持和英文声画效果，不把供应商 `SUCCEEDED` 当成质量通过。
5. 保持一次提交、零自动重试、零备用模型和明确费用上限。
6. 为后续转绘同链接入提供可验证能力证据，但不在本轮开放线上目录或入口。

### 3.2 非目标

- 不验证完整 68.733333 秒短剧已经完成演员替换。
- 不承诺单模型输出达到像素级复刻。
- 不把 4 秒低层适配器真实调用描述成浏览器到供应商的完整转绘 E2E。
- 不创建或更新生产模型配置、生产能力目录或生产计费记录。
- 不自动重试失败、超时或返回不确定状态的供应商任务。
- 不在本轮部署、推送或恢复线上一键转绘入口。

## 4. 输入媒体合同

### 4.1 源视频片段

真实运行前必须再次校验完整源片哈希和媒体参数。只有匹配上述合同的源片才能提取 A 镜头。
本地使用 FFmpeg 生成独立临时片段：

- 时间范围：`0.000–4.000` 秒；
- 视频：H.264/AVC、`720x1280`、30 fps、竖屏；
- 音频：移除；
- 像素格式：`yuv420p`；
- 容器：MP4，启用 fast-start；
- 生成后重新执行 ffprobe、时长和 SHA-256 校验。

移除中文音轨是硬约束，避免参考视频携带的中文声音污染英文原生音轨。临时片段不得加入 Git。

### 4.2 演员参考

现有照片级演员概念图位于：

`frontweb/e2e/fixtures/redraw-latin-american-case/actor-cast-reference.png`

它作为群演和整体选角风格参考。实现阶段从该图单独裁出中央男演员 Mateo 的清晰人像，
作为主要身份参考。裁剪图必须由人工确认仍为真人照片风格、只突出 Mateo，且不会把其他
人物误当成同一身份。完整合照和 Mateo 裁剪图都要记录 SHA-256；裁剪图属于临时测试产物，
不作为已经通过生产角色一致性门禁的身份包。

所有目标学生角色明确为 18 岁或以上。

## 5. iCreat Mini 请求合同

模型固定为 `bytedance/seedance-2-0-mini`。请求体内容顺序固定为：

1. 服务端编译的英文文本提示词；
2. A 镜头 HTTPS 地址，`type=video_url`、`role=reference_video`、
   `need_review=true`；
3. Mateo 裁剪图 HTTPS 地址，`type=image_url`、`role=reference_image`、
   `need_review=true`；
4. 演员合照 HTTPS 地址，`type=image_url`、`role=reference_image`、
   `need_review=true`。

固定参数：

```json
{
  "ratio": "9:16",
  "resolution": "480p",
  "duration": 4,
  "generate_audio": true
}
```

不得同时传 `first_frame` 或 `last_frame`，避免进入首尾帧互斥模式并丢失参考图或参考视频。
参考视频和参考图 URL 必须为 `https://`，拒绝 `file:`、数据 URL、localhost、内网地址、
空值、重复 URL 和超过模型上限的输入。

提示词至少包含以下约束：

- 保留源视频的竖屏构图、镜头运动、人物走位、动作顺序和 4 秒节奏；
- 把所有可见人物重建为写实真人拉美学生；
- Mateo 使用主身份参考，其他人物使用演员合照的选角方向；
- 不保留东亚面孔，不生成动漫、玩偶、畸形肢体或额外人物；
- 场景仍为校园入口；
- Mateo 以困惑、略带质问的自然表演说出 `Dude, who are you?`；
- 台词时间目标为约 `0.7–2.4` 秒，使用自然美式英语。

## 6. 最小代码范围

### 6.1 `backend-node/src/services/videoClient.js`

1. `buildIcreatVideoBody` 接收 `reference_video_urls`。
2. 新增严格的视频内容构造：HTTPS 校验、去重、最多 3 个、
   `role=reference_video`、`need_review=true`。
3. `callIcreatVideoApi` 将已签名/已解析的参考视频传入请求体。
4. 日志只记录模型、参考视频数量、参考图数量和是否生成音频；不得记录完整媒体 URL、
   查询参数、Authorization 或 API Key。
5. 保持现有文生视频、参考图、首帧、首尾帧和参考音频行为不变。

### 6.2 `backend-node/src/services/redrawGenerationService.js`

1. 源视频能力判断增加精确的 `icreat_task + bytedance/seedance-2-0-mini` 支持。
2. 原生音频能力判断增加同一精确模型的 `generate_audio` 支持。
3. 只有已经通过现有 locale/generation evidence 校验的配置才可被选择；不得因为模型名存在
   就绕过能力证据门禁。
4. 4 秒时长仅对精确的 iCreat Mini 原生声画路径开放；其他供应商继续保持现有 5–15 秒
   合同，避免扩大行为变化。
5. 不修改客户端可控字段、资产审核门禁、预留/结算或人工原生音轨审核合同。

### 6.3 本地真实验证运行器

运行器调用现有通用 `callVideoApi`/iCreat 客户端，不复制供应商请求实现。它负责：

- 校验输入媒体并准备 A 镜头和演员参考；
- 建立一次性请求快照和 SHA-256；
- 读取项目中 iCreat 配置到内存，不打印密钥；
- 执行费用和模型权限预检；
- 建立不可复用的一次性提交锁；
- 只提交一次并轮询状态；
- 下载、验证并生成脱敏证据清单。

低层真实调用只证明 iCreat 适配器和该组输入能够工作。若调用成功，可把产物作为后续
隔离数据库中的能力证据候选，但仍不得直接修改共享/生产配置，也不得宣称完整转绘 E2E
已经通过。

## 7. 临时 HTTPS 媒体传输

iCreat 文档要求 `image_url`/`video_url`，未提供可直接使用的文件上传接口。本轮采用用户
已批准的临时本地 HTTPS 传输方案：

1. 在新建私有临时目录中放置 A 镜头、Mateo 裁剪图和演员合照副本。
2. 本地服务只绑定环回地址，不启用目录浏览，只允许三个随机路径的 GET/HEAD。
3. 在外层建立临时 HTTPS 隧道；URL 携带高熵随机路径或查询令牌。
4. 响应设置正确媒体类型、固定长度和禁止缓存头，不暴露本地绝对路径。
5. 服务和隧道最长存活 15 分钟；供应商任务进入终态或发生失败后立即关闭。
6. 关闭后删除临时副本、裁剪图和服务状态文件；保留源片、Git 夹具和脱敏证据。
7. 隧道不可用、无法限制暴露范围或 URL 不能被供应商读取时停止，不切换到生产 MinIO、
   生产服务器或其他未经批准的公共存储。

隧道启动、上传/暴露素材和真实供应商调用都属于执行阶段。生产冲突冻结解除且用户再次
明确授权前，不得执行。

## 8. 费用、幂等与失败状态

公开价格页没有提供本模型的可执行单价，因此提交前必须从 iCreat 控制台或官方只读接口
核实当前单次价格、余额和 Key 分组权限。无法确认预计费用，或预计费用超过
`50 积分 / 0.25 美元`，都必须停止。

运行器对请求快照创建独占的一次性锁。任何一次 POST 尝试后，该锁都标记为已消费；即使
网络中断且没有拿到 task ID，也只能标记 `submission_unknown`，不得再次提交。iCreat 没有
公开的供应商幂等合同，因此不能把本地锁描述成供应商幂等保证。

轮询间隔为 10–15 秒，最长 10 分钟：

- `SUCCEEDED`：获取结果并进入媒体和人工审核；
- `FAILED`/`NOT_FOUND`：记录失败，不重试；
- 超时、状态结构异常或网络不确定：标记 `needs_attention`/`submission_unknown`，不重试；
- 下载失败或产物不可读：保留任务 ID 哈希和失败证据，不重试。

不得自动切换 Fast、Seedance 2.0 完整版、ToAPIs、飞拓或其他模型。

## 9. 验证与证据

### 9.1 合同测试

至少覆盖：

- Mini 模型别名归一化；
- 文本、参考视频、Mateo 图、演员合照的内容顺序和角色；
- 所有人脸/视频参考均带 `need_review=true`；
- HTTPS 校验、去重、数量上限和秘密脱敏；
- 参考视频与 `generate_audio=true` 同时保留；
- 4 秒只对精确 iCreat Mini 路径开放；
- 未验证 capability、错误协议或错误模型继续失败关闭；
- 已有首尾帧、参考图、参考音频和其他供应商测试不回归。

### 9.2 自动媒体验证

真实结果必须满足：

- 可下载的 MP4，保存输出 SHA-256 和字节数；
- 存在可解码视频流和音频流；
- 竖屏、480p 档位、时长约 4 秒，允许不超过 0.25 秒的编码误差；
- 视频和音频时长无明显漂移；
- 音轨不是全静音；
- 输出文件位于本地隔离证据目录，可再次打开。

### 9.3 人工质量审核

以下项目必须逐项记录 `passed/failed/uncertain`：

1. 画面为写实真人，而不是动漫、玩偶、空镜或非人对象；
2. 前景说话者为批准的拉美 Mateo 方向；
3. 背景所有可辨识人物均为拉美演员方向，没有明显东亚面孔残留；
4. 校园入口、竖屏构图、运镜、走位、动作顺序和节奏与源镜头基本保持；
5. 英文内容为 `Dude, who are you?`，语气自然；
6. 英文对白与嘴部动作达到可接受同步；
7. 不存在严重人脸漂移、肢体畸形、多人融合或额外人物。

只有全部关键项通过时，证据清单才能记录
`visual_actor_replacement_verified=true`。任何失败或不确定都保持 `false`，并记录原因。

### 9.4 脱敏证据清单

清单记录：运行 ID、时间、源片/片段/演员参考/输出哈希、模型、脱敏配置 ID、请求快照哈希、
供应商 task ID 的哈希、状态时间线、媒体参数、预计/实际费用和人工审核结果。不得记录 API
Key、Authorization、完整签名 URL、完整 task ID 或本地临时服务令牌。

## 10. 完成条件与后续门禁

本设计的实施完成必须同时满足：

1. 精确范围的合同测试、相关转绘测试、后端全量测试和前端既有转绘回归全部通过；
2. Git 改动只包含批准的适配、测试、运行器、规格和实施计划；
3. 未部署、未修改生产数据、未恢复线上入口；
4. 用户重新授权后的一次真实调用产生可读候选或形成明确、不可重试的失败证据；
5. 最终报告严格区分代码合同、真实供应商结果、人工视觉审核和完整产品 E2E。

即使一次 4 秒候选全部通过，也只代表“iCreat Mini 参考视频 + 拉美演员参考 + 英文原生音轨”
已形成真实模型证据。完整 68.733333 秒短剧、多镜角色一致性、遮挡处理、全片配音、合成、
下载归档和线上发布仍是后续独立阶段。
