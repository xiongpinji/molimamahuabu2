# 平台完整验收与稳定锁定设计

## 状态

- 设计日期：2026-08-21
- 用户确认：按“完整验收后锁定”标准执行
- 基线：`origin/main@eae7c5d3`
- 目标分支：`codex/platform-complete-stability-lock-20260821`
- 本文档只固化验收与锁定标准；不授权生产部署、生产数据修改、启用 `enforce`、自动付费巡检或触碰 AI 音乐。

## 背景与事实基线

本设计承接以下既有规格，不重建第二套稳定性体系：

- `docs/superpowers/specs/2026-08-15-platform-stability-one-pass-lock-design.md`
- `docs/superpowers/specs/2026-08-18-platform-stability-proactive-canary-design.md`
- `docs/verification/platform-stability/platform-feature-inventory.json`
- `docs/verification/platform-stability/feature-lock-manifest.json`

截至本设计基线，机器可读功能清单包含 140 项：124 项为 `unverified`，16 项为 `blocked`。这意味着主动巡检、公开目录门禁和发布保护已经存在，但“图片节点、视频节点、画布模式、短剧工厂、剧本分析全部正常”尚未形成同一轮、逐功能的完整证据，不能直接宣称已经锁定。

## 目标

1. 对公共能力、画布、短剧工厂和剧本分析逐项执行一次“验证—必要修复—复验—锁定”闭环。
2. 图片、视频、文本和音频生成必须同时验证用户入口、后端任务、供应商终态、可读取产物、业务回写和积分账本。
3. 外部线路故障时，只在安全条件下切换到已验证的同逻辑模型线路；提交或结果未知时立即停止，不自动重试。
4. 没有缺陷的功能不修改业务代码，直接登记证据并锁定；存在缺陷的功能只做精准修复。
5. 后续修改触碰已锁功能时，必须显式解锁、运行该功能的固定回归集合并重新登记证据。
6. 每个阶段使用独立 PR 和受保护增量发布，不覆盖其他会话，不触碰 `/opt/moli-mama` AI 音乐。

## 非目标与真实性边界

- 不承诺外部供应商永不宕机、永不限流或永不改变协议。
- 不把单元测试、Mock、构建成功、模型列表或只读连接探测当作真实生成成功。
- 不把历史成功记录当作当前线路可用证据。
- 不为通过验收而扩大模型能力、降低安全规则、改写用户提示词或静默降级清晰度、时长、参考素材数量。
- 不在本设计中启用 `enforce`。只有公开线路和业务功能达到书面 readiness，且用户另行授权后，才能提出启用方案。
- 不执行未获单次预算授权的真实生成；任何结果未知均停止且不重试。
- 不把本轮范围扩展到 AI 音乐项目。

## 采用方案

采用“完整验收后锁定”，不采用以下两种替代方案：

1. **仅增加回归测试**：成本较低，但不能证明生产、供应商、产物和计费闭环正常。
2. **绝对冻结后台配置**：能减少误操作，但供应商故障时管理员无法换线，会降低可运营性。

本方案允许管理员受审计地暂停、换线和更新价格；任何配置、成本、能力或运行依赖变化都会使旧证据失效，线路必须重新验证后才能恢复为可信状态。

## 验收对象与阶段边界

### 阶段 0：清单与证据框架

- 从前端路由、可见控件、后端接口和生产入口重新生成清单，不依赖历史文档猜测。
- 为 140 项现有条目核对入口、角色、是否写状态、是否可能扣费、适用证据链和固定测试集合。
- 已从产品移除的入口必须有删除依据；不能用“找不到入口”把功能标记为通过。
- 16 项现有 `blocked` 条目必须保持阻断，直到缺少的能力或验收覆盖真实补齐。

### 阶段 1：公共运行底座

- 登录、权限、管理员 RBAC、租户隔离。
- 模型目录、逻辑模型映射、配置启停、能力、用户价格与管理员成本。
- 数据库、队列、静态素材、对象存储、下载、签名访问。
- 任务幂等、积分预占、结算、退款、未知冻结与管理员对账。
- 服务器重启、页面刷新、并发请求和重复回调恢复。
- 管理员可见线路身份和安全日志；普通用户接口递归移除中转站、配置、成本、证据和凭据字段。

### 阶段 2：图片节点

- 模型目录、模型能力标签、分辨率、比例、数量、风格和排除词。
- 文生图、参考图、上传、连线自动采用、顺序、编号提及、预览、删除和刷新恢复。
- 每个公开图片逻辑模型至少完成一次当前 Key 的真实生成，达到明确成功终态，产物可解码并可从业务记录重新打开。
- 公开声明的参考图上限、分辨率和比例由合同测试覆盖；高成本边界能力只在单独预算授权后做真实抽样。
- 任务、产物、素材库、画布回写和积分账本一致；失败退款与未知冻结符合状态机。

### 阶段 3：视频、文本和音频节点

- 视频首尾帧、多图、多视频、多音频、时长、分辨率、比例、数量、同步音频和特效能力。
- 文本编辑、模型选择、生成、刷新恢复和下游运行。
- 音频上传、参考、TTS/音频生成、预览、下载和下游引用。
- 每个公开逻辑模型的主线路和拟公开备用线路必须分别具备当前真实成功证据；产物需通过对应媒体解析。
- 同模型切换不得跨能力、跨价格或跨输出语义；已受理、提交未知、结果未知和产物未知禁止自动重提。

### 阶段 4：画布模式

- 项目中心、新建、打开、保存、自动保存、刷新恢复和并发写入保护。
- 撤销、重做、缩放、平移、节点定位、拖动、缩放、复制、删除、连线和断线。
- 所有节点编辑框随视口响应，不越出可用画布；内容完整展示，节点移动或缩放不造成编辑内容丢失。
- 图片、视频、文本、音频及现有业务节点的全部可见按钮和参数。
- 素材上传、素材库、生成历史、参考素材编号、右键引用、预览、下载和结果回写。
- 导演台的人物移动、旋转、缩放、姿态、摄影机、焦距、灯光、时间线、保存、恢复和导出。
- 每个生成入口保留 `canvas-credit-callout-v1`：已定价时醒目显示“本次预计扣除 X 积分”，未定价时显示“积分待管理员配置”。

### 阶段 5：短剧工厂

- 项目、剧集、剧本页签、角色、场景、道具、分镜和素材资产。
- 参考图上传与主图绑定，单个和批量生成，重新生成、版本替换、任务恢复。
- 图片、视频、文本和音频任务的进度、失败、结果预览、下载、导出和积分闭环。
- 项目 ZIP、分镜表、SRT 和归档导出必须验证文件可打开且内容属于当前租户和项目。
- 归档、小说、示例导入必须验证结果身份、顺序和资源归属。
- 剧本分析导入与画布投影后，角色、场景、道具、分镜、素材、引用和参数能够完整回读。

### 阶段 6：剧本分析

- 文本输入、TXT/Markdown 导入、项目保存、模型选择、预计积分、提交、进度与错误。
- 页面刷新和服务器重启后恢复原任务，不创建重复分析。
- 分析结果、人物、场景、道具、导演故事板、修订、审核和版本历史。
- V1/V2 数据兼容，资产 ID 和版本 ID 稳定。
- 下载结果必须提供真实入口和可打开文件；若产品决定不提供，必须从功能清单中以获批产品变更移除，不能记为通过。
- 导入短剧工厂和投影画布后执行完整数据回读。

### 阶段 7：锁定、合入与生产回读

- 每个阶段独立 PR、Hosted CI、增量 allowlist 和功能锁审计。
- 从实时 `/opt/moli-drama/current` 克隆候选，只覆盖该阶段获批文件。
- 执行数据库备份与完整性检查、活动任务检查、部署锁、CAS、健康、日志和回滚目标检查。
- 仅使用共享 `activate-protected-release.sh CANDIDATE EXPECTED_CURRENT` 激活。
- 发布前后核对 AI 音乐 PID、端口和文件树未变化。
- 生产回读失败立即使用受保护回滚流程，不继续叠加修复。

## 证据模型

每项功能保存一个不可变的验收记录，至少包含：

- `feature_id`、模块、入口、角色和验收动作。
- 基线提交、候选提交、生产 release 和验证时间。
- 适用的合同测试、后端集成、真实浏览器、供应商、产物、下载、计费和生产回读证据。
- 缺陷编号、修复提交；无缺陷时记录“未修改业务代码”。
- 敏感信息扫描结果和证据文件路径。
- `locked_pass`、`locked_fixed`、`blocked` 或 `not_applicable`。

证据状态规则：

- `locked_pass`：全部适用证据通过，且没有业务代码修复。
- `locked_fixed`：缺陷已稳定复现、精准修复，全部适用证据重新通过。
- `blocked`：能力缺失、环境缺失、真实结果未知、预算未授权或证据链不完整。
- `not_applicable`：有明确产品或协议依据证明该证据不适用；不能用于隐藏缺陷。

任何适用证据为 `blocked` 或 `fail` 时，功能不得写入锁定通过状态。证据必须来自同一候选；历史证据只能作为背景，不能替代当前验收。

## 真实生成与付费控制

1. 先完成本地合同、集成、浏览器和零成本生产准备。
2. 每批付费前只读确认模型、线路、参数、次数、用户积分、供应商成本、余额和既有未知任务。
3. 用户明确批准该批次数和硬上限后才提交。
4. 每次提交只执行一次；超出预算、存在未决同类任务或返回未知状态时立即停止。
5. 成功必须包含明确供应商终态、可读取产物、业务回写和账本结算。
6. 提交未知、结果未知或产物不可读取保持冻结并进入管理员核查，不退款、不切线、不重试。

当前已核对的三款公开图片模型基础测试预算为 3 次、用户积分上限 160、供应商成本建议上限 ¥0.40；该预算仍需在真实提交前获得用户对硬上限的明确确认，不能由本规格自动授权。

## 线路容灾与用户可用性

- 用户只选择逻辑模型，不看到供应商、域名、配置 ID、密钥或内部成本。
- 候选线路必须启用、未暂停、健康、未熔断、能力覆盖、用户价格有效、内部成本有效，并具有与当前配置/成本/运行指纹一致的新鲜成功证据。
- 明确未受理、可靠幂等或请求发送前失败时，才允许切换到下一条已验证同模型线路。
- 有任务号、请求可能已发送、2xx 无产物、轮询超时或状态不可判定时，不允许自动切换。
- 所有可信线路不可用时，在 `enforce` 模式隐藏逻辑模型；当前仍保持 `shadow`，只记录将被隐藏的候选和管理员告警。
- 管理员修改配置、Key、模型、能力、价格、成本或运行适配器后，旧证据立即失效。

## 锁定与受控解锁

锁定实现复用现有 `docs/verification/platform-stability/feature-lock-manifest.json`：

- 按公共底座、图片节点、视频/文本/音频节点、画布、短剧工厂和剧本分析建立独立锁。
- 每个锁固定 `protectedPaths`、`requiredTests`、完整证据历史和最近一次获批解锁理由。
- 触碰保护路径时，CI 与发布门禁必须验证本轮有新的获批解锁记录和对应测试。
- 新证据只能追加，不能删除或重写历史记录。
- 生产配置变化通过证据失效机制处理，不能靠修改 manifest 伪造可用。

允许解锁的原因只有：可复现生产缺陷、用户批准的需求变化、供应商协议变化、浏览器或必要依赖变化。解锁后必须重新完成受影响功能的全部适用证据。

## 测试与发布门禁

每个阶段必须在同一候选上完成：

- 新增或修复行为的 TDD 红灯与绿灯。
- 后端全量测试和前端全量 Node 测试。
- 前端生产构建。
- 对应模块 Playwright 浏览器测试。
- 后端真实接口、SQLite、任务、素材、下载和积分集成测试。
- 公开 DTO 敏感字段扫描、租户隔离和 RBAC 回归。
- 模型目录、能力、用户价格、线路成本和证据一致性审计。
- 功能锁、增量范围、受保护合同和 secret 扫描。
- 获批的真实供应商测试与生产回读；未授权项保持 `blocked`。

存在以下任一情况时禁止合入或部署：

- 未解决 P0/P1。
- 任务或积分状态未知且没有管理员核查记录。
- 真实产物不可读取。
- 功能锁、增量范围或 `canvas-credit-callout-v1` 失败。
- 候选不是从实时 `current` 构建。
- 与其他会话发生文件或部署锁冲突。
- AI 音乐隔离检查失败。

## 完成定义

只有同时满足以下条件，才能向用户报告“本轮完整验收与锁定完成”：

1. 机器可读清单中每项均为 `locked_pass`、`locked_fixed` 或有用户认可原因的 `not_applicable`；不存在未解释的 `unverified` 或 `blocked`。
2. 所有公开生成模型具有当前线路的新鲜真实成功证据，或已从公共目录隐藏。
3. 所有真实成功记录的产物可读取，任务、业务回写和积分账本一致。
4. 后端全量、前端全量、构建、浏览器、Hosted CI、功能锁和发布门禁全部通过。
5. 每个阶段已合入 `main`，生产使用从实时 `current` 构建的受保护增量 release。
6. 生产健康、日志、活动任务、冻结积分和公开入口完成回读，AI 音乐未受影响。
7. `enforce` 是否启用仍作为独立运营决定；未获授权时保持 `shadow` 不影响本轮代码和功能锁完成度。

## 交付顺序

严格按阶段 0 至阶段 7 顺序推进。每个阶段独立完成“规格对应清单—红灯—最小修复—完整验证—锁定—PR—受保护发布—生产回读”，下一阶段不得顺带重构上一阶段已经锁定的实现。
