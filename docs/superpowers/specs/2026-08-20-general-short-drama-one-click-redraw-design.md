# 通用短剧一键转绘产品设计

日期：2026-08-20

状态：流程设计已确认，等待书面规格确认

适用范围：本地开发与验证，不包含部署、推送或未单独授权的付费调用

## 1. 背景

本项目的目标不是手工模仿某一条视频，而是建设一个可复用的短剧一键转绘产品。

用户上传任意短剧或短视频后，系统应自动完成分镜、剧情和人物分析，并生成面向目标国家和目标语言的新版本。新版本使用虚构成年演员、目标国家姓名和新的目标语声音，同时保留原剧情、人物关系、镜头顺序、镜头时长、构图、动作和镜头运动。

现有样片 `ac087bcd4cf5f856f85182834794853a.mp4` 只用于验证通用产品链路。实现不得针对该样片写死镜头数量、角色、台词、时长或供应商请求。

## 2. 设计目标

首版必须满足以下目标：

1. 支持上传任意短剧或短视频，建立不可变源版本。
2. 每个项目选择一个目标国家和一种目标语言。
3. 支持 A 安全审核模式和 B 自动模式，并复用同一套业务状态与证据链。
4. 自动识别剧情、分镜、人物、说话人、对白、动作、镜头运动和画面文字。
5. 自动生成目标国家化的角色姓名、目标语对白和文化适配结果。
6. 为每个可识别角色创建虚构成年演员身份包，并锁定整集形象、服装和声音。
7. 逐镜去除原人物、原文字和原对白，同时保留场景、构图、动作和镜头运动。
8. 逐镜生成新演员视频，并完成目标语声音、字幕和口型处理。
9. 每个镜头可以独立审核、失败、返工和恢复，不因单镜失败重跑整集。
10. 所有镜头通过后，生成可播放整集、字幕和审计报告。
11. 对预算、付费请求、供应商异常和结果不明状态执行 fail-closed 门禁。
12. 核心业务不绑定单一供应商。首个计划接入的真实适配器为 Fumin Seedance 2.0 Mini 480p，但是否开放必须以当前有效的真实生成证据为准。

## 3. 非目标

首版不包含以下内容：

- 不追求像素级复制，也不保证生成画面与原片逐像素一致。
- 不在一个项目内同时批量生成多个目标国家或多种语言。
- 不克隆原演员声纹，不保留原演员身份。
- 不把样片的 9 镜、角色或英文台词写成产品固定规则。
- 不把供应商返回 `completed` 直接视为镜头通过。
- 不把单元测试、Mock、前端页面或历史候选当作完整端到端交付证据。
- 本规格不授权部署、生产数据库写入、推送、供应商付费调用或真实上传。

## 4. “1:1 复刻”合同

“1:1”定义为剧情、人物关系、分镜和时间轴级复刻，不是像素级复制。

必须保留：

- 原剧情事件及其因果关系；
- 原人物关系和每镜出场关系；
- 镜头数量、顺序和起止时间；
- 景别、构图、机位、镜头运动和主要动作；
- 静默镜头、对白镜头和环境声的时间结构。

必须替换：

- 原演员的脸、头发、身体和服装；
- 原角色姓名及目标市场不适配的文化信息；
- 原语言对白、字幕和画面文字；
- 原演员声纹。

环境声可以保留或重建，但必须证明不含原对白和可识别的原演员声纹。静默镜头的合同是“无对白”，不是“必须无音轨”。

译文超过原镜时长时，系统必须优先压缩和改写台词，使其适配原时间窗。系统不得为容纳译文而静默改变镜头顺序或整集时间轴。

## 5. 运行模式

### 5.1 A 安全审核模式

A 模式自动执行分析和准备工作，但在关键门禁等待人工确认：

1. 角色姓名、演员身份、声音和服装确认；
2. 逐镜净景、文字区域和参考包确认；
3. 生成候选、对白、口型和整集质量确认。

未经确认，系统不得继续到会产生付费调用或正式交付的状态。

### 5.2 B 自动模式

B 模式仅在确定性合同和版本化置信度策略全部通过时自动推进。

以下任一情况出现时，B 模式必须自动降级为 A：

- 人物或说话人映射不确定；
- 角色身份、年龄、服装或声音合同不完整；
- 原人物或原文字去除不确定；
- 目标语台词、字幕或文化适配不确定；
- 生成候选的身份、动作、声音、口型或时长处于边界结果；
- 预算、供应商能力或费用状态不明确。

降级只暂停受影响镜头或阶段。其他镜头可以继续执行不产生风险的本地准备工作。

### 5.3 预算与自动重试

B 模式启动前必须由用户一次性确认项目预算上限和自动尝试上限。未配置上限时，B 模式不得发起付费生成。

只有在供应商明确返回未受理或明确终态失败，并且费用状态可证明安全时，系统才可以在既定上限内创建下一次尝试。

供应商响应未知、请求超时后受理状态未知或结算状态未知时，系统必须进入 `needs_attention`，禁止自动重提。

## 6. 总体架构

采用“分层流水线 + 双策略编排 + 供应商适配器”架构。

### 6.1 共享流水线

两个运行模式共享以下 8 个阶段：

1. 项目输入；
2. 剧情与分镜分析；
3. 目标市场本地化；
4. 角色资产锁定；
5. 净景与参考包；
6. 逐镜供应商生成；
7. 声音、口型与逐镜 QA；
8. 整集合并与导出。

A、B 模式只改变门禁的决策策略，不建立两套业务代码、两套状态或两套数据。

### 6.2 编排边界

编排器负责：

- 读取当前项目、角色和镜头版本；
- 判断当前阶段是否具备完整输入；
- 执行确定性门禁和版本化置信度策略；
- 按 A、B 模式决定自动推进、等待审核或停止；
- 只调度受影响镜头；
- 记录状态变化、费用和证据；
- 保证同一规范请求不会重复提交。

编排器不得：

- 根据供应商自由文本猜测成功；
- 跳过角色、净景、参考包或审核门禁；
- 在 `needs_attention` 状态自动重试；
- 用新结果覆盖旧尝试的证据。

### 6.3 供应商适配器

核心系统只向适配器发送规范请求。供应商专有字段只能存在于适配器边界内。

规范请求至少包含：

- 项目、镜头、角色和参考包版本；
- 请求幂等键和规范请求哈希；
- 目标时长、尺寸、语言和声音合同；
- 角色身份、净景、动作和构图参考；
- 预算预留标识；
- 不含本地绝对路径和密钥的审计字段。

适配器必须返回规范状态：

- `accepted`：供应商已明确受理；
- `running`：任务仍在处理；
- `completed_candidate`：候选可下载，但尚未通过产品 QA；
- `failed_terminal`：供应商明确失败；
- `submission_unknown`：是否受理未知；
- `result_unavailable`：任务终态存在，但产物不可读取或不可验证。

## 7. 产品工作台

工作台使用阶段导航，而不是要求用户在画布中手工拼接完整流程。

### 7.1 六个工作区

1. **项目设置：** 上传、目标市场、运行模式、预算和自动尝试上限。
2. **分析与本地化：** 剧情、分镜、人物、说话人、目标姓名、译文和文字替换。
3. **角色资产库：** 虚构成年演员身份包、声音、服装和版本审核。
4. **逐镜工作台：** 净景、遮罩、动作、构图、参考包、提示词和返工。
5. **生成与 QA：** 供应商队列、费用状态、候选、自动指标和人工接管。
6. **合并与导出：** 整集、字幕、封面、逐镜清单和审计报告。

### 7.2 全局可见信息

工作台顶部必须始终显示：

- 当前项目和目标市场；
- A、B 运行模式及是否发生自动降级；
- 已使用预算、已预留预算和剩余预算；
- 当前项目版本；
- 待审核、`needs_attention` 和失败镜头数量；
- 下一步动作是否会产生付费调用。

### 7.3 逐镜可见信息

每个镜头必须显示：

- 源时间段、代表帧和镜头版本；
- 出场角色、说话人、目标语台词和静默合同；
- 原人物、原文字和遮挡风险；
- 角色身份包、净景和参考包状态；
- 生成尝试、供应商状态、费用和候选；
- 自动 QA、人工审核和失效原因；
- 返工入口及其影响范围。

## 8. 核心数据对象

### 8.1 Project

记录源版本、目标国家、目标语言、运行模式、预算、自动尝试上限、当前阶段和当前项目版本。

### 8.2 Analysis Version

记录剧情、连续分镜时间轴、人物、说话人、原对白、动作、镜头运动和画面文字。分析版本不可原地覆盖。

### 8.3 Character Pack

每个源人物键对应一个目标角色身份包，至少包含：

- 目标国家化姓名；
- 成年状态；
- 正面、侧面和全身身份参考；
- 身份一致性确认；
- 目标语声音；
- 服装版本；
- 文件哈希、审核人、审核状态和版本。

一张多人合照不能代替单角色生产身份包。

### 8.4 Shot

记录源起止时间、构图、机位、动作、镜头运动、角色、说话人、对白、文字区域、风险和当前版本。

### 8.5 Reference Bundle

逐镜参考包绑定：

- 源镜头和代表帧；
- 去人净景、人物遮罩和文字净化证据；
- 动作、构图和镜头运动参考；
- 该镜涉及的角色身份包版本；
- 文件哈希、审核状态和更新时间。

### 8.6 Generation Attempt

每次尝试记录规范请求哈希、幂等键、供应商、任务标识、费用预留、状态、候选产物、失败阶段和审计时间。

尝试记录只追加，不覆盖旧记录。

### 8.7 Candidate Review

候选审核记录至少包含：

- 文件可读性、时长、尺寸和哈希；
- 角色身份、服装和出场关系；
- 原人物与原文字残留；
- 对白内容、说话人声音和静默合同；
- 字幕、口型、动作、构图和镜头运动；
- 自动指标、人工结论、审核人和版本。

### 8.8 Episode Release

整集交付版本按镜头顺序锁定已通过候选的文件哈希，并记录字幕、音轨、封面、成片和审计报告。

## 9. 镜头状态机

每个镜头独立推进：

`parsed` → `localized` → `identity_bound` → `clean_ready` → `reference_ready` → `submitted` → `candidate_ready` → `approved` → `included`

辅助状态：

- `needs_review`：等待 A 模式人工确认；
- `needs_attention`：供应商受理、结算或产物状态未知；
- `failed`：明确失败，可以在预算和尝试上限内创建新尝试；
- `stale`：上游版本变化，现有下游证据不再有效；
- `canceled`：用户主动取消，保留已有审计记录。

状态推进必须携带期望版本，通过比较并交换（Compare-and-Swap，CAS）防止旧页面覆盖新状态。

## 10. 版本失效传播

只失效受影响数据：

- 修改角色身份包：失效引用该角色的参考包、候选审核和整集合并版本；
- 修改目标语台词或声音：失效对应对白镜头的音频、口型、候选审核和整集合并版本；
- 修改文字区域：失效对应镜头的文字净化、参考包、候选审核和整集合并版本；
- 修改镜头时间：失效对应镜头的参考包、候选和整集合并版本；
- 修改项目目标市场：创建新的本地化版本，不覆盖原目标市场版本。

未受影响且已通过的镜头继续有效。

## 11. 八阶段合同

### 11.1 项目输入

- 输入：原短剧、目标国家、目标语言、运行模式、预算和自动尝试上限。
- 输出：源文件哈希、音视频探针、项目版本和输入合同。
- 门禁：文件可读、包含视频轨、媒体参数可探测、哈希与版本绑定。
- 失败：损坏、路径逃逸、哈希漂移或版本冲突时停止，不创建下游状态。

### 11.2 剧情与分镜分析

- 输入：源版本、视频帧和原音轨。
- 输出：连续分镜、剧情、人物、说话人、原对白、动作、镜头运动和文字区域。
- 门禁：镜头连续覆盖整集且不重叠；对白绑定说话人和时间；可见人物与文字有证据帧。
- 降级：人物、说话人或文字区域不确定时转 A。

### 11.3 目标市场本地化

- 输入：人物关系、原对白、文字区域和目标市场。
- 输出：目标姓名、目标语台词、字幕、屏幕文字和文化替换说明。
- 门禁：姓名一对一；译文适配原时长；不得残留源语言台词和原姓名。
- 降级：语义、文化或台词长度处于边界时转 A。

### 11.4 角色资产锁定

- 输入：源人物键、目标姓名、年龄、关系和服装需求。
- 输出：虚构成年演员身份包、目标语声音和服装版本。
- 门禁：所有可识别人脸有唯一映射；文件可读且哈希绑定；整集只引用锁定版本。
- 降级：相似角色、年龄、身份一致性或声音不确定时转 A。

### 11.5 净景与参考包

- 输入：镜头帧、人物和文字区域、角色包、动作及镜头运动。
- 输出：去人净景、文字净化、遮罩、动作参考、构图参考和逐镜参考包。
- 门禁：原人物和原文字不可识别；非遮罩区域保持场景一致；参考包绑定正确版本。
- 降级：遮挡、残留、画面破坏或映射不确定时转 A。

### 11.6 逐镜供应商生成

- 输入：已通过参考包、角色版本、镜头时长、规范请求和预算预留。
- 输出：唯一尝试、供应商任务、费用状态、下载候选和文件证据。
- 门禁：请求幂等、预算充足、供应商能力匹配、候选可下载和解码。
- 停止：受理或结算未知时进入 `needs_attention`，禁止自动重提。

### 11.7 声音、口型与逐镜 QA

- 输入：视频候选、目标语台词、角色声音、静默合同和字幕。
- 输出：有声镜头、字幕时间轴、口型结果、自动指标和人工审核记录。
- 门禁：对白逐句匹配；声音属于正确角色；静默镜头无对白但允许合规环境声；身份、服装、文字、动作、口型和时长通过。
- 降级：任何边界结果转 A。

### 11.8 整集合并与导出

- 输入：按顺序锁定的已通过候选哈希、字幕和整集元数据。
- 输出：可播放整集、字幕、封面、逐镜清单、费用报告和质量审计报告。
- 门禁：所有镜头属于当前版本且已通过；时间轴连续；音画可读；总时长正确；全片媒体探针通过。
- 失败：任一镜头缺失、失效或不可读时，禁止生成正式交付版本。

## 12. 费用与结算

付费生成遵循以下顺序：

1. 校验项目预算、镜头版本、参考包和供应商能力；
2. 按规范请求哈希创建唯一费用预留；
3. 发起一次供应商提交；
4. 等待明确终态并下载候选；
5. 验证候选可读性、媒体参数和文件哈希；
6. 明确成功后结算；
7. 明确失败且供应商未扣费时释放预留；
8. 受理、结果或结算未知时保持 `held`，进入 `needs_attention`。

新幂等键不得绕过旧 `needs_attention` 尝试。人工接管必须先解决旧费用状态。

## 13. 安全与隐私

- 所有项目、角色、镜头、资产、审核和费用记录必须按租户与所有者隔离。
- 原片、角色参考和候选不得通过可猜测的公共路径暴露。
- 本地文件必须使用受控相对路径、真实路径校验和哈希验证，拒绝绝对路径、`..` 和符号链接逃逸。
- 响应、日志和审计报告不得包含密钥、Authorization、供应商敏感响应或本地绝对路径。
- 供应商 Key 只能从受控配置读取，不写入项目数据、提示词、证据或提交记录。
- 真实上传和付费调用必须有当次明确授权；“继续”不视为授权。
- 生产部署必须单独执行生产冲突协调和受保护发布流程。

## 14. 错误处理

错误必须同时具有稳定错误码和安全阶段，不返回原始异常路径或供应商敏感正文。

错误按处理方式分为：

1. **输入错误：** 用户修正后重新进入当前阶段；
2. **审核阻断：** 转 A，等待人工确认；
3. **明确失败：** 保留旧尝试，在预算和上限允许时创建新尝试；
4. **结果不明：** 进入 `needs_attention`，禁止自动重试；
5. **版本冲突：** 返回当前版本，要求客户端刷新后重新决策；
6. **证据漂移：** 标记 `stale`，只重建受影响链路。

任何失败都不得写入“已通过”状态，也不得删除旧候选和旧审核证据。

## 15. 验证策略

### 15.1 合同测试

验证字段白名单、租户隔离、版本约束、CAS、状态机、幂等、费用和错误码。

### 15.2 本地媒体测试

使用真实 FFmpeg、ffprobe 和文件哈希验证分镜、音轨、字幕、代表帧、候选和整集合并。

### 15.3 浏览器工作台测试

验证项目创建、A/B 模式、自动降级、预算显示、逐镜状态、人工接管、返工和下载。

### 15.4 样片整集验收

当前 68.7 秒样片作为首个整集验收夹具，但必须通过公开产品入口上传，不得调用样片专用脚本或写死数据。

同一次验收必须贯通：

`上传 → 分析 → 本地化 → 角色包 → 净景/参考包 → 真实生成 → 声音/口型 → QA → 合并 → 下载`

### 15.5 真实供应商验收

先完成单镜真实生成，确认目标模型、参考输入、声音和下载合同可用，再按单独授权扩大到整集。

真实验收必须记录不含密钥的请求模型、任务标识、终态、费用状态、文件哈希、媒体探针和审核结果。

## 16. 首版完成定义

只有同时满足以下条件，才能宣称首版完整交付：

- 任意合法短剧可以从产品入口创建项目；
- A、B 模式使用同一流水线，B 能在不确定时正确降级 A；
- 一个目标市场可以完成角色、台词、文字和声音本地化；
- 每个镜头具有可追溯的身份、净景、参考包、生成和审核版本；
- 真实供应商候选经过下载、媒体、身份、对白、口型和残留检查；
- 单镜失败可以恢复，不重复提交未知任务，不重跑已通过镜头；
- 所有镜头通过后可以生成并下载可播放整集、字幕和审计报告；
- 当前样片通过同一通用链路完成整集验收；
- 没有使用 Mock、静态 UI 或历史候选代替真实同次端到端证据；
- 未部署部分、跳过门禁和供应商能力边界均被明确记录。

## 17. 已确认决策

- 采用分层流水线和供应商中立适配器，不采用单体一次性任务或首版全微服务化。
- 同时提供 A 安全审核模式和 B 自动模式。
- B 模式低置信度自动降级 A。
- 一个项目只选择一个目标国家和一种目标语言。
- 角色使用虚构成年演员，姓名、形象、服装和声音整集锁定。
- 不克隆原声纹；有对白镜头生成目标语声音并做口型，静默镜头保持无对白。
- “1:1”保留剧情、分镜、时间轴、构图、动作和镜头运动。
- 译文必须适配原镜时长，不以延长镜头解决翻译超时。
- B 模式使用项目预算上限；超预算、结果不明或额外付费时转 A。
- 当前样片只作为产品验收夹具，不作为产品范围。

## 18. 后续流程

本书面规格经用户确认后，再编写独立实施计划。实施计划必须先盘点当前主线可复用模块与真实缺口，再按可验证的纵向切片安排任务，不得恢复到与主任务无关的模型缓存或单视频手工制作主线。
