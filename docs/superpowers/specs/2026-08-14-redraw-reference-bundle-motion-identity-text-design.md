# 转绘全员换人与文字净化参考包设计

## 背景与失败证据

现有 5 秒真实样片已证明 Seedance 2.0 Mini 480p 能生成可播放且带英文音轨的视频，但没有完成目标视觉转绘：原片中的东亚人脸和中文场景文字仍然可辨认。只把原视频作为视频参考并在提示词中要求“外国人、英文对白、去中文”，不足以约束角色身份和逐帧文字净化。

本设计将供应商调用前置为一份服务端生成、可审计、可失效的“转绘参考包”。供应商只能收到已净化的运动参考视频、已批准的虚构美国成年角色身份图和已批准的英文对白，不能收到带原人物、中文字或原音的原视频。

## 本阶段边界

本阶段只做本地实现、fixture、自动化测试和脱敏报告：

- 不读取供应商 Key；
- 不调用 Fumin、ToAPIs 或其他付费供应商；
- 不上传用户源片；
- 不访问 `/opt/moli-drama`，不部署、不 activate、不写生产数据库；
- 不恢复线上一键转绘入口；
- 不把本地参考包通过宣称为供应商换人成功、整集完成或生产验收通过。

当前最新转绘分支先实现供应商无关的参考包。Fumin 接入在后续独立工作树中进行，只移植经过审计的 Fumin 客户端文件，不用旧分支整体覆盖当前身份包和文字净景实现。下一次真实付费提交仍需单独授权。

## 目标与非目标

### 目标

1. 对输入片段中的每一张可辨认人脸建立完整覆盖清单，并绑定到已批准的虚构美国成年角色身份包。
2. 从原片派生一份无原人脸、无中文字、无原音的运动参考视频，保留镜头、动作、构图和时间线。
3. 将人脸覆盖、文字覆盖、英文对白、角色英文名和运动参考的指纹固化为 `redraw-reference-bundle-v1`。
4. 只允许服务端从当前资产和审核状态组装供应商请求；客户端只能提交业务对象 ID，不能自报路径、URL、哈希或审核结论。
5. 任一证据缺失、过期或超过参考图上限时，在数据库写入、积分冻结和供应商调用之前失败。

### 非目标

- 不在本阶段实现 Fumin 请求发送、轮询、计费或结果下载。
- 不在本阶段实现整集分镜调度或自动拆镜，只输出明确的超限错误和拆镜要求。
- 不用提示词代替人脸、文字、音轨和资产哈希门禁。
- 不以 AI 生成的写实人物图片冒充真实自然人的身份；目标角色必须标记为虚构、AI 生成、已确认成年。
- 不允许生成结果自动成为已验收成片；供应商结果仍需人物、文字、对白、音轨和可播放性复核。

## 方案选择

采用“原片隔离 + 净化运动参考 + 角色身份图”的方案：

1. 原片只进入本地分析和净化流程。
2. 本地流程输出无音轨的净化运动参考视频，并生成覆盖证据。
3. 已批准的 `target-actor-identity-v1` 身份包提供角色外观；每个业务角色只能绑定一个当前身份包版本。
4. 已批准的 `text_clean_plate` 资产提供字幕和场景文字清除证据。
5. 后端把上述证据组装成规范化参考包，再投影成供应商无关的生成请求。

不继续采用“原视频 + 更强提示词”，因为失败样片已经证明模型会优先保留原人物和原中文字。不采用直接丢弃运动视频只做图生视频，因为会失去 1:1 镜头、动作和节奏依据。

## 原片隔离与净化流水线

```text
原片片段
  ├─ 人脸轨迹清单 ──> 角色身份包绑定
  ├─ 文字时间区域 ──> text-clean 证据绑定
  ├─ 对白时间轴 ────> en-US 对白与美国化角色名
  └─ 本地净化 ──────> 无原脸、无中文字、无原音的运动参考视频
                              │
                              v
                    redraw-reference-bundle-v1
                              │
                              v
                  后续供应商请求白名单投影
```

原片 URL、原始人脸帧、带中文字的场景图片和原音轨不得进入供应商请求。净化视频必须保留片段起止时间、帧率、画幅、镜头切点、人物动作和摄影机运动；人脸与文字区域只保留脱敏后的轨迹和覆盖哈希。

## 参考包合同

服务端按稳定排序生成如下快照：

```json
{
  "schema_version": "redraw-reference-bundle-v1",
  "source": {
    "asset_id": 1001,
    "sha256": "64位小写hex",
    "clip_start_ms": 0,
    "clip_end_ms": 5000
  },
  "motion_reference": {
    "asset_id": 2001,
    "sha256": "64位小写hex",
    "duration_ms": 5000,
    "width": 864,
    "height": 496,
    "mime_type": "video/mp4",
    "audio_stream_count": 0,
    "face_coverage_sha256": "64位小写hex",
    "text_coverage_sha256": "64位小写hex"
  },
  "face_tracks": [
    {
      "track_key": "face-001",
      "source_character_key": "character-001",
      "time_ranges": [[0, 5000]],
      "target_character_name": "Ethan",
      "identity_asset_id": 3001,
      "identity_pack_sha256": "64位小写hex",
      "persona_origin": "fictional_ai_generated",
      "target_country": "US",
      "adult_status": "verified_18_plus"
    }
  ],
  "text_regions": [
    {
      "region_key": "text-001",
      "kind": "text_screen",
      "time_ranges": [[0, 5000]],
      "text_clean_asset_id": 4001,
      "text_clean_sha256": "64位小写hex"
    }
  ],
  "dialogue": {
    "localized_script_version_id": 5001,
    "target_locale": "en-US",
    "script_sha256": "64位小写hex",
    "character_name_map_sha256": "64位小写hex"
  },
  "coverage": {
    "recognizable_face_count": 1,
    "mapped_face_count": 1,
    "unresolved_face_count": 0,
    "review_status": "approved"
  },
  "coverage_sha256": "64位小写hex"
}
```

### 规范化与哈希

- `source.sha256`、片段范围、媒体元数据和所有产物哈希由服务端从当前可读资产计算。
- `face_tracks` 按 `track_key` 排序，时间段按开始时间排序并合并重叠区间；`text_regions` 使用相同规则。
- `coverage_sha256` 对去除审核时间等易变字段后的规范 JSON 计算；输入顺序变化不得改变结果。
- 保存参考包使用当前版本和 `expected_updated_at` 做 CAS。任何关联资产更新后，旧参考包必须变为过期，不能沿用旧请求快照。
- 对外投影不返回本地根目录、绝对路径、临时公网地址、Authorization、Key 或底层错误对象。

## 人脸覆盖与角色身份门禁

### 覆盖范围

“可辨认人脸”包括前景主角、配角、同框人物和背景群演中仍能辨认身份特征的脸。每条轨迹必须进入 `face_tracks`；遮挡、转身或切镜造成的多段轨迹在人工确认属于同一业务角色后可共享 `source_character_key`。

- 同一业务角色跨镜头必须复用同一个当前身份包。
- 不同业务角色不得绑定同一个身份包；同框的不同人物必须具有不同目标身份。
- 每个目标角色名从已批准的 en-US 角色表派生，使用适合美国语境的英文名，客户端不能在提交时临时改名。
- 角色身份包必须是 `target-actor-identity-v1`，正面、侧面、全身三视图齐全，身份一致性已确认，`adult_status='verified_18_plus'`，并标记 `persona_origin='fictional_ai_generated'`、`target_country='US'`。
- 身份包、底层图片或审核状态发生变化后，旧绑定立即失效。

供应商单次请求最多投影 9 个不同身份参考图。出现第 10 个身份时返回超限错误，由上层按镜头边界拆分；不得静默漏掉背景人物，不得自动用同一身份替代多个角色。

### 人脸覆盖审核

自动轨迹只作为候选证据。人工审核必须确认 `recognizable_face_count === mapped_face_count`、`unresolved_face_count === 0`，并批准覆盖清单。覆盖未批准时，即使每个已列轨迹都有身份包，也不能进入生成。

## 文字覆盖门禁

文字覆盖复用现有 `text_clean_plate` 合同，但从静态代表帧扩展为完整片段时间范围：

- `text_subtitle` 表示硬字幕；
- `text_screen` 表示屏幕、牌面或场景内可读中文；
- 每个区域必须绑定时间段、源帧指纹、mask 指纹、text-clean 产物指纹和已批准审核；
- 时间段必须覆盖该文字在片段内出现的所有帧，不能只凭一张静态 clean plate 宣称整段已清除；
- 文字类型、位置或持续时间变化时必须形成新的区域或关键帧证据；
- 不允许在证据缺失时回退到带中文字的源场景或原视频。

运动参考的 `text_coverage_sha256` 必须与当前文字区域规范清单一致。任一 text-clean 资产更新、撤销批准或哈希漂移后，运动参考和参考包同时过期。

## 英文对白、声音与角色名

- 目标语言固定为 `en-US`，对白来自当前已批准的本地化剧本版本。
- 服务端按对白时间轴绑定说话角色、英文台词哈希和美国化角色名映射；源中文对白不得进入供应商提示词。
- 同一角色在身份包、对白说话人、提示词和结果审核中必须使用同一个 `target_character_name`。
- 净化运动参考必须没有音频流，不能把原中文音轨作为参考音频上传。
- 后续供应商投影可以声明生成英文音频，但本阶段只验证请求合同，不调用模型，也不宣称口型或音色已经通过。

## 供应商请求白名单投影

后续供应商适配器只能接收参考包服务输出的白名单对象：

```json
{
  "reference_urls": ["已批准的角色三视图合成图"],
  "reference_video_urls": ["已净化且无音轨的运动参考视频"],
  "prompt": "由已批准 en-US 剧本和角色名映射生成的提示词",
  "target_locale": "en-US",
  "generate_audio": true
}
```

- `reference_urls` 只含身份包当前合成图，按 `track_key` 的首次出现顺序去重，数量为 0 至 9。
- `reference_video_urls` 必须恰好包含一个当前净化运动参考视频。
- 投影前再次校验参考包哈希、资产可读性和审核状态。
- 原片 URL、原始人脸图、原音频、带中文字图片以及客户端自报 URL 一律拒绝。
- 当前阶段使用捕获型假适配器断言请求投影，真实 Fumin 适配在后续独立阶段完成。

## 状态、错误码与副作用

稳定错误码如下：

- `REDRAW_REFERENCE_BUNDLE_FACE_COVERAGE_REQUIRED`：可辨认人脸未完整列出、未映射或覆盖未审核。
- `REDRAW_REFERENCE_BUNDLE_IDENTITY_PACK_REQUIRED`：身份包缺失、不完整、未批准、非虚构 AI 成年角色、国家不符或哈希过期。
- `REDRAW_REFERENCE_BUNDLE_TEXT_COVERAGE_REQUIRED`：字幕或场景文字未覆盖、未批准、类型不符或哈希过期。
- `REDRAW_REFERENCE_BUNDLE_MOTION_REFERENCE_STALE`：运动参考含音轨、源片/时间范围不符、覆盖哈希不符、文件不可读或已漂移。
- `REDRAW_REFERENCE_BUNDLE_REFERENCE_LIMIT_EXCEEDED`：不同身份参考超过 9 个，必须拆镜。
- `REDRAW_REFERENCE_BUNDLE_DIALOGUE_REQUIRED`：en-US 剧本、时间轴或角色名映射缺失或过期。
- `REDRAW_REFERENCE_BUNDLE_INPUT_INVALID`：未知字段、客户端自报哈希/路径/URL/审核结论或结构非法。
- `REDRAW_REFERENCE_BUNDLE_PROJECTION_FAILED`：安全白名单投影无法形成，不允许回退到原始内部对象。

所有失败都必须发生在首次业务状态写入、积分冻结和供应商调用之前。失败时：

- 数据库目标行不变；
- 积分冻结和扣除均为 0；
- 供应商调用次数为 0；
- 原片、身份包、text-clean 和旧审核资产保持不变；
- 响应只返回可定位的业务 ID 和稳定错误码，不泄露文件路径或供应商凭证。

成功生成参考包后，生成状态仍为待审核/待执行，不能直接标记为已生成或已验收。

## 本地 5 秒验证交付物

本阶段提供一个完全本地、无网络的 5 秒 fixture 和 CLI：

1. fixture 包含源片指纹、至少两条人脸轨迹、虚构美国成年角色三视图身份包、字幕/屏幕文字时间区域、en-US 对白和角色名映射。
2. runner 生成可完整解码的 MP4 运动参考，音频流数量为 0，并输出人脸与文字覆盖哈希。
3. runner 输出脱敏 JSON manifest 和 contact sheet；manifest 只含相对产物名和业务证据，不含绝对路径、Key、Authorization、原中文对白或临时公网 URL。
4. 捕获型假适配器证明最终投影只包含身份参考图、净化运动参考视频和 en-US 提示词。
5. 相同 fixture 重复运行得到相同的规范结构和覆盖哈希；时间戳和输出目录不进入哈希。

## 测试矩阵

### 必须先红灯的失败场景

- 人脸轨迹缺失、重复、时间范围重叠非法或存在未映射人脸。
- 同一业务角色跨段绑定不同身份，或不同业务角色复用同一身份。
- 身份参考超过 9 个。
- 身份包缺三视图、未批准、非成年、非虚构 AI 来源、目标国家不是 US 或内容哈希漂移。
- `text_subtitle` / `text_screen` 缺失、类型错配、时间覆盖有空洞、审核撤销或哈希漂移。
- 运动参考含音轨、源片指纹不符、片段范围不符、时长/尺寸/MIME 不符、覆盖哈希过期或路径越界。
- 对话目标语言不是 en-US、角色名映射缺失、说话角色与身份绑定不一致或脚本哈希过期。
- 请求中出现原片 URL、原始人脸图、带中文字图片、原音频或客户端自报 URL。
- 所有失败场景断言数据库不变、积分冻结为 0、供应商调用为 0。

### 必须绿灯的成功场景

- 反序输入得到稳定的人脸、文字和时间段排序及相同 `coverage_sha256`。
- 所有可辨认人脸一一绑定当前已批准的虚构美国成年身份包，角色名与 en-US 剧本一致。
- 5 秒运动参考可完整解码，音频流数量为 0，人脸与中文字覆盖证据完整。
- manifest 和错误序列化不含绝对路径、Key、Authorization、原中文对白或内部存储根。
- 白名单投影只有去重后的身份参考图和一个净化运动参考视频，不含原片及其派生产物 URL。
- 任何资产版本或审核状态变化都会使旧参考包失效，重新构建后才能进入待执行状态。

## 实现边界与阶段验收

当前分支的实现范围限定为：

1. 供应商无关的参考包构建与验证服务；
2. 生成前置门禁和安全请求快照；
3. 本地 5 秒 fixture、CLI、manifest、contact sheet；
4. 服务、门禁、投影和 CLI 自动化测试；
5. 一份脱敏本地验证报告。

本阶段验收通过只表示本地合同和门禁成立，不代表 Fumin 已完成全员换人、中文字清除、英文对白、完整 5 秒视频或整集 1:1 复刻。后续真实验证必须先在独立集成工作树接入已审计 Fumin 客户端，再取得一次明确付费授权，且只允许提交一个通过本设计门禁的请求。
