# 母本蓝图优先的一键转绘设计

日期：2026-09-03

状态：设计已通过，等待书面规格确认

适用范围：短剧一键转绘主链

## 1. 背景与问题

现有整集 Fumin 验收脚本直接依赖固定的九镜测试 fixture。人物 Mateo、Diego、Lucas、Elena、Rafael、九镜对白、镜头提示词和生成时长均为预先编写内容。该链路能够验证参考素材上传、视频生成、音轨检查、目标语言 ASR、角色一致性和结果下载，但不能证明产品能够从任意母本自动完成整集转绘。

现有原生母本分析已经具备视频探测、全片接触表、镜头时间轴、角色、场景、道具、动作、画面文字和事实合同，但分析输入没有母本音频转写证据。无可见字幕时，当前策略会把对白镜头降级为静音，因此尚不能形成完整的母本剧本。

产品主链必须由“围绕固定样片生成”调整为：

> 任意母本 → 多模态证据提取 → 完整母本蓝图 → 人物与对白本地化 → 逐镜生产包 → 视频生成 → 整集验收与导出

## 2. 目标

1. 从任意可读取的短剧母本生成覆盖全片的、可审核的 `episode-blueprint-v1`。
2. 严格区分母本事实、本地化版本和生成结果，任何下游处理不得覆盖母本事实。
3. 从母本音轨提取原始对白、时间码和说话人证据，并与镜头、人脸轨迹、字幕和画面动作对齐。
4. 按目标国家、市场和语言统一替换人物姓名、对白、地点、货币、屏幕文字及必要文化元素。
5. 从已批准蓝图自动派生逐镜生产包；真实产品运行路径不得依赖固定九镜 fixture。
6. 复用现有角色身份包、动作参考、素材审核、逐镜生成、语言验收、合成和导出能力。

## 3. 非目标

1. 不承诺像素级复制母本；验收对象是剧情、人物关系、镜头、动作、时间轴、对白和连续性。
2. 不允许系统补写母本未呈现的剧情或对白。
3. 本阶段不修改线上模型信息、供应商配置或定价。
4. 本阶段不执行供应商调用、付费生成、部署、生产数据库写入或生产切换。
5. 不重写已有生成与导出系统，只调整其输入来源并补齐缺失的母本反推链。

## 4. 方案选择

### 4.1 采用：母本蓝图优先

先完成全片证据提取和蓝图审核，再进行本地化和生成。优点是全局人物、剧情、对白和时间轴统一，可审计、可恢复，也能支持更换目标市场而不重复分析母本。

### 4.2 不采用：扩展固定九镜模板

继续给当前 fixture 增加更多人物和镜头虽然开发较快，但无法处理任意母本，且会把测试数据继续固化为产品事实。

### 4.3 不采用：边分析边逐镜生成

流式逐镜处理启动更快，但在尚未理解整集人物关系、因果链和后续反转时就生成前镜，容易产生跨镜角色、对白和剧情矛盾。

## 5. 总体架构

```text
源片上传
  ↓
媒体证据提取
  ├─ ffprobe 与音视频流信息
  ├─ 音轨提取、ASR 与说话人聚类
  ├─ 镜头边界、关键帧与人脸轨迹
  └─ OCR、字幕、动作、场景、道具与运镜分析
  ↓
多模态证据融合
  ↓
episode-blueprint-v1（母本事实）
  ↓
人工审核与事实锁定
  ↓
目标市场本地化版本
  ↓
人工审核与本地化锁定
  ↓
逐镜生产包
  ↓
现有素材、生成、QA、合成和导出链
```

母本蓝图是全链路唯一事实源。渲染供应商只能执行生产包，不能决定或重写剧情、人物姓名、对白和镜头时间轴。

## 6. 组件边界

### 6.1 媒体证据提取器

职责：读取母本并产生可验证的原始证据，不做剧情推断。

输出包括：

- 源文件 SHA-256、时长、分辨率、帧率、视频流和音频流；
- 完整音轨及其 SHA-256；
- 带单词或语句时间码的源语言 ASR；
- 说话人聚类和各聚类的发声时间段；
- 镜头边界、关键帧、连续人脸轨迹；
- OCR 文本、位置、出现时间及类型；
- 各证据文件的哈希、工具版本和生成时间。

### 6.2 多模态事实融合器

职责：将音频、视觉、OCR 和时间轴证据融合成一份全片蓝图。

规则：

- 视觉模型不得根据口型或剧情猜测对白；
- ASR 文本必须保留原文和精确时间范围；
- 说话人可以映射为角色、画外音角色或未解决声音聚类；
- 每项推断必须带证据引用和置信度；
- 镜头必须按时间连续覆盖完整母本，不得出现缺口或重叠；
- 低置信度结果进入人工审核，不自动补齐。

### 6.3 蓝图审核器

职责：让审核者在同步播放母本时检查和修正蓝图。

允许修正：镜头边界、人物映射、说话人、对白文字和时间码、OCR、场景、动作、运镜、道具及剧情关系。

审核通过后生成不可变的 `blueprint_hash`。后续修改必须产生新的蓝图修订版，不能原地改写已锁定版本。

### 6.4 本地化转换器

职责：从已锁定母本蓝图生成目标市场版本。

处理内容：

- 全剧统一的人物姓名映射；
- 对白翻译、语气和文化适配；
- 称谓、地点、货币、屏幕文字及必要文化元素；
- 目标对白时长、语速、情绪和发音要求；
- 全剧术语表、禁止变化项和映射一致性。

本地化版本引用 `blueprint_hash`，保存自己的 `localization_hash`，不得修改母本原文。

### 6.5 生产包编译器

职责：将已审核本地化版本编译为现有生成链能够消费的逐镜输入。

每镜生产包至少包含：

- 镜头 ID、母本起止时间和目标时长；
- 本镜角色身份参考及角色映射；
- 动作参考、关键帧、场景、服装和道具；
- 从蓝图派生的生成提示词；
- 按说话人绑定的目标语言对白和时间码；
- 对白模式、环境音、音乐和音效合同；
- 分辨率、画幅、连续性和验收要求；
- 源蓝图、本地化版本和生产包哈希。

### 6.6 现有执行与验收链

继续复用已有参考素材、角色身份包、逐镜生成、候选审核、音轨与目标语言检查、合成、整集 QA 和导出能力。固定九镜 fixture 仅保留为测试数据，不再作为真实运行入口。

## 7. `episode-blueprint-v1` 数据合同

顶层结构：

```json
{
  "schema_version": "episode-blueprint-v1",
  "source": {},
  "evidence_manifest": {},
  "story": {},
  "characters": [],
  "scenes": [],
  "props": [],
  "shots": [],
  "causal_chain": [],
  "locked_facts": [],
  "reversals": [],
  "episode_hook": {},
  "review": {},
  "blueprint_hash": ""
}
```

关键要求：

- `source` 记录源资产、源 SHA、音视频参数和完整时长；
- `evidence_manifest` 只记录受控证据引用、SHA 和工具版本，不嵌入密钥或供应商请求；
- `characters` 包含源角色名、显示名、人物关系、人脸轨迹和证据引用；
- `shots` 连续覆盖全片，包含构图、运镜、动作起止状态、可见人物、对白、文字区域和音频合同；
- 每句对白包含稳定 ID、原文、源语言、起止时间、说话人引用、情绪、画内或画外标记、证据和置信度；
- 未确定说话人使用稳定的 `speaker-cluster-N`，状态为 `needs_review`，不得强行映射给当前画面中的人物；
- 已锁定蓝图使用规范序列化计算 `blueprint_hash`。

## 8. 本地化数据合同

本地化版本独立保存：

```json
{
  "schema_version": "episode-localization-v1",
  "blueprint_hash": "",
  "locale": "en-US",
  "market": "US",
  "character_name_map": {},
  "dialogue_map": [],
  "text_region_map": [],
  "cultural_adaptations": [],
  "glossary": [],
  "locked_terms": [],
  "review": {},
  "localization_hash": ""
}
```

每条本地化对白必须引用源对白 ID，同时保存目标文本、预计发声时长、语速、情绪、发音提示和人工审核状态。人物姓名只从全剧统一映射中解析，不能在单镜提示词中临时命名。

## 9. 状态机与门禁

```text
uploaded
→ extracting
→ blueprint_review
→ blueprint_locked
→ localizing
→ localization_review
→ ready_to_generate
→ generating
→ episode_qa
→ delivered
```

门禁要求：

- `extracting` 只有在媒体、ASR、说话人、镜头、OCR 和视觉证据均形成可读产物后才能完成；
- 时间轴不完整、对白无时间码或证据不可读时不能进入 `blueprint_locked`；
- 未解决的关键角色或说话人必须人工确认；
- 只有 `blueprint_locked` 后才能创建本地化版本；
- 只有 `localization_review` 通过后才能创建逐镜生产包；
- 只有 `ready_to_generate` 才允许报价、预留积分或调用供应商；
- 任意上游版本发生变化时，依赖其哈希的下游生产包和生成结果自动失效。

## 10. 失败处理与恢复

1. 每个阶段产物独立、不可变并绑定 SHA；失败后从最近通过的阶段恢复。
2. ASR、说话人、镜头边界、角色对应或 OCR 置信度不足时进入审核，不允许模型补写。
3. 异步任务结果未知时保留状态并停止，不自动重试或重复计费。
4. 生成结果出现额外对白、错误语言、角色不一致、音轨缺失或时间超限时，只把该镜头标记失败，不污染母本蓝图。
5. 母本事实和已批准本地化版本保持可追溯；任何修正产生新修订和新哈希。
6. 产品逻辑与具体供应商解耦，不通过修改模型目录或线上模型配置解决剧本反推问题。

## 11. 用户界面

现有转绘工作台沿用，但“分析本地化”阶段拆成两个明确审核面：

1. 母本反推审核：左侧同步播放源片，右侧展示剧情、角色、镜头、原对白、说话人、OCR 和证据置信度。
2. 本地化审核：并排展示原文和目标文本，集中维护人物姓名映射、术语表和文化转换。

逐镜工作台只能读取已批准生产包；允许调整生产表现参数，但不能无痕修改母本剧情或本地化对白。

## 12. 测试策略

### 12.1 合同测试

- 蓝图时间轴必须从 0 连续覆盖到源片时长；
- 对白时间码必须落在所属镜头内；
- 支持画外音、内心独白和未解决声音聚类；
- 原始蓝图与本地化版本严格分离；
- 姓名映射、对白引用和内容哈希保持稳定；
- 上游哈希变化会使下游生产包失效。

### 12.2 组件测试

- 音轨提取、ASR、说话人聚类、镜头检测、OCR 和视觉证据产物可读；
- 证据融合不会在缺少音频或字幕证据时虚构对白；
- 同一人物改名会同步更新全剧称呼和所有生产包；
- 无对白镜头不会生成可听对白；
- 生产包编译结果不依赖固定测试 fixture。

### 12.3 端到端验收

使用用户提供的完整母本，依次验证：

1. 上传并生成完整母本蓝图；
2. 蓝图覆盖全片且无时间缺口或重叠；
3. 所有可听对白均有原文、时间码和说话人或待审核声音聚类；
4. 人物关系、场景、动作、运镜、文字和音频可追溯到母本证据；
5. 生成 `US / en-US` 本地化版本并统一替换人物姓名；
6. 自动生成全部逐镜生产包；
7. 在上述本地门禁通过且另获真实生成授权后，才执行视频生成验收；
8. 最终进行跨镜角色、剧情、对白、音轨和时间轴连续性检查并导出整集。

## 13. 完成标准

- 任意母本能够产生完整、可审核、可追溯的 `episode-blueprint-v1`；
- 所有可听对白进入母本事实层，不再依赖人工预写九镜台词；
- 人物姓名和目标对白由本地化版本统一维护；
- 逐镜提示词和生成输入全部从已批准蓝图派生；
- 固定 Mateo 九镜案例不再出现在真实产品运行路径；
- 母本分析、本地化、生成和整集交付分别有明确状态、哈希和验收证据；
- 未通过完整母本蓝图与本地化验收时，系统保持零付费生成。

## 14. 实施顺序

1. 扩展并版本化蓝图、证据和本地化合同；
2. 接入母本音轨提取、ASR 和说话人聚类；
3. 实现多模态证据融合及审核门禁；
4. 实现全剧人物姓名和对白本地化；
5. 实现蓝图到逐镜生产包的编译；
6. 将真实运行入口从固定 fixture 切换到生产包；
7. 完成合同、组件和完整母本端到端验收；
8. 在独立授权下进行真实视频生成、整集合成与交付验收。
