# 图片节点工具栏 P15：对口型实施规格

## 目标

为图片节点接入真实的“图片 + 项目音频 → 对口型 MP4”能力。源图片和源音频保持不变，成功结果作为视频派生资产写入，并在画布创建独立视频结果节点。

本包不包含核验、侵权检测或版权判断。

## 分包

### P15-A：来源与运行门控

- 只接受官方 `TMElyralab/MuseTalk` 源码和官方发布的模型权重。
- 固定并记录源码提交、许可证文件哈希和依赖清单哈希。
- 排除官方明确禁止商业使用的 Wav2Lip 开源版。
- 没有 NVIDIA CUDA GPU、FFmpeg、完整模型权重或可复现运行环境时，`lip_sync` 必须保持不可用。
- 本阶段不修改图片节点、视频节点或既有生成链的运行行为。

### P15-B：真实处理链

- 输入必须是当前项目可访问的图片资产和音频资产。
- 后端校验资产归属、类型、本地路径和允许的存储根目录。
- 使用固定版本的 MuseTalk 官方源码执行推理，不接受任意命令、任意 Python 模块或任意模型路径。
- 输出必须是包含视频流和音频流的 MP4；使用 FFprobe 校验时长、编码流和可读取性。
- 任务成功后创建 `type=video` 的派生资产，元数据记录源图片、源音频、源码提交、模型哈希、任务 ID 和处理参数。
- 前端不得用视频 URL 覆盖源图片节点；应创建独立视频结果节点并连接来源。
- 失败时保留源节点与源资产，写回可见错误并允许重试。

## P15-B 开工门槛

以下条件必须全部满足：

1. 本地或隔离验证服务器可识别 NVIDIA CUDA GPU，显存不少于 MuseTalk 官方已验证的 4GB 下限。
2. Python 3.10、匹配的 PyTorch/CUDA 环境和 FFmpeg 可用。
3. MuseTalk 1.5 及其 `sd-vae-ft-mse`、Whisper、DWPose、SyncNet、face parsing、ResNet 权重完整下载。
4. 每个源码和权重文件具有固定 SHA-256 清单，且许可证审计通过。
5. 使用非互联网测试素材完成真实图片 + 音频 → MP4 推理。

## 完成定义

只有以下条件全部成立时，`lip_sync` 才能从不可用切换为可用：

- `implemented`
- `backend_readback`
- `artifact_verified`
- `failure_writeback`
- `real_browser_verified`
- `license_audited`

静态 UI、固定 MP4、普通图生视频、测试桩或只有适配接口均不计为完成。
