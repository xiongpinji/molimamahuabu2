# 图片节点工具栏 P11：3D 角色姿势预演规格

## 1. 范围

本阶段只补齐图片节点“工具 → 姿势”：

- 复用现有 3D 导演台、Three.js 程序化骨骼角色和 GLTF/VRM 骨骼编辑链。
- 当前图片只作为造型与构图参考，不把图片人物伪装成已经完成骨骼绑定的角色。
- 已有可编辑角色时选中角色并定位到姿势编辑器。
- 尚无可编辑角色时不静默创建数据，只聚焦“添加角色”，由用户明确添加。
- 姿势预设、语义滑杆和关节旋转继续写入现有 `director_timeline`，不覆盖原图片。

本阶段不实现：

- 核验、侵权检测、版权判断；
- 图片人物自动抠取、3D 重建、骨骼绑定或图片重绘；
- 姿势生成模型、姿势迁移模型或新模型依赖；
- 全景、联想、推演、三视图、九宫格、对口型。

## 2. 真实能力边界

- 程序化角色使用项目现有真实 3D 关节层级和语义骨骼旋转。
- 用户加载的 GLTF/VRM 只有在模型资源状态为 `ready` 且包含骨骼时开放骨骼姿态编辑。
- “姿势”入口只打开导演台，不调用图片工具执行接口。
- 用户若需要图片结果，仍须在导演台内明确触发现有截图动作，截图生成新素材。

## 3. 交互

1. 后端能力接口将 `pose` 声明为：
   - `available=true`
   - `engine=director-stage`
   - `action=open`
   - `mode=pose`
2. 图片节点点击“姿势”后，导演台进入动画工作区和导演视角。
3. 若场景中存在 `type=character` 或 `type=humanoid` 的真实 3D 角色对象：
   - 选中该角色；
   - 定位并聚焦姿势编辑器。
4. 若没有角色对象：
   - 不自动新增或持久化数据；
   - 聚焦“添加角色”，等待用户明确操作。
5. 用户明确添加程序化角色后，定位到姿势编辑器。
6. 其他导演台、灯光和角度入口保持不变。

## 4. 验收

- `pose` 不调用 `/api/v1/image-tools/operations`。
- 姿势入口显示当前参考图和“不直接修改原图”的说明。
- 无角色入口不静默创建；显式新增后产生真实 `humanoid` 场景对象。
- 预设或语义控制写入对象 `poseRotations`，后端回读与刷新恢复一致。
- 原图 URL、资产 ID 和文件保持不变。
- 前后端专项、全量测试和前端构建通过。
- 生产代码没有核验、侵权或版权判断入口。
