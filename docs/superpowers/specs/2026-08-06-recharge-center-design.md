# 充值中心页面架构设计

## 状态

- 设计状态：用户已确认。
- 参考截图：`C:\Users\canqu\AppData\Local\Temp\codex-clipboard-233706bd-4eef-47d4-a1a3-244d15b9bd52.png`。
- 视觉方向：竞品的信息层级与茉莉妈妈橙色品牌体系结合，不做像素级复制。
- 支付边界：本阶段暂停支付宝商户联调，不改变支付网关、回调或积分入账逻辑。

## 已确认决策

1. 新建独立全屏充值中心，不再把完整充值表单塞在工作区管理长页面中。
2. 保留既有业务：固定 `1 元 = 100 积分` 的自定义充值，以及管理员动态套餐。
3. 默认展示「精选套餐」，通过顶部圆角分段控件切换到「自定义充值」。
4. 套餐卡片上半部使用大广告图，约占卡片高度 40% 至 45%。
5. 管理员通过结构化表单编辑广告图、角标、主标题、副标题、套餐名称、按钮文案、售价、积分、有效期、强调色和启停状态。
6. 套餐数量不固定。管理员可以拖动排序，并且最多指定 1 个推荐套餐。
7. 广告图由管理员直接上传，支持替换和实时预览。
8. 支付通道未配置时，页面仍完整展示，但所有下单按钮禁用并显示「支付通道准备中」。前端不得调用创建订单接口。

## 不在范围内

- 不新增月付、年付或自动续费会员。
- 不新增礼品卡、优惠券或自由排版广告编辑器。
- 不配置支付宝密钥，不发起真实支付，不调整支付宝回调账务。
- 不允许管理员写入 HTML、CSS 或脚本。
- 不删除兑换码、积分流水或工作区管理能力。

## 用户端信息架构

### 路由与入口

- 新增路由：`/recharge`，名称为 `recharge-center`。
- 顶部「充值积分」按钮直接进入 `/recharge`。
- 兼容旧入口：访问 `/tenant-console?section=recharge` 时跳转到 `/recharge`。
- 工作区页面保留积分概览和简短充值入口，不再渲染完整套餐网格。

### 页面顶部

- 左侧：茉莉妈妈标识与「充值中心」。
- 右侧：当前工作区可用积分、充值记录入口、关闭/返回按钮。
- 充值记录使用抽屉展示本人订单，继续按当前 `tenant_id + created_by` 隔离。

### 精选套餐标签页

- 桌面端默认 4 列；不足 4 个时不填充虚假卡片，超过 4 个时自动换行。
- 平板端 2 列，手机端 1 列。
- 排序规则：`sort_order ASC, created_at ASC`。
- 推荐套餐在桌面端上移约 10 px，并使用强调色边框与柔和光晕；移动端不位移。
- 卡片内容从上到下为：
  1. 广告图。
  2. 推荐标识与角标。
  3. 广告副标题与主标题。
  4. 套餐名称与有效期。
  5. 售价、到账积分和每元积分比例。
  6. 基础积分与额外赠送积分。
  7. 购买按钮。
- 基础积分按 `售价（元）× 100` 计算。额外赠送积分为 `max(到账积分 - 基础积分, 0)`；没有正赠送时隐藏赠送角标，不限制管理员设置低于 1:100 的套餐。

### 自定义充值标签页

- 固定显示 `1 元 = 100 积分`，比例不能由用户或套餐配置改变。
- 金额范围沿用后端配置，当前为 `1.00` 至 `50000.00` 元，最多 2 位小数。
- 快捷金额为前端辅助值：`10`、`30`、`50`、`100`、`300`、`500` 元；用户仍可直接输入合法金额。
- 左侧展示金额输入、快捷金额、预计积分和规则说明。
- 右侧展示订单摘要与支付通道状态。
- 支付通道未配置时，按钮禁用并明确说明不会创建订单或扣款。

## 管理员后台

### 页面结构

- 继续放在 `/billing-admin` 的「充值套餐」标签页。
- 左栏：套餐缩略图、名称、价格、状态、拖动手柄和推荐标识。
- 中栏：结构化编辑表单。
- 右栏：用户端卡片实时预览。
- 小屏幕下改为单列，预览区移动到表单下方。

### 可编辑字段

| 字段 | 约束 |
|------|------|
| `name` | 必填，最多 60 个字符 |
| `badge_text` | 可选，最多 20 个字符 |
| `ad_title` | 必填，最多 48 个字符 |
| `ad_subtitle` | 可选，最多 80 个字符 |
| `button_text` | 必填，最多 20 个字符，默认「立即购买」 |
| `amount_cents` | `1` 至 `5000000` 分 |
| `credits` | 正整数，最多 `100000000` |
| `starts_at` / `ends_at` | 可选 ISO 8601 时间；结束时间必须晚于开始时间 |
| `image_url` | 必填；只接受后台上传得到的同源 `/static/uploads/recharge-packages/` 地址或 HTTPS 地址 |
| `accent_color` | `#RRGGBB`，默认 `#ff7139` |
| `sort_order` | 非负整数，由拖动排序统一更新 |
| `is_featured` | `0/1`；全表最多 1 条为 `1` |
| `status` | `active` 或 `inactive` |

强调色只用于边框、角标和按钮渐变，不覆盖广告图内容。管理员不能提交任意 CSS。

### 图片上传

- 新增管理员专用接口：`POST /billing/admin/recharge-packages/image`。
- 复用现有 `uploadService` 和存储目录，不复制上传系统。
- 路由必须经过 `requireAdmin` 与 `requireBillingManager`。
- 仅接受 JPEG、PNG、WebP；沿用服务器统一上传大小上限。
- 沿用现有 `uploadService` 合同，返回同源 `/static/uploads/recharge-packages/` 地址，管理员保存套餐时再写入 `image_url`。
- 上传失败不修改当前套餐图片；保存套餐失败也不清空已有图片。

## 数据模型

新增迁移 `49_recharge_package_presentation.sql`，为 `recharge_packages` 增加：

```sql
badge_text TEXT NOT NULL DEFAULT ''
ad_title TEXT NOT NULL DEFAULT ''
ad_subtitle TEXT NOT NULL DEFAULT ''
button_text TEXT NOT NULL DEFAULT '立即购买'
accent_color TEXT NOT NULL DEFAULT '#ff7139'
sort_order INTEGER NOT NULL DEFAULT 0
is_featured INTEGER NOT NULL DEFAULT 0 CHECK (is_featured IN (0, 1))
```

增加部分唯一索引，保证最多只有 1 个推荐套餐：

```sql
CREATE UNIQUE INDEX uq_recharge_packages_featured
ON recharge_packages(is_featured)
WHERE is_featured = 1;
```

设置新推荐套餐时，服务层必须在同一 SQLite 事务中先清除旧推荐，再保存新推荐。

## API 调整

- 现有 `GET /billing/recharge/packages` 返回新增展示字段，并按 `sort_order` 排序。
- 现有管理员创建和更新接口接收新增结构化字段。
- 新增 `PUT /billing/admin/recharge-packages/order`，请求体为完整套餐 ID 顺序列表；服务端验证 ID 不重复且与现有套餐集合一致后，在事务中更新 `sort_order`。
- 新增管理员广告图上传接口，权限与套餐管理一致。
- 支付订单继续保存套餐名称、金额和积分快照。广告文案变化不修改历史订单。

## 前端组件边界

- `RechargeCenter.vue`：页面数据装载、标签切换、支付配置状态和记录抽屉。
- `RechargePackageCard.vue`：单张套餐卡片，只接收套餐数据和禁用状态。
- `CustomRechargePanel.vue`：金额校验、快捷金额、预计积分与订单摘要。
- `RechargePackageAdminPanel.vue`：列表排序、结构化编辑、上传和实时预览。

不为一次性字段再创建额外抽象。现有计费 API 保留在 `src/api/billing.js`，上传调用保留在现有上传 API 层。

## 数据流

1. 页面并行读取支付配置、可用套餐、本人订单和当前积分。
2. 支付配置为关闭状态时，页面只展示，不允许创建订单。
3. 支付启用后，套餐和自定义充值继续调用同一个支付宝订单接口。
4. 同步跳转只负责回到充值中心；积分到账仍只由已验签的异步通知触发。
5. 返回充值中心后重新读取订单、积分和积分流水。

## 错误与空状态

- 无套餐：显示「暂无可用套餐」，仍允许切换到自定义充值。
- 图片加载失败：显示套餐强调色占位层和套餐名称，不影响金额信息。
- 套餐过期或被停用：后端不返回；即使用户保留旧页面，创建订单时仍由后端拒绝。
- 上传失败：保留旧图片并显示明确错误。
- 排序保存失败：恢复服务端顺序，不保留仅前端成功的假象。
- 支付配置关闭：按钮禁用，不发送订单请求。

## 无障碍与响应式

- 所有标签切换、拖动排序和按钮支持键盘操作；拖动排序同时提供「上移/下移」菜单。
- 图片提供由套餐名称生成的替代文本。
- 强调色不能作为唯一状态提示；推荐、停用、过期均有文字标签。
- 金额、积分和有效期保持文本可读，不把业务文字烘焙进图片。
- 实现后使用浏览器截图验证 1440 px、1024 px、390 px 三个视口。

## 验收标准

1. 顶部充值入口进入独立 `/recharge` 页面。
2. 套餐页按管理员顺序展示大图卡片，最多 1 个推荐套餐。
3. 自定义充值始终固定为 `1:100`，预计积分计算准确。
4. 管理员能上传图片并修改全部结构化内容，用户端实时反映保存结果。
5. 支付未配置时页面完整可见，但任何按钮都不会创建订单。
6. 非计费管理员不能上传套餐图片、调整顺序或修改套餐。
7. 桌面、平板和手机布局不溢出，按钮与文本可读。
8. 原有回调验签、订单幂等、积分原子入账和租户隔离测试继续通过。
