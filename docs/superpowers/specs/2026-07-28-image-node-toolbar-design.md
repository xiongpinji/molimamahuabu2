- 状态：已获用户确认，进入本地实现

## 1. 目标

在现有自由画布图片节点上补齐参考站展示的图片工具能力，并复用项目已有的任务、资产、失败回写和画布持久化链路。所有处理结果生成派生资产，不覆盖原图。

本轮明确不实现：

- 侵权检测、版权判断或相似作品检索
- “核验”按钮、绿盾状态、核验报告
- 任何会让用户误认为内容已通过版权核验的状态

核验能力应在本轮全部功能完成并经过独立设计、数据源与法律边界评审后，另开任务和 PR。

## 3. 产品交互

图片节点被选中且已有图片结果时，在节点上方展示工具栏：

1. 一级入口：`720 全景`、`灯光`、`高清`、`工具`、`设定`。
2. 快捷入口：任务历史、节点色标、替换图片、下载、全屏预览。
3. `工具`菜单：
   - 裁剪 / 压缩 / 镜像
   - 标记修图
   - 宫格裁剪
   - 智能抠图
   - 框选抠图
   - 图片调整
   - LUT 调色
   - 生成导演台
   - 姿势
   - 角度
   - 扩图
   - 画面联想
   - 角度联想
   - 对口型
4. `设定`菜单：
   - 生成全景场景
   - 角色三视图
   - 多机位叙事九宫格
   - 画面推演：3 秒后
   - 画面推演：5 秒前
   - 电影级光影校正
   - 细节纹理增强

入口只在图片节点上出现。没有源图片、节点正在运行或能力未配置时，按钮必须显示明确禁用原因，不能调用空处理器或返回假结果。

## 4. 架构

```text
图片节点工具栏
  -> 工具参数面板
  -> 统一图片操作 API
     -> 确定性处理器（Sharp）
     -> 本地模型适配器（经许可证审计）
     -> 现有生成供应商适配器
  -> 现有任务状态与失败回写
  -> 派生资产入库
  -> 节点更新为新结果
```

### 4.1 前端

- `HomeCanvasNode.vue` 只负责图片节点工具栏挂载和入口状态。
- 新建独立工具栏、菜单和参数面板组件，避免继续放大节点组件。
- `DramaCanvas.vue` 继续作为画布编排边界，复用现有 `runFreeCanvasNode`、任务轮询、资产入库与失败回写模式。
- 下载、全屏和替换图片复用现有结果动作与上传能力。

### 4.2 后端

新增统一接口：

```http
GET  /api/v1/image-tools/capabilities
POST /api/v1/image-tools/operations
GET  /api/v1/image-tools/operations/:taskId
```

创建操作的最小请求：

```json
{
  "assetId": "source-asset-id",
  "operation": "crop",
  "parameters": {}
}
```

成功结果必须包含：

```json
{
  "taskId": "task-id",
  "status": "success",
  "sourceAssetId": "source-asset-id",
  "resultAssetId": "derived-asset-id",
  "resultUrl": "/static/...",
  "operation": "crop"
}
```

所有接口沿用现有鉴权和租户边界。后端必须从当前租户资产记录解析源文件，不接受任意本地文件路径或未经允许的远程 URL。

### 4.3 派生资产

派生资产 metadata 至少记录：

- `sourceAssetId`
- `sourceNodeId`
- `operation`
- `parameters`
- `engine`
- `engineVersion`
- `taskId`
- `createdAt`

原资产保持不变。失败时不创建成功资产，节点保留原结果并写入可重试错误。

## 5. 实施包

### P1：工具栏与确定性图片处理

- 工具栏、菜单、快捷动作和能力状态
- 替换图片、下载、全屏、任务历史入口
- 裁剪、压缩、旋转 / 镜像、宫格裁剪
- 亮度、对比度、饱和度、色温等图片调整
- 基础 LUT 调色
- 派生资产和失败回写

实现：项目自有 Vue 交互与 API 编排，后端复用已安装的 Sharp。裁剪交互优先评估 Cropper.js，只有在依赖审计通过后引入。

### P2：局部编辑与抠图

- 标记修图
- 智能抠图
- 框选抠图

实现：前端蒙版编辑器自研；模型处理只接入许可证和权重均通过审计的成熟实现。候选为 rembg 或 BiRefNet 兼容服务，不能把非商用权重带入商用链路。

### P3：高清、细节和灯光

- 高清增强
- 细节纹理增强
- 灯光调整
- 电影级光影校正

候选：Real-ESRGAN、IC-Light。IC-Light 默认示例链中的背景移除模型存在商用限制，必须替换并单独记录权重许可证。

### P4：生成与推演

- 720 全景、生成全景场景
- 扩图
- 姿势、角度
- 画面联想、角度联想
- 角色三视图、多机位叙事九宫格
- 前后帧推演
- 生成导演台
- 对口型

这些功能复用现有图片 / 视频供应商和任务链。只有真实供应商能力存在且完成本地同链验证时才标记完成；静态 UI、固定文件、模拟任务或仅测试桩不计为完成。

### P5：审计与交付

- 全量后端测试
- 全量前端测试与构建
- 隔离端口浏览器验证
- 源资产到派生资产的数据库回读
- 产物 MIME、尺寸与可下载性验证
- 失败写回与重试验证
- 许可证、模型权重、依赖漏洞和网络行为审计
- 确认无核验相关入口或状态

## 6. TDD 行为清单

按垂直切片逐条执行“一个失败测试 -> 最小实现 -> 测试通过”：

1. 当前租户可以读取图片工具能力，未配置能力带明确原因。
2. 当前租户可以用自己的图片资产创建裁剪派生资产。
3. 不能处理其他租户的资产。
4. 非图片、缺失资产、非法操作和越界参数被拒绝。
5. 处理失败不覆盖原资产，并返回可用于节点失败回写的信息。
6. 前端只在有图片结果的图片节点上显示工具栏。
7. 前端提交处理后显示运行态，成功切换到派生资产，失败保留原图。
8. 下载、全屏、替换图片和历史入口继续使用现有公共链路。

## 7. 完成定义

单个功能只有同时满足以下条件才标记完成：

- `implemented`：真实代码已接入
- `backend_readback`：任务和派生资产可从后端回读
- `artifact_verified`：产物存在且 MIME、尺寸和下载内容有效
- `failure_writeback`：失败状态可见且可重试
- `real_browser_verified`：隔离端口浏览器完成同链操作
- `license_audited`：源码及模型权重许可证已记录并通过

任一条件缺失时，该功能保持未完成或受阻状态，不进入 PR 完成声明。
