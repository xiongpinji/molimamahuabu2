# 画布图片自适应质量优化设计

- 日期：2026-08-09
- 状态：用户已批准
- 范围：自由画布图片节点的文生图、单图参考、多图参考
- 计费决定：用户只支付首次生成积分；质量门禁触发的一次自动重试由平台承担

## 1. 背景与已确认问题

用户反馈画布图片节点生成结果不够真实、细节质量偏低，同时要求兼顾：

1. 写实度；
2. 人物、场景和多参考图的一致性；
3. 生成时间与供应商成本。

当前代码存在一条明确的降质链路：

- `frontweb/src/utils/freeCanvasGeneration.js` 的画布图片请求包含模型、分辨率、尺寸、负面词和参考图，但没有传递 `quality`；
- `backend-node/src/services/imageService.js` 创建 `image_generations` 记录时没有持久化 `quality`，而后续处理阶段读取的是 `row.quality`；
- `backend-node/src/services/imageClient.js` 对未提供质量档的 GPT Image 请求默认补入 `quality: low`，并使用 JPEG 85 压缩。

因此，至少对 GPT Image 兼容路径，画布选择 2K 并不等于供应商使用高质量档。该源代码证据足以说明当前链路可能主动降质，但最终改善幅度仍必须通过同一模型、同一提示词和同一参考素材的真实生成对照确认。

## 2. 目标

1. 所有画布图片生成入口默认使用“推荐质量”策略。
2. 按模型已验证能力显式选择原生质量、分辨率、输出格式和参考图上限。
3. 在不改变用户主体、构图和剧情意图的前提下增强写实摄影表达。
4. 对人物和参考图任务增强身份、场景和角色对应关系。
5. 生成后执行质量门禁；不合格时只允许一次定向自动重试。
6. 用户账本始终只结算首次生成，平台重试不得产生第二笔用户扣费。
7. 保留受保护合同 `canvas-credit-callout-v1`，继续醒目显示“本次预计扣除 X 积分”。

## 3. 非目标

- 不更换或擅自开放未经真实生成验证的供应商模型。
- 不固定生成两张图片后择优。
- 不用普通放大或锐化冒充模型原生高质量输出。
- 不给所有供应商强行发送相同参数。
- 不无限重试，也不因纯主观风格差异自动重试。
- 不改动短剧工厂、首页快捷生成等非画布入口，除非后续单独批准。

## 4. 总体架构

```text
画布节点请求
  -> 后端质量策略解析
  -> 已验证模型能力映射
  -> 写实提示增强与参考角色锁定
  -> 首次高质量生成
  -> 本地硬指标门禁
  -> 按需语义质量门禁
     -> 合格：保存结果
     -> 不合格：按失败原因修正并重试一次
        -> 保存较优结果并标记 passed 或 review_required
```

后端是质量规则的唯一来源。前端只提交 `quality_profile: recommended` 并展示状态，不自行拼装供应商专属参数。

## 5. 模型能力与质量策略

### 5.1 能力登记

沿用现有模型能力目录，在每个已经过真实生成验证的图片模型上声明：

- 支持的质量档，如 `high`、`standard`；
- 支持的原生分辨率和尺寸映射；
- 支持的输出格式及高质量压缩策略；
- 文生图、单图参考、多图参考能力；
- 最大参考图数量；
- 是否接受负面词；
- 是否允许质量门禁自动重试。

未声明或未验证的能力不得靠模型名称猜测。模型不支持的参数不得发送给供应商。

### 5.2 推荐质量解析

`recommended` 的解析顺序为：

1. 使用该模型已验证的最高稳定质量档；
2. 使用用户所选画幅对应的原生尺寸，优先 2K；
3. 高质量模式不得回落到 `quality: low`；
4. GPT Image 高质量路径不使用 JPEG 85 作为固定默认值；具体使用无损格式或更高压缩质量，以真实供应商验证结果为准；
5. 模型只有 1K 或标准档时，界面如实展示，不做伪 2K。

## 6. 提示增强与参考锁定

### 6.1 写实增强

后端在用户提示词之后追加受控、版本化的写实段落，覆盖：

- 真实摄影机与镜头语义；
- 自然皮肤、毛发、布料、金属和环境材质；
- 合理光照、阴影、反射、景深和动态范围；
- 抑制蜡像、过度磨皮、塑料感、CG/3D 渲染感。

增强段落不得改写用户的人物、动作、地点、时代、镜头位置和构图。

### 6.2 多参考图角色锁定

- 保持参考图顺序；
- 为每张参考图建立稳定编号；
- 提示词明确“参考图 N 对应角色/场景 N”；
- 人物任务保留脸型、五官比例、发型、年龄感和服装关键特征；
- 场景任务保留空间结构、色调和关键道具；
- 继续使用现有防拼贴负面词，避免把多张参考图直接拼成分栏画面。

## 7. 两层质量门禁

### 7.1 第一层：本地硬指标

不调用外部模型，至少检查：

- 结果文件可读取且不是空白图；
- 实际像素尺寸达到当前模型档位承诺；
- 不存在严重模糊；
- 不存在极端过曝或欠曝；
- 不存在明显压缩损坏或错误格式。

硬指标失败可直接进入定向重试，不再调用语义检查。

### 7.2 第二层：按需语义检查

仅在人物、参考图或明确写实任务中启用，检查：

- 塑料感、蜡像感或明显 CG 感；
- 人脸、肢体和手指的明显畸形；
- 人物身份、服装和场景与参考素材的一致性；
- 多参考图角色是否串位。

语义检查必须使用已经验证可读取图片和多参考输入的视觉评估能力。若没有已验证评估器，状态必须记为 `not_evaluated`，不得向用户显示“语义检查已通过”，也不得仅凭伪分数触发扣费或无限重试。

阈值必须版本化，初始阈值由真实样本集校准；不得在没有对照证据时写死一个看似精确的通用分数。

## 8. 定向重试规则

自动重试上限固定为一次，并且只修正检测失败的维度：

| 失败原因 | 第二次请求修正 |
| --- | --- |
| 模糊、细节不足、压缩明显 | 强制该模型已验证的高质量原生输出，强化真实焦点与微细节 |
| 塑料感、CG 感 | 增加自然皮肤纹理、真实光学、环境反射，压制蜡像和 3D 渲染感 |
| 参考人物不一致 | 强化身份锁定和参考图编号，不改变构图 |
| 肢体或手指异常 | 只追加解剖约束和相应负面词 |
| 文件损坏或供应商空结果 | 使用相同语义请求重试，不擅自改写提示词 |

第二次仍不合格时停止调用，比较两次结果并保留较优文件，状态设为 `review_required`，向用户展示“建议复核”，不得继续消耗供应商调用。

## 9. 状态与审计数据

画布节点至少支持以下可见状态：

- `generating`：高质量生成中；
- `checking`：质量检查中；
- `retrying`：正在定向重试 1/1；
- `passed`：质量检查通过；
- `review_required`：已保留较优结果，建议人工复核；
- `failed`：没有可读取结果。

在现有 `image_generations.request_snapshot` 中保存质量策略输入；在结果审计数据中保存：

- 质量策略版本；
- 实际供应商质量、尺寸和输出格式；
- 每次尝试的开始、终态、文件地址和检查结果；
- 触发重试的原因；
- 最终选择哪次结果；
- 第二次调用属于 `platform_quality_retry`，用户计费金额为零。

若现有字段无法保证原子更新和可追溯性，实施时只增加一个结构化质量审计字段或最小事件表，不同时引入两套存储。

## 10. 积分结算

已批准规则：

1. 生成前仍按首次生成显示醒目加粗的“本次预计扣除 X 积分 · 1 次”；
2. 首次生成沿用现有积分预占、成功结算和失败退款逻辑；
3. 质量门禁触发的第二次供应商调用由平台承担；
4. 第二次调用不得创建用户积分预占、扣款或第二笔账本流水；
5. 平台重试必须单独记录供应商成本和触发原因；
6. 首次没有任何可读取结果时，仍按现有失败退款规则处理；不能因为平台重试也失败而吞掉退款。

## 11. 画布交互

- 图片节点默认显示“质量策略：推荐”；
- 显示实际能力标签，例如“原生 2K”“参考一致性已启用”；
- 生成过程中显示当前阶段，不让用户误以为页面卡死；
- 发生自动重试时显示“正在定向重试 1/1”，但积分卡片金额不增加；
- 结束时显示“已通过”或“建议复核”；
- 继续保留 `canvas-credit-callout-v1`：已定价显示“本次预计扣除 X 积分”，未定价显示“积分待管理员配置”。

## 12. 错误处理

- 不支持的质量参数：在供应商提交前由能力映射拒绝或降为该模型已验证档位，并在响应中返回实际档位；不得静默变为 `low`。
- 质量评估器不可用：完成本地硬指标检查，语义状态记为 `not_evaluated`，不触发语义重试。
- 首次成功、重试网络失败：保留首次可读取结果并标记 `review_required`。
- 两次都有结果：根据门禁结果选择较优文件，不能仅按“第二次更新”覆盖首次结果。
- 任务中断或进程重启：根据持久化的尝试次数恢复，已执行一次平台重试后不得再次提交。

## 13. 测试与验收

### 13.1 自动测试

1. 请求合同测试：画布文生图、单图和多图请求均携带 `quality_profile: recommended`。
2. 持久化测试：质量档不会在 `imageService` 创建记录后丢失。
3. GPT Image 客户端测试：推荐质量不得生成 `quality: low`，高质量输出格式符合能力配置。
4. 能力映射测试：不同模型只收到自身支持的质量、尺寸和参考字段。
5. 提示增强测试：用户原始提示完整保留，多参考编号稳定。
6. 门禁测试：硬指标通过/失败、语义可用/不可用、一次重试上限和较优结果选择。
7. 计费测试：平台重试不会产生第二笔用户预占或扣费；完全失败仍正确退款。
8. 状态恢复测试：进程恢复后不会重复提交平台重试。
9. 前端测试：质量状态、推荐标签和醒目积分卡片始终存在。
10. 执行共享积分合同审计器并要求构建产物通过。

### 13.2 真实生成验收

使用同一已验证模型、同一提示词、同一画幅和同一组参考素材完成对照：

- 文生图至少一组；
- 单图人物参考至少一组；
- 多图人物与场景参考至少一组；
- 至少一组故意容易产生塑料感或身份漂移的样本，用于验证定向重试。

每组必须保存不含密钥的请求摘要、供应商成功终态、可读取原文件、实际尺寸、文件哈希、质量门禁结果、用户账本和平台重试审计。只通过单元测试、构建或供应商模型列表不能判定完成。

## 14. 发布与回滚

- 生产候选必须从实时 `/opt/moli-drama/current` 克隆，只覆盖本任务审计过的文件；
- 候选执行后端相关测试、前端测试与构建、真实模型验收、积分合同共享审计器；
- 只能通过 `/opt/moli-drama/shared/release-guard/activate-protected-release.sh CANDIDATE EXPECTED_CURRENT` 激活；
- 禁止直接替换 `current` 或弱化共享门禁；
- 质量策略必须有总开关，回滚时可关闭门禁和平台重试，同时保留显式高质量参数修复与积分卡片合同；
- 发布后监控质量通过率、重试率、平均耗时、平台重试成本、人工复核率和用户失败退款率。

## 15. 成功标准

本设计只有在以下条件全部满足时才算实现完成：

1. 源代码链路不再隐式使用 `low`；
2. 画布文生图、单图和多图参考均完成真实生成并取得可读原图；
3. 对照样本的写实度、清晰度和参考一致性有可审查证据；
4. 自动重试严格最多一次；
5. 用户只扣首次积分，平台重试可追溯；
6. 醒目积分卡片合同未回退；
7. 自动测试、构建、共享门禁与生产前审计全部通过。
