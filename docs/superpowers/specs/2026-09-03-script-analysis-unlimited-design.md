# 剧本分析不限字数与线上短视频验收设计

## 目标

从生产前端用户路径移除剧本分析固定 60,000 字符上限，使超过原上限的剧本能够保存并通过自动分段完成导演分析；发布后再用一个短剧本从剧本分析入口进入短剧工厂，生成并验证一个可读取、可播放的短视频。

## 已确认现状

- 生产版本前端 `ScriptAnalysis.vue` 同时通过 `maxlength`、字数上限文案和文件导入校验限制 60,000 字符。
- 后端 `scriptAnalysisService.js` 的 `getProjectInputError()` 再次拒绝超过 60,000 字符的剧本。
- 数据库存储字段为 SQLite `TEXT`，Express JSON 请求体上限为 10 MB；这属于系统容量边界，不作为用户可见的剧本字数配额。
- 当前模型调用把整份剧本放入一次提示词。只删除校验会造成“可以输入但模型上下文溢出”，因此需要分段分析。
- 生产发布必须从操作时 `/opt/moli-drama/current` 克隆候选，只叠加本任务允许文件，并通过共享发布门禁后用受保护激活器切换。

## 方案

### 输入与保存

前端移除剧本 textarea 的 `maxlength`、`SCRIPT_CHAR_LIMIT` 和导入文件的 60,000 字符拒绝逻辑，标签改为只展示当前字符数。后端删除 `sourceScriptChars` 业务校验，但保留空剧本、锁定事实数量与单条长度校验。请求体仍受既有 10 MB 基础设施容量保护。

### 自动分段分析

- 短剧本继续走现有单次模型调用，避免改变已验证行为。
- 超过安全分段阈值时，按换行或句末标点从靠近阈值的位置切分；无法找到自然边界时按 Unicode 字符安全切分。
- 每段沿用用户选择的导演 Skill、创作策略和锁定事实，调用现有生产包生成与校验链路。
- 将分段生产包确定性合并：保留完整原剧本作为 `source.source_script`；人物、场景、道具按稳定名称去重；分段的集、场、镜头按原顺序拼接并重新编号；连续性规则、AI 变更与审核问题按顺序合并；合计目标时长。
- 每个分段产物必须先通过现有 schema 校验，合并后的完整产物再次通过同一 schema 校验。任一分段失败则整个分析任务失败，不保存半成品版本。
- 日志只记录分段编号、总数和字符数，不记录剧本文本。

## 修改边界

预计只修改：

- `frontweb/src/views/ScriptAnalysis.vue`：移除固定输入/导入上限并保留实时计数。
- `frontweb/test/scriptAnalysisUnlimited.test.js`：锁定前端无固定上限合同。
- `backend-node/src/services/scriptAnalysisService.js`：移除 60,000 字符拒绝，增加分段与确定性合并。
- `backend-node/test/scriptAnalysisService.test.js`：覆盖长文本接受、自然边界分段、分段调用和合并校验。
- `docs/superpowers/plans/2026-09-03-script-analysis-unlimited.md`：实现与发布计划。
- `docs/superpowers/reports/2026-09-03-script-analysis-unlimited-verification.md`：记录不含密钥的测试、发布和线上验收证据。

不修改积分规则、视频模型目录/配置、AI 音乐、生产数据结构、共享发布门禁或其他页面功能。

## 错误与费用边界

- 超长剧本会产生多次文本模型调用，按现有剧本分析计费策略处理；不得静默截断。
- 线上长剧本验收只做一次，长度略高于旧 60,000 字符边界，并等待成功终态。
- 短视频验收使用独立的简短剧本，只生成一个最短可用视频，避免把长剧本批量送入图片/视频生成链路。
- 若模型、积分、供应商或页面流程失败，保留任务证据并停止，不重复点击造成重复扣费。

## 验证与线上 QA 清单

1. TDD 红灯：旧实现拒绝 60,001 字符；新测试必须先以预期原因失败。
2. 绿灯：后端接受长剧本，分段调用次数与顺序正确，合并产物保留完整源剧本并通过 V1/V2 校验。
3. 前端合同：不再出现 `SCRIPT_CHAR_LIMIT`、剧本 `maxlength` 或“超过 60,000 字符”导入拒绝；当前字符数仍可见。
4. 回归：剧本分析专项测试、路由测试、前端测试、前端构建、生产预检和受保护合同审计通过。
5. 发布：确认其他会话无生产动作；实时读取 current/锁/活动任务/AI 音乐 PID；从实时 current 构建精确候选；shared verify-only 通过；由共享激活器切换。
6. 线上桌面浏览器：登录、打开剧本分析、粘贴或导入 60,001 字符以上文本、保存并启动分析、等待成功、确认生产包与版本可见。
7. 线上短视频：用简短剧本完成分析、导入短剧工厂、只生成一个镜头视频、等待成功，确认页面视频元素可加载且媒体文件返回成功并可读取。
8. 探索性检查：空剧本仍被阻止；非法文件类型仍被阻止；页面在 1600x900 和较小桌面视口无新增截断或横向溢出。
9. 发布后复核：内部健康、公开路由、服务 PID/重启数、活动任务、SQLite `quick_check`、严重日志和 8787 AI 音乐 PID。

## 完成标准

只有同时拿到“超过旧上限的线上前端分析成功”和“一个线上前端生成的视频成品可读取/播放”两条证据，才能宣称用户要求完成。测试、构建或 API 成功不能替代这两项用户视角验收。
