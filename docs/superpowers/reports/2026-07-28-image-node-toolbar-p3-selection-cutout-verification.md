## 1. 结论

框选抠图已在独立工作树、独立数据库、独立素材目录和独立端口完成真实本地链路验证：

- 前端用固定版本 Cropper.js 生成真实像素选区，不提交相对比例或客户端命令。
- 后端校验选区坐标、边界和像素上限，先生成临时选区 PNG，再调用 P2 已审计的 `rembg 2.0.77` 与 `u2netp`。
- 同一并发令牌覆盖选区解码、裁剪、临时文件写入、rembg 执行和最终产物校验，忙碌请求不会提前消耗图像处理资源。
- 临时选区 PNG 通过流式计数限制为 64 MiB；损坏、超像素上限或写入失败等底层错误只记入服务端日志，接口和任务记录统一返回固定错误。
- 产物是选区尺寸的透明 PNG，并以派生素材、异步任务和节点历史记录落库。
- 成功后删除临时选区文件；失败时沿用图片工具链的产物清理、错误写回和重试状态。
- 未配置或配置无效的 rembg/U²-Net 环境不会公布框选抠图能力。
- 核验、侵权检测和版权判断仍未加入生产代码。

该结论只覆盖本地开发与验证。本阶段不推送 PR、不部署服务器，也不声称线上可用。

## 2. 实现边界

混合方案继续复用 P2 已审计的模型供应链：

- 成熟模型能力：`rembg 2.0.77`（MIT）与 U-2-Net `u2netp`（Apache-2.0）。
- 项目自有代码：选区交互、参数白名单、图片边界校验、临时文件生命周期、租户并发、任务记录、派生素材和画布状态。
- 模型文件固定 SHA-256：`309C8469258DDA742793DCE0EBEA8E6DD393174F89934733ECC8B14C76F4DDD8`。
- 框选抠图与智能抠图共享同一受控并发器和能力探针，不新增第二套模型进程管理。
- 并发器在任何 Sharp 解码或临时文件创建之前获取，并保持到 rembg 产物校验和素材落库完成。
- 临时选区 PNG 使用流式字节上限，不把完整中间产物一次性载入 Node.js 内存。
- 选区输出语义是“只保留所选矩形区域并移除背景”，不是保持原图尺寸的蒙版。

请求只接受：

```json
{
  "left": 48,
  "top": 32,
  "width": 544,
  "height": 357
}
```

坐标必须是有效整数，矩形必须完全位于源图片内，选区面积不得超过 4000 万像素。重试持久化只保留以上四个字段。

## 3. 自动化验证

新增或扩展的覆盖项：

- 未配置模型时 `selection_cutout.available=false` 并返回许可证审计原因。
- 配置真实 rembg 后，框选抠图和智能抠图公布相同的受审计引擎信息。
- 有效选区生成预期宽高的透明 PNG、派生素材、任务结果和审计元数据。
- 越界选区返回 HTTP 400。
- 成功后不存在 `-selection.png` 临时文件。
- 同租户已有框选任务占用令牌时，第二个请求在解码损坏源图前即返回 HTTP 429。
- 损坏源图、超 4000 万像素源图和临时目录写入失败均返回固定的 `IMAGE_TOOL_PROCESSING_FAILED`，任务表不保存本地路径或 libvips 错误。
- 前端显示“框选抠图”，与普通裁剪共用固定版本 Cropper.js。
- 失败重试状态只持久化矩形参数，不保存额外命令或未知字段。

- 文件：透明 PNG
- 尺寸：`544x357`
- 通道：4
- Alpha 最小值：`0`
- Alpha 最大值：`255`
- 文件大小：`10891` 字节
- SHA-256：`FF30B95F060297FF769FE69C813A73308D5748778A6950EC848CA8DFD11307DD`

第一次浏览器验证错误地使用了已经连续做过两次智能抠图的素材。该次任务虽然成功，但产物 Alpha 最大值为 `0`，是全透明图，因此未计入最终验收。随后只在临时验收数据库中把节点恢复到原始素材 ID `9`，重新执行完整浏览器链并得到 Alpha 范围 `0..255` 的有效前景产物。

这次修正属于验收样本修正，不修改产品代码。全透明结果仍可能是用户框选空白区域时的合法模型输出，当前不把“必须存在不透明像素”设为服务端规则。

标准审计随后指出两个问题：选区预处理发生在并发令牌获取之前，以及 Sharp/文件系统异常可能把本地路径写入接口和任务表。修正后先以失败测试复现，再完成以下更改：

- 把并发令牌前移到输出目录创建和 Sharp 解码之前，覆盖选区预处理、rembg、产物校验和落库。
- 以流式 Transform 对临时选区 PNG 施加与最终产物相同的 64 MiB 上限。
- 仅服务端日志保留底层诊断；客户端和任务表固定为“框选抠图处理失败”。
- 增加损坏源图、超像素上限源图、临时目录写入失败和“忙碌时不预处理第二张损坏源图”回归测试。
- 修正后重新执行全量测试、生产构建、依赖审计和上述真实浏览器链；最终产物哈希与有效样本一致。
