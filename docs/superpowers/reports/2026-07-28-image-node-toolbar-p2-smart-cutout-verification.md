## 1. 结论

P2 智能抠图已在独立工作树、独立数据库、独立素材目录和独立端口完成真实本地链路验证：

- 后端只在配置了真实可执行文件后公布能力，未配置时明确返回不可用原因。
- 真实调用 `rembg 2.0.77` 与 `u2netp` 模型生成透明 PNG，不使用模拟处理结果。
- 原素材保持不变，结果以派生素材和异步任务记录落库。
- 浏览器端支持执行、失败提示、重试、结果回写和刷新后的历史读取。
- 原始引擎错误和本地路径不会返回客户端或写入客户端可读任务错误。
- 其他尚未接入的模型功能继续显示为不可用，没有用静态按钮冒充可用能力。

该结论只覆盖本地开发与验证。生产镜像目前未打包 Python、rembg 和模型文件，因此本阶段不推送 PR、不部署服务器，也不声称线上可用。

## 3. 配置与隔离

新增可选配置：

```dotenv
IMAGE_TOOL_REMBG_PATH=
IMAGE_TOOL_REMBG_VERSION=
IMAGE_TOOL_REMBG_MODEL=u2netp
IMAGE_TOOL_REMBG_MODEL_HOME=
```

约束：

- `IMAGE_TOOL_REMBG_PATH` 必须是存在的绝对文件路径。
- 模型只允许当前已审计的 `u2netp`。
- 启动时会执行固定的 `rembg --version` 只读探针；实际版本必须与配置版本完全一致。
- 模型目录必须是绝对路径，对应的 `u2netp.onnx` 必须是可读普通文件，且 SHA-256 必须与代码内固定的已审计值完全一致。
- 命令参数由服务端固定组装，不接受用户提供命令、脚本或附加参数。
- 子进程超时为 180 秒，输出缓冲上限为 1 MiB。
- 输出必须是具有 Alpha 通道且宽高有效的 PNG，并在落库前通过 `stats()` 完整解码；不创建整图 RAW Buffer。
- 输出文件上限为 64 MiB、解码像素上限为 4000 万，超限产物会失败并清理。
- 派生文件仍受项目素材根目录和租户权限约束。
- 未配置或配置无效时，`smart_cutout.available=false`。
- 公开平台请求同时进入现有模型生成限流。
- rembg 默认全局并发与单租户并发均为 `1`，超限立即返回 HTTP 429，不继续拉起进程。

可选并发配置：

```dotenv
IMAGE_TOOL_REMBG_MAX_CONCURRENCY=1
IMAGE_TOOL_REMBG_MAX_TENANT_CONCURRENCY=1
```

## 6. 自动化验证

新增或扩展的覆盖项：

- 默认未配置时不公布智能抠图能力。
- 仅配置真实可执行路径后公布能力和版本、模型信息。
- 成功生成透明 PNG、派生素材、任务结果和审计元数据。
- 引擎失败时任务失败、临时输出清理、HTTP 返回 503。
- 截断 PNG 即使能读取元数据，也必须在完整像素解码时失败并清理。
- 超过 4000 万像素的 PNG 必须失败并清理，主 API 进程不分配整图 RAW Buffer。
- 客户端错误和任务错误不包含引擎原始 stderr。
- 可执行路径为目录、探针版本不符、模型缺失或模型哈希不符时不公布能力。
- 同租户并发与全局并发超限均返回 HTTP 429。
- 图片工具操作进入公共平台共享模型生成限流。
- 智能抠图的零参数重试状态随画布持久化，且额外参数不会被保存。
- 前端将 `smart_cutout` 显示为“智能抠图”。
