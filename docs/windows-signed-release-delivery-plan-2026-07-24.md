# Windows 正式签名发布交付计划

日期：2026-07-24

## 目标

将现有标签发布流程补齐为可审计的 Windows 正式交付闭环：

1. `vX.Y.Z` 标签必须与桌面包版本一致。
2. 缺少 `WIN_CSC_LINK` 或 `WIN_CSC_KEY_PASSWORD` 时，在构建前明确失败。
3. 安装包与便携版必须具有有效 Authenticode 签名和时间戳。
4. 签名版安装包必须通过安装、覆盖安装、卸载和用户数据保留回归。
5. 发布产物必须附带 SHA-256 校验和及机器可读验证报告。
6. 所有门禁通过后只创建 GitHub 草稿 Release，由管理员复核后发布。

## 非目标

- 不在仓库中保存证书、密码或证书内容。
- 不在缺少真实证书时伪造“已签名”结果。
- 不自动发布公开 Release。
- 不修改桌面应用功能、品牌或安装身份。

## 实施顺序

1. 先用测试固定签名报告、时间戳和签名安装回归的工作流契约。
2. 新增单一 PowerShell 验证脚本，负责产物识别、签名、时间戳、版本与校验和验证。
3. 为安装回归脚本增加可选的签名检查；普通 PR 仍验证未签名包，标签发布开启强制签名检查。
4. 发布工作流上传 `SHA256SUMS.txt` 和 `release-verification.json`，并对二进制执行产物证明。
5. 运行测试、PowerShell 语法检查和无证书失败验证。

## 成功标准

- 发布契约测试通过。
- 验证脚本在未签名样本或缺失产物上非零退出。
- 标签工作流只在签名、时间戳、安装回归和校验和全部通过后创建草稿 Release。
- 仓库中不出现任何证书或密码。

## 外部阻塞

GitHub 仓库当前未配置 `WIN_CSC_LINK` 和 `WIN_CSC_KEY_PASSWORD`。因此本阶段可以交付并合并发布门禁，但不能诚实地产出首个正式签名安装包；管理员配置证书密钥后，才可推送与 `desktop/package.json` 版本一致的标签触发真实签名发布。
