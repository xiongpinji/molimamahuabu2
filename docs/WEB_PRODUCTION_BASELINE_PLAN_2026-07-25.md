# 网页端生产部署基线计划

## 目标

把当前前后端工程交付为可在单台 Linux 云服务器运行的网页服务，不制作桌面安装包。

## 当前假设

- 暂未确定云厂商、服务器 IP、域名和 DNS 管理方式。
- 第一阶段采用 Docker Compose 单机部署；应用保持单实例，继续使用现有 SQLite。
- Caddy 负责 HTTPS 和反向代理，Node.js 同源提供前端、API 与素材。
- 模型密钥、平台 JWT 密钥和管理员令牌只由部署环境注入，不进入镜像或 Git。

## 本阶段范围

1. 用环境变量覆盖开发配置中的调试、TLS、CORS、数据库和素材路径。
2. 构建包含前端静态产物、Node.js 后端和 FFmpeg 的生产镜像。
3. 使用持久卷保存 SQLite、素材和数据库备份。
4. 使用 Caddy 自动申请 HTTPS 证书并反向代理应用。
5. 增加 GitHub Actions 镜像构建与容器健康冒烟测试。
6. 提供首次管理员引导、生产预检、备份和回滚操作手册。

## 不在本阶段范围

- 不创建 Windows 安装包、签名证书或桌面自动更新。
- 不在没有服务器、域名和 DNS 权限时执行外网部署。
- 不把 SQLite 扩展为多副本数据库；上线基线只允许单应用实例。
- 不自动开放注册；首次管理员引导完成前保持注册关闭。

## 验收标准

- 配置覆盖单测通过，未设置环境变量时保持现有开发行为。
- 前后端构建通过，生产镜像可构建。
- 容器启动后 `/health` 返回 `status=ok`，首页返回前端 HTML。
- 重建应用容器后数据库与素材文件仍存在。
- Compose 配置包含健康检查、自动重启、持久卷和 HTTPS 入口。
- 示例环境文件不包含真实密钥。
- GitHub Actions 可在 Linux 上构建并启动镜像完成健康检查。
- 生产预检仍要求安全配置、管理员、模型价格和数据库完整性全部通过。

## 发布与回滚

- 发布前先创建并验证 SQLite 备份，再拉取已验证镜像并重建应用容器。
- 回滚时恢复上一镜像标签；数据库只通过已验证备份进行人工恢复，不由部署脚本覆盖。
- 任何 `DATA_BACKUP_LOW_SPACE`、`ENOSPC`、`EIO` 或预检失败都应停止发布。
