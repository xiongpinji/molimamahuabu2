# 情绪调节与人脸识别修复验收单（2026-08-01）

## 问题复现与根因

- 线上情绪调节任务虽然返回成功，但目标脸部的平均像素变化仅约 3.36%，肉眼看不出要求的表情变化。
- 当前后端把完整原图作为第一参考图、脸部裁片作为第二参考图；生产异步图片模型使用第一参考图作为主编辑输入，第二张裁片不能可靠锁定目标脸。
- 当前前端只调用浏览器实验性 `window.FaceDetector`；当前 Chromium 环境没有该接口，因此“自动识别”直接退回手动框选。
- 现有后端仅校验整张结果文件是否不同，无法拒绝“颜色或压缩略有变化、表情没有变化”的假成功，也可能修改同图中的其他人物。

## 本次边界

- 前端改用随应用部署的 MediaPipe 人脸检测模型，保留手动框选作为无脸或模型异常时的回退。
- 情绪调节只提交扩展后的目标脸/头部裁片作为第一且唯一的参考图。
- 模型结果缩放到该局部区域后羽化合成回原图；选区外保持原图，不影响同图其他人物。
- 对目标脸区域计算实际像素变化量；低于随强度变化的最低阈值时任务失败，不创建“无变化”的成功素材。
- 人像质感调节与其他图片工具不在本次改动范围内。

## 可验证验收标准

1. 前端代码和构建产物不再依赖 `window.FaceDetector`，真实 Chromium 页面可检测测试图中的多张人脸。
2. 后端供应商请求只有一个 `referenceImage`，内容是比原始脸框稍大的局部裁片，尺寸小于完整原图。
3. 情绪结果保持原图宽高；目标脸区域变化量达到阈值；局部编辑区域外的像素与原图一致。
4. 模型返回几乎未变化的目标脸时，接口返回处理失败且不创建派生素材。
5. 定向测试、全量测试、前端生产构建、真实浏览器检测、真实供应商生成、PR CI 与线上健康检查全部通过后才交付。
