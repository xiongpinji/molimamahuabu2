# 剧本分析：电影化视觉导演增强

## 目标与零回退边界

本期把外部 `cinematic-storyboard-generator` 中有价值的四维剧本分析方法吸收到现有剧本分析流程，但不替换当前能力：

1. 默认 Skill 继续是 `short-drama-director@1.0.0`，其提示词和输出契约不变。
2. 新能力以用户主动选择的 `cinematic-visual-director@1.0.0` 提供。
3. `visual_direction` 是 `schema_version 1.0` 上的附加字段；旧版本没有该字段仍可读取、审核和导入画布。
4. 原剧本、不可改事实、角色/场景/道具、分镜、连续性、人工审核和版本链均不得被增强字段替代。
5. 不执行 ZIP 中的 Shell 脚本，不新增数据库迁移，不改画布数据结构。

## 新增数据

`visual_direction` 包含：主/辅情绪及证据、场景类型分布、节奏标签及证据、视觉母题，以及可执行的构图、运镜、灯光、色彩和风险建议。证据必须回溯原始剧本，风格建议使用客观生产语言，不把导演姓名当作结果。

服务端会拒绝缺少证据、节奏标签或客观视觉语言的增强结果；证据是否忠实于原文继续进入既有人工审核，避免用简单字符串匹配误判合理转述。

人工校订会保留该附加字段，并强制沿用当前版本的 `skill_snapshot`，避免客户端篡改实际使用的 Skill。

## 验收门槛

- 默认 Skill 元数据和版本不变。
- 旧生产包不含 `visual_direction` 时继续通过校验。
- 选择电影化视觉导演时必须返回合法 `visual_direction`。
- 原文由服务端回填；人工校订保留视觉方案和不可变 Skill 快照。
- 前端仅在存在视觉方案时展示增强区，原审核和导入画布操作保持原位可用。
- 后端定向/全量测试、本期相关前端测试和生产构建通过后才能交付；若全量前端存在基线失败，必须确认失败文件不在本期 diff 内并如实留档。
