# 剧本分析生产包导入短剧工厂计划

## 目标

把上一阶段的“短剧工厂导入预览”升级为用户明确确认后的真实导入。导入必须一次性创建可继续编辑的短剧项目，并保留审核版本、Skill 快照、锁定事实、视觉方案和制作提示词。

## 边界

1. 只有当前审核通过版本可以导入；历史版本、未审核版本和其他用户的项目均拒绝。
2. 首次确认创建一个新短剧项目；相同“剧本分析项目 + 版本”重复确认返回原项目，不重复创建。
3. 导入使用单个数据库事务；任何角色、场景、道具、分集或分镜写入失败时整体回滚。
4. 导入只转换已有生产包，不调用文本、图片或视频模型，不创建异步生成任务，不扣积分。
5. 导入只新增短剧项目，不覆盖或修改已有短剧项目、原剧本分析项目和历史版本。
6. 不新增数据库迁移；导入来源和幂等键保存在新项目 metadata 中。

## 数据映射

- 项目：标题、故事梗概、类型、项目类型 `factory`。
- 来源快照：分析项目 ID、当前版本、审核状态、Skill 快照、锁定事实、视觉方案、连续性规则和完整生产包快照。
- 角色：`character_bible` / `characters` 映射到项目角色。
- 场景：`scene_bible` / `scenes` 与各集场景映射到项目场景，同名同时段场景去重。
- 道具：`prop_bible` / `props` 映射到项目道具。
- 分集：保留集号、标题、描述、时长，并把结构化场次整理成可编辑剧本文本。
- 分镜：保留图片提示词、视频提示词、对白、动作、场景、时长、景别、角度、运镜和连续性快照。

## 交互

1. 用户先打开现有导入预览。
2. 点击“确认导入并打开项目”后出现二次确认，明确说明会新增一个项目、不会调用模型或扣积分。
3. 确认后调用受控导入 API；成功后直接打开 `/film/{dramaId}`。
4. 若该版本已导入，则提示“已打开原项目”，不创建副本。

## 验收标准

1. 后端测试证明首次导入完整写入，重复导入返回同一项目且数据库计数不增加。
2. 后端测试证明未审核、过期版本和越权访问不会创建项目。
3. 后端测试证明图片/视频提示词及来源快照保持原值，失败时事务回滚。
4. 前端测试证明只有二次确认后才调用导入 API，并跳转到创建的短剧项目。
5. 定向测试、相关全量测试、生产构建和真实浏览器验收通过后，才允许增量部署。
6. 部署仅传输本阶段修改的生产文件；不得触碰 AI 音乐、数据库文件、Nginx、PM2、密钥和积分数据。
