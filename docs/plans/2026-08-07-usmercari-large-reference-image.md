# USMercari 大参考图上传修复

## 生产证据

- 失败任务：视频任务 `202`，模型 `MiniMax H3`，`480p`、`15 秒`、三张参考图。
- 失败发生在供应商任务提交前，错误为“USMercari 参考图超过 25MB 上传上限”。
- 三张参考图实际大小分别为 `42,625,985`、`356,156`、`490,835` 字节；首图为 `8192×4608` PNG。
- 该任务预留的 `7` 积分已由失败回退完整返还，没有形成净扣费。

## 根因

USMercari 客户端将供应商单张图片 `25MB` 上传限制直接作为本地硬错误。站内大图没有先经过已有的 Sharp 图片压缩能力，因此尚未上传参考图、也尚未提交收费视频任务就失败。

## 修复边界

1. 只对超过 `25MB` 的参考图片自动旋转并转为 JPEG；音频和视频继续执行原有硬上限。
2. 压缩结果仍必须小于 `25MB`，无法解码或压缩后仍超限时继续失败，禁止绕过供应商限制。
3. 不触发任何真实付费生成；用本地大图、模拟上传响应和现有自动化验证完整请求链。
4. 保留 `canvas-credit-callout-v1`、模型验证/定价门禁与供应商模型原名路由。

## 验收标准

- 大于 `25MB` 的有效参考图被转换为小于上限的 JPEG 上传载荷。
- 普通图片、音频、视频行为不变；超限音频/视频仍被拒绝。
- 三张参考图上传后形成三个媒体 ID，并且只提交一次视频任务。
- 定向测试、后端基线对比、前端构建和共享发布门禁通过。
- 候选从实时 `/opt/moli-drama/current` 制作并经受保护激活脚本切换；线上健康、日志、活动任务与 AI 音乐进程隔离正常。

- 线上原图无网络实测：`42,625,985` 字节 PNG 自动转为 `2,506,938` 字节 JPEG，仍保持 `8192×4608`，低于 `25MB`。
