# 剧本分析到短剧工厂生产闭环计划

## 目标

在不调用模型、不扣积分、不改写原剧本分析项目的前提下，补齐导入项目在短剧工厂中的来源追溯与生成前检查，并验证既有画布投影链路完整可用。

## 已验证基线

1. 线上项目 45 已显示 2 个角色、3 个场景、2 个道具和 3 个分镜。
2. `/film/45/canvas?episode=28` 已投影 23 个节点和 17 条关系线，包含三镜连续链及角色、场景、道具关系。
3. 画布入口首次失败来自旧页面缓存引用过期分块；刷新到当前发布后已恢复，不需要修改路由逻辑。

## 本阶段范围

1. 在制作页显示剧本分析来源项目、审核版本、审核状态、锁定事实数量和导入时间。
2. 明确当前短剧工厂项目是可编辑副本，来源剧本保持只读；显示当前集剧本与来源文本是否已发生工厂内调整。
3. 增加纯前端、无扣费的生成前检查：视频模型、画幅、分镜时长、提示词、角色/场景关系和缺失参考图。
4. 缺失参考图作为警告展示，不自动触发图片或视频生成；任何付费生成继续由现有按钮和确认流程控制。
5. 验证提示词保存后刷新可回读，且来源快照、锁定事实和积分不变。

## 非目标

1. 不修改导入事务、数据库结构、积分、生成模型或生产任务。
2. 不重新实现已经存在且验收通过的画布投影。
3. 不改动 AI 音乐程序、8787 端口、Nginx、密钥或共享数据库文件。

## 验收标准

1. 先写失败测试，证明来源追溯和预检规则尚未实现；最小实现后测试转绿。
2. 前端相关测试与生产构建通过。
3. 真实浏览器中项目 45 可见实际剧本分析审核版本和无扣费预检结果。
4. 保存一个不改变语义的分镜提示词后刷新，文本与关系仍存在；可用积分保持不变。
5. 部署以切换时最新 `/opt/moli-drama/current` 为父目录，只覆盖本阶段修改的前端源文件并在副本中构建；不得用本地整包覆盖线上复合发布。
6. 部署后 `moli-drama.service`、5679 健康，AI 音乐 8787 的进程号保持不变。
