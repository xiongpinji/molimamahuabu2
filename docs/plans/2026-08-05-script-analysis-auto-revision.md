# 剧本分析退回后自动模型修订

## 用户目标

当前版本填写“人工审核备注”并点击“退回修改”后，系统自动把备注作为修订要求交给模型，生成一个新的待审核版本，不再要求用户手工重新点击分析。

## 行为合同

1. 退回修改必须提交非空备注，并且只能作用于当前版本。
2. 接口立即把当前版本保存为 `rejected`，创建用户归属的异步修订任务并返回任务编号。
3. 模型输入包含原剧本、不可改事实、当前生产包、当前 Skill 和人工审核备注；未被备注要求修改的内容应保持不变。
4. 成功时追加 `current_version + 1`，新版本为 `needs_review`，记录来源版本和人工备注；旧版本继续保留为 `rejected`。
5. 失败时不创建新版本，项目回到旧版本的 `rejected` 状态，任务记录错误，允许用户再次退回修改。
6. 同一项目已有修订任务运行时拒绝重复提交；“确认通过”保持现有同步审核行为。
7. 前端在退回后直接复用任务轮询，完成后刷新项目和版本列表，并显示“已按审核意见生成新版本”。

## 不在范围

- 不自动点击或运行生产中的真实剧本任务。
- 不修改原剧本、锁定事实、历史版本号或已经导入画布的内容。
- 不引入新的模型、计费规则、数据库表或通用工作流抽象。
- 不合并尚未完成真实模型验收的导演故事板 V2。

## 验收标准

1. 路由级红测证明退回会创建任务，并在任务成功后追加待审核版本。
2. 模型提示词包含人工备注、当前生产包和原剧本，归一化后仍保留来源事实。
3. 失败和重复提交均不会产生额外版本。
4. 前端退回分支接收任务编号并进入轮询；通过分支行为不变。
5. 后端定向/全量测试、前端定向/全量测试和生产构建完成，既有失败与基线对照披露。
6. 发布候选从实时 `/opt/moli-drama/current` 克隆并通过 `canvas-credit-callout-v1` 共享门禁。
