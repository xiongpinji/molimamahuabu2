# 支付宝自主充值接入

## 目标

为公开平台模式下的登录用户提供共用同一支付宝支付渠道的两种充值入口：

- 自定义充值：1 元人民币 = 100 积分。
- 限时套餐：管理员分别设置售价与到账积分，因此可以形成不同于 1:100 的套餐比例。
- 所有订单金额按“分”存储，避免浮点误差。

## 用户接口

- 当前工作区页面显示固定比例、自定义金额输入、有效限时套餐、支付宝支付按钮和本人充值记录。
- 用户可输入 1.00 至 50000.00 元，两位小数以内。
- 套餐卡显示管理员设置的名称、售价、到账积分、折算比例、限时和广告图片。
- 创建订单后跳转支付宝电脑网站收银台。
- 支付宝同步回跳只负责返回页面；页面展示的最终结果以服务端订单状态为准。

## 服务端接口

- `GET /api/v1/billing/recharge/alipay/config`：返回安全的渠道状态、比例和金额范围。
- `POST /api/v1/billing/recharge/alipay/orders`：为当前用户和当前工作区创建幂等订单并返回支付 URL。
- `GET /api/v1/billing/recharge/alipay/orders`：只返回当前用户在当前工作区创建的充值订单。
- `POST /api/v1/billing/recharge/alipay/notify`：支付宝异步通知，不要求用户登录。
- `GET /api/v1/billing/recharge/packages`：返回当前处于展示时间内的有效套餐。
- `GET/POST/PUT /api/v1/billing/admin/recharge-packages`：管理员查看、新建或更新套餐。

## 套餐配置

- 套餐名称。
- 售价（人民币，精确到分）。
- 到账积分（正整数），由售价和积分共同决定套餐兑换比例。
- 可选开始时间和结束时间；开始前或结束后不在用户端展示，也不能下单。
- 必填 HTTPS 广告图片地址；用户端卡片展示该图片，后台提供即时预览。
- 启用/停用状态。

套餐下单会把名称、金额、积分和套餐 ID 快照到充值订单。后续修改或停用套餐不改变既有订单。

## 入账约束

异步通知必须同时满足以下条件才可入账：

1. 支付宝 SDK 验签通过。
2. `app_id` 与本地配置一致。
3. `seller_id` 与本地配置一致。
4. `trade_status` 为 `TRADE_SUCCESS` 或 `TRADE_FINISHED`。
5. `out_trade_no` 对应本地待支付订单。
6. `total_amount` 与本地订单快照金额完全一致。
7. 同一订单只允许绑定一个支付宝交易号，订单状态变更与积分增加在同一 SQLite 事务中完成。

重复通知返回成功但不重复加积分。验签失败、身份或金额不一致均返回失败并保留待支付状态。

## 配置与安全

- 私钥和支付宝公钥只从环境变量或环境变量指向的文件读取，不进入仓库或数据库。
- 未完整配置时，充值查询接口仍可用，创建订单明确返回 `ALIPAY_NOT_CONFIGURED`。
- 回调日志不记录完整通知内容、买家账号或密钥。
- 使用支付宝官方 Node.js SDK 的 RSA2 验签和电脑网站支付 URL 生成能力。

## 非目标

- 本次不实现退款、订阅自动续费、管理员代充值或其他支付渠道。
- 本次不新建媒体上传系统；套餐广告图使用管理员配置的 HTTPS 图片地址。
- 本次不部署生产，也不做真实扣款；生产启用必须由商户完成支付宝应用、电脑网站支付产品、密钥和回调域名配置后，再进行小额验收。

## 验收清单

- 合法自定义金额按 1:100 创建订单，相同幂等键不重复建单。
- 非法金额被拒绝。
- 管理员可设置 0.01 至 50000.00 元内任意合法售价与积分的套餐；未开始、已过期或已停用套餐不会展示且不能下单。
- 套餐订单使用创建时快照，管理员后续修改套餐不改变订单金额或积分。
- 合法成功通知原子入账。
- 重复成功通知不重复入账。
- 伪造签名、错误应用号、错误商户号、金额不符、未知订单不入账。
- 不同用户或工作区不能读取彼此订单。
- 前端构建通过，充值入口明确显示比例和订单状态。
