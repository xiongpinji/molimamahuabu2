# 视觉导演方案下游桥接计划

## 目标

把剧本分析中可选的 `visual_direction` 安全地追加到自由画布，并在自由画布接入项目后允许 3D 导演台预览、确认应用、撤销和重新读取来源。

## 既有边界

1. 不含 `visual_direction` 的旧制作包导入结果保持不变。
2. 角色、场景、道具、分镜节点及图片/视频提示词不得被视觉方案覆盖或改写。
3. `/canvas/local` 继续是本地草稿，不新增伪项目 ID、伪保存接口或独立导演台。
4. 继续使用现有“接入项目”把自由画布增量合并到项目画布；不改变已有项目节点和 `director_timeline`。
5. 视觉方案是生产指导信息，不自动推导人物位置、摄影机角度或灯光数值。

## 数据契约

- 自由画布新增一个 `homeCanvasNode` 文本节点，`scriptAnalysis.sourceType` 为 `visual_direction`。
- 节点正文是可读摘要；`data.visualDirection` 保存原始结构化方案；`data.skillSnapshot` 保存实际 Skill 快照。
- 来源包含剧本分析项目 ID、版本、来源节点 ID 和 Skill 标识。
- 项目导演台仅在找到该节点时展示方案预览。
- 点击“应用到导演台”后，把方案和来源写入 `director_timeline.extensions.visualDirectionGuidance`。
- 应用操作必须进入导演台现有撤销/重做栈；撤销后不能留下部分机位、人物或灯光修改。
- 重新打开导演台时，从持久化的 `extensions.visualDirectionGuidance` 回读已应用方案。

## 验收标准

1. 旧制作包的节点和边数量、节点内容与改动前一致。
2. 增强制作包只额外增加一个视觉方案节点和一条概览到方案的边。
3. 图片和视频提示词保持逐字一致。
4. 自由画布接入项目后，视觉方案元数据不丢失。
5. 导演台可区分“待应用”和“已应用”，确认应用后保存，撤销后恢复此前时间线。
6. 相关单元测试、前端构建和真实浏览器验收通过后，才允许增量部署本次变更文件。
