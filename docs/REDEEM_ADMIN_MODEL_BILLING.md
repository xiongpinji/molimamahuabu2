# 兑换码与管理员计费后台阶段设计

## 目标

本阶段停止扩展支付、套餐和订阅链路，改为可审计的兑换码积分体系：

- 平台管理员可查看、启用或停用用户账号。
- 平台管理员可创建、停用兑换码，并查看兑换次数。
- 用户在当前租户工作区兑换积分，积分直接进入该租户账户。
- 平台管理员可对租户积分做正负调整，并查看调整与兑换流水。
- 平台管理员可为每个实际模型独立配置积分价格、模型类型和启用状态。
- 未配置、已停用或价格无效的模型继续默认拒绝生成，不能猜测价格。

## 解释边界

用户原话中的“对话”结合上下文按“兑换”处理。当前项目没有独立聊天业务，本阶段不新增聊天系统。

## 数据设计

### `redeem_codes`

- 只保存兑换码的 SHA-256 摘要，不保存明文。
- `code_hint` 仅用于管理员识别，不可还原完整兑换码。
- 每个兑换码记录积分、最大兑换次数、当前兑换次数、到期时间和状态。

### `redeem_code_usages`

- 记录兑换码、租户、操作用户和到账积分。
- 同一兑换码只能被同一租户兑换一次。

### `tenant_credit_adjustments`

- 记录兑换入账和管理员调账。
- 正数增加可用积分；负数只允许在可用余额充足时扣减。
- 业务入账与流水写入必须位于同一个数据库事务。

### `model_credit_prices`

- 在原模型价格表上增加 `display_name`、`category` 和 `status`。
- 模型 ID 使用规范化后的实际调用 ID，允许管理员新增模型。
- `status=disabled` 的模型禁止生成。

## API

### 用户

- `POST /billing/redeem`：向当前租户兑换积分。
- `GET /billing/credit-transactions`：查看当前租户兑换与管理员调账流水。

### 平台管理员

- `GET /billing/admin/users`
- `PUT /billing/admin/users/:userId`
- `GET /billing/admin/tenants`
- `POST /billing/admin/tenants/:tenantId/credits`
- `GET /billing/admin/credit-transactions`
- `GET /billing/admin/redeem-codes`
- `POST /billing/admin/redeem-codes`
- `PUT /billing/admin/redeem-codes/:codeId`
- `GET /billing/prices`
- `PUT /billing/prices/:model`

管理员接口继续使用已有的安全平台管理员令牌，不将令牌写入长期存储。

## UI

- `/billing-admin` 改为统一管理后台，提供账号、兑换码、积分流水、模型计费四个页签。
- `/tenant-console` 移除套餐和待支付订单操作，改为兑换码输入与积分流水。
- 现有支付/订阅表和 API 暂不删除，仅从前端流程下线，避免破坏已提交的数据结构。

## 验收标准

- [ ] 兑换码明文只在创建响应中出现一次，数据库不保存明文。
- [ ] 重复兑换、过期、停用、次数耗尽均不会增加积分。
- [ ] 兑换入账与兑换流水具备事务一致性。
- [ ] 管理员可停用账号，已有登录令牌随即失效。
- [ ] 管理员调账不会将可用积分扣成负数。
- [ ] 每个模型可独立新增、定价、分类、启停。
- [ ] 未定价或停用模型默认禁止生成。
- [ ] 租户之间的兑换和积分流水完全隔离。
- [ ] 前后端目标测试、全量测试和生产构建通过。

## 非目标

- 不接支付渠道，不处理支付回调。
- 不激活订阅，不按套餐自动发积分。
- 不删除上一阶段的订阅基础表。
- 不新增聊天、客服或私信系统。
