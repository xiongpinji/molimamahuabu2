# 短剧工厂线上热修任务（2026-07-31）

## 线上故障

- 角色、场景和道具生图在未显式选择模型时提示“模型 ID 必须是 1 到 120 个可见字符”。
- 场景单图生成提示 `no such column: polished_prompt_single`。
- 全能模式 AI 生成分镜提示“AI 返回内容为空”；供应端实际通过 HTTP 200 SSE 返回 `upstream_error`。

## 已确认根因

- 资产生图计费在解析默认图片模型前校验空模型；道具链还会被 YAML 供应商兜底过滤，可能偏离数据库全局默认图片模型。
- `scenes.polished_prompt_single` 已被运行时代码使用，但生产数据库迁移链和启动自愈均未声明该字段。
- 全能模式把完整多节拍格式规范追加进分镜批量系统提示，生产供应端在该大请求上返回上游错误；流式解析器又忽略了 SSE `error` 事件，将其误报为空响应。
- 线上角色、场景提取还会收到 HTTP 200 但只有角色事件和结束事件的空 SSE；同一模型和提示改用非流式请求可稳定返回正文。
- 首轮部署后的线上角色提取实测收到 SSE `upstream_error`（供应端临时不可用）；该错误适合同模型非流式单次兜底，认证、参数和内容安全等明确错误不应重试。

## 热修范围

- 角色、场景和道具生图统一先解析数据库中的实际图片模型，并把该模型用于计费、任务记录及供应端调用。
- 增加场景单图提示词字段迁移、启动自愈和生产预检。
- 识别并上抛 HTTP 200 SSE 的结构化上游错误，不再按空响应重试。
- 连续两次空 SSE 后只追加一次同模型非流式兜底；未输出任何正文的 SSE `upstream_error` 也只追加一次同模型非流式兜底，已输出部分正文或其他明确上游错误仍立即失败。
- 全能模式批量生成只请求基础分镜 JSON，保存时使用共用多节拍格式器补齐 `universal_segment_text`。

## 验收标准

- 新迁移与旧库启动自愈均能补齐字段，重复执行安全。
- 未显式传模型的角色、场景和道具生图可使用默认图片模型计费建单。
- SSE 上游错误只请求一次并返回可诊断错误。
- 两次空 SSE 后的非流式兜底可返回正文，且不会改写模型路由或产生第二次业务计费。
- 临时 SSE `upstream_error` 可通过一次同模型非流式请求恢复；其他结构化上游错误不触发兜底。
- 流请求已经输出部分正文后再报错时不触发兜底，避免增量保存混入两次生成结果；跨空流重试的用量完整合并。
- 全能分镜请求不再携带超长格式后缀，保存结果仍为合法多节拍文本且各拍时长之和等于镜头时长。
- 后端全量测试、前端生产构建、生产预检和线上短剧工厂实测均通过。
