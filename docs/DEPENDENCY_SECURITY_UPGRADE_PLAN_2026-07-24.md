# 后端高危依赖升级计划（2026-07-24）

## 目标

在不改动业务功能和供应商调用协议的前提下，升级后端已被官方 `npm audit` 标记为高危的直接依赖：

- `adm-zip`：`0.5.16` → `0.6.0`
- `sharp`：`0.34.5` → `0.35.3`

## 已确认调用面

- `adm-zip`
  - `dramaExportService`：生成包含 `project.json` 与媒体文件的项目 ZIP。
  - `dramaImportService`：解析项目 ZIP，并恢复项目数据与媒体文件。
- `sharp`
  - 分镜宫格拆分与图片尺寸对齐。
  - 视频参考图探测、旋转、缩放和压缩。
  - 分镜图片超分接口。

## 范围

1. 只更新 `backend-node/package.json` 与 `backend-node/package-lock.json` 中上述两个直接依赖及其必要传递依赖。
2. 因 `sharp@0.35.3` 要求 Node.js `>=20.9.0`，同步后端运行时声明与相关安装文档。
3. 新增依赖兼容性回归测试，覆盖：
   - ZIP 中 `project.json` 与媒体文件解析。
   - Sharp 的元数据读取、缩放与 PNG 输出。
4. 若新版本产生真实兼容性失败，只做通过回归测试所需的最小修复。
5. 记录官方审计、后端全量测试、前端测试与生产构建结果。

## 非目标

- 不升级其他业务依赖。
- 不修改图片、视频或模型供应商协议。
- 不调用真实付费模型。
- 不调整生产配置、数据库结构或计费规则。

## 验收标准

- `npm audit --omit=dev --registry=https://registry.npmjs.org` 不再报告高危或严重漏洞。
- 依赖树实际解析到 `adm-zip@0.6.0`、`sharp@0.35.3`。
- ZIP 与 Sharp 定向兼容性测试通过。
- 后端全量测试通过。
- 前端全量测试和生产构建通过。
- Git 差异仅包含本阶段文档、依赖清单/锁文件、必要测试和 Node.js 运行时要求文档；如无兼容性故障，不修改生产代码。

## 执行顺序

1. 在旧版本依赖上运行兼容性表征测试，确认当前生产契约。
2. 定向升级两个依赖。
3. 在新版本上重跑定向测试；若失败，先保留失败证据，再做最小兼容修复。
4. 执行官方依赖审计与全量回归。
5. 选择性提交、推送并创建独立 PR。
