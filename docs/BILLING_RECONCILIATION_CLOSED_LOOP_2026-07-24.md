# 积分预扣对账闭环设计与验收

## 目标

为长期停留在 `held` 的个人/租户积分预扣提供可审计的后台闭环：

1. 查询超过阈值的冻结记录，并关联 `async_tasks`、`image_generations`、`video_generations`。
2. 只把“全部关联任务已明确失败，且没有继续运行可能”的记录标记为可退款。
3. 后台管理员以幂等键手工触发安全退款；重复请求不得重复入账。
4. 保留对账处理历史和审计事件，后台可查看异常、阻断原因及处理结果。

## 安全边界

- `pending` / `processing` 任务或生成记录一律不退款。
- “结果未知”“状态未知”“仍可能处理中”等不确定结果一律不退款。
- “用户已取消”目前不能中断已经发出的 AI 调用，因此一律不退款。
- 取消接口只把任务标记为失败以停止轮询，关联预扣继续保持 `held`；实际调用返回后仍由原生成链结算。
- 已完成但仍冻结的记录只能人工复核，不能走退款接口。
- 没有任何任务/生成记录关联证据的孤立预扣只能人工复核。
- 可退款仅限：存在关联证据，所有关联状态均为失败类终态，且不存在上述风险标记。
- 本次不增加自动定时退款，避免在缺少供应商终态时扩大资金风险。

## 最小实现

- 新增对账服务：
  - 扫描陈旧 `held`；
  - 统一安全分类；
  - 幂等执行退款；
  - 写入对账历史与 `audit_events`。
- 新增管理员 API：
  - `GET /billing/admin/reconciliation/anomalies`
  - `GET /billing/admin/reconciliation/history`
  - `POST /billing/admin/reconciliation/:reservationId/refund`
- 管理后台新增“积分对账”页签，只对 `refundable` 记录显示退款按钮。

## 验收标准

- [ ] 陈旧扫描同时覆盖租户和未迁移的个人预扣，且不重复返回同一预扣。
- [ ] 运行中、结果未知、用户取消、已完成、无关联证据均被阻断。
- [ ] 明确失败且不可继续运行的陈旧预扣可退款。
- [ ] 同一幂等键重试只产生一条退款账本和一条对账历史。
- [ ] 不同预扣复用幂等键返回冲突。
- [ ] 管理员 API 返回异常列表、历史记录和明确错误码。
- [ ] 后台 UI 能刷新异常/历史并执行安全退款。
- [ ] 目标测试、全量后端测试、全量前端测试、前端构建和 `git diff --check` 全部通过。
